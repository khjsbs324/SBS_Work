[DAY9 PPT 자동화 실습 — 기초]

당신은 이 프로젝트의 PPT 제작 에이전트다. 현재 작업 폴더는 DAY9 프로젝트 루트이며, 이 실습은 원본 보존을 위해 DAY9를 복제한 별도 작업본에서 수행한다.

목표
- 주제: 「AI 에이전트 업무 입문 — 반복 업무를 줄이는 디지털 동료」
- 대상: AI 에이전트를 처음 접하는 사무직 교육생
- 분량: 총 6페이지, 16:9(1920×1080)
- 톤: 쉽고 명료한 교육용, 밝은 배경, 블루 계열 포인트
- 외부 이미지 없이 타이포그래피, 도형, 선, 카드만 사용한다.

반드시 먼저 읽을 파일
1. CLAUDE.md
2. presentation/config/document.md
3. presentation/config/manifest.md
4. presentation/config/page-types.md
5. presentation/design-system/*.md
6. .claude/rules/*.md

페이지 구성
1. p1 / cover — 제목, 부제 「반복 업무를 줄이는 디지털 동료」, 교육용 표기
2. ps1 / section — “AI 에이전트란?” 한 문장 정의와 학습 목표 3개
3. ps1_1 / content — 핵심 구성요소 3가지: 모델, 도구, 메모리
4. ps1_2 / content — 업무 흐름 4단계: 요청 → 계획 → 실행 → 검증
5. pb1 / section — 실무 활용 사례 4개: 문서 요약, 이메일 초안, 자료 조사, 보고서 정리
6. pb1_1 / content — 시작 전 체크리스트 5개와 오늘의 실습 과제

콘텐츠 규칙
- 제목은 24자 이내, 본문 한 문장은 45자 이내로 쓴다.
- 페이지마다 핵심 메시지는 1개만 둔다.
- 설명은 쉬운 한국어로 쓰고 불필요한 전문용어를 피한다.
- 수치는 근거가 없는 성과 주장 대신 “예시” 또는 “목표”로 표시한다.
- 각 요소 ID는 `{pageId}.{elementId}` 형식으로 작성한다.

실행 절차
1. slide-planner 관점으로 6페이지 계획을 먼저 작성한다.
2. manifest의 페이지 순서와 유형을 위 구성에 맞게 정리한다. 사용하지 않는 기존 페이지는 임의로 이름을 바꾸지 말고 manifest에서 제외한다.
3. 기존 디자인 토큰을 우선 사용해 각 페이지 Markdown을 작성한다.
4. 필요한 값이 기존 토큰에 없을 때만 디자인 시스템 문서에 최소한으로 추가한다.
5. output 폴더를 직접 수정하지 말고 반드시 원본 Markdown/renderer를 통해 반영한다.
6. 아래 명령을 순서대로 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\validate.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

검증 조건
- Page ID와 Element ID가 규칙에 맞아야 한다.
- manifest 등록 순서와 실제 페이지가 일치해야 한다.
- 모든 요소가 1920×1080 캔버스 안에 있어야 한다.
- 제목/본문/카드의 정렬과 간격이 일관되어야 한다.
- validation과 build가 모두 성공해야 한다.
- output/html/index.html과 output/html/presentation.json의 존재를 확인한다.

최종 보고 형식
- 생성/수정한 파일 목록
- 6페이지별 한 줄 요약
- 사용한 주요 디자인 토큰
- validate/build 실행 결과
- 남아 있는 경고 또는 수동 확인 항목

중간에 질문하지 말고 합리적인 교육용 문구를 직접 작성해 끝까지 수행하라.
