# CLAUDE.md

이 파일은 Claude Code(claude.ai/code)가 이 저장소에서 작업할 때 따라야 하는 지침을 제공한다.

## 작업공간의 목적

이곳은 소프트웨어 제품 저장소가 아니라 **NCS(국가직무능력표준) 직업훈련 평가자료를 제작하고 학생 결과를 채점하는 작업공간**이다. 수업 범위는 HTML, CSS, JavaScript, Git, GitHub이며, 사용자가 범위를 넓히지 않는 한 백엔드는 사용하지 않는다.

업무는 다음 두 종류로 구분한다.

1. **능력단위평가 코딩 문제 제작**: NCS 원문과 수행준거를 분석하여 문제 코드, 정답 코드, 학생용 안내, 강사용 채점기준을 제작한다.
2. **채점 및 피드백**: 능력단위별 `Exam.md`를 만들고 학생 GitHub 저장소를 증빙 중심으로 채점한 뒤 학생별 결과를 저장하고 SBS아카데미 평가 사이트에 등록한다.

현재 `수정 보완(LM0802010406_13v1)` 자료와 `정답/`, `문제 코드/`, `예시 코드/`는 첫 번째 업무인 **능력단위평가 코딩 문제 제작**의 현행 예시이다. Markdown 산출물과 HTML/CSS 실습 문제를 모두 평가 대상 산출물로 중요하게 다룬다.

이 폴더의 `AGENTS.md`가 작업 목적, 트리거, 공통 원칙 및 역할 배정을 정의하는 최상위 지침이다. 중요한 변경이나 채점을 수행하기 전에 `AGENTS.md`, `skills/ncs-exam-production/SKILL.md`, 관련 기준 파일을 읽는다.

## A. 능력단위평가 코딩 문제 제작

### 자료 우선순위

자료가 서로 충돌하면 `skills/ncs-exam-production/references/project-map.md`에 따라 다음 순서로 판단한다.

1. 사용자의 최신 요청
2. 현재 `문제 코드/`와 `정답/`의 파일
3. 해당 NCS 원본 PDF(`[5](수정 보완)LM...pdf`, 요약본은 `pdf요약결과.md`)
4. 등록 형식과 채점기준의 상세 수준을 확인하기 위한 `문제 출제 예시.pdf`
5. 기존에 작성된 Markdown 및 생성된 PDF

### 제작 원칙

- 편집하기 전에 현재 파일 구조를 확인하고 파일 배치를 추측하지 않는다.
- `문제 코드/`와 `정답/`을 현재 코드의 기준으로 삼는다. `강사_제공_산출물/`과 `학생_제출_산출물/`에는 이전의 상세 시나리오인 가상의 `EDU-PORTAL-2026` 프로젝트 자료 15개가 있다. 현재 사용하는 간결한 실습 문제는 `최종 결과 산출물/`의 문서 4개와 `문제 코드/`, `정답/`이다. 사용자가 요청하지 않으면 두 시나리오를 합치거나 일치시키지 않는다.
- 백엔드, 데이터베이스, 서버, 프레임워크 또는 배포 요구사항을 추가하지 않는다. 수업 범위는 HTML, CSS, JavaScript, Git, GitHub이다.
- 최종 자료는 `최종 결과 산출물/`에 간결하게 정리하고 명시적인 요청 없이 중복 출력 폴더를 만들지 않는다.
- 강사용 자료와 학생용 자료를 분리하고 학생용 파일에 정답을 노출하지 않는다.
  - 학생 제공 가능: `문제 코드/index.html`, `문제 코드/css/style.css`, `문제 코드/정답.png`, `최종 결과 산출물/02_학생용_과제안내서.md`, `최종 결과 산출물/03_학생_제출_산출물.md`, `강사_제공_산출물/01`~`10`
  - 강사 전용이며 평가 전에 배포 금지: `정답/`, `문제 코드/강사용_정답_가이드.md`, `최종 결과 산출물/01_강사용_수업진행안.md`, `최종 결과 산출물/04_강사용_정답_및_채점표.md`, `강사_제공_산출물/11_강사용_정답_및_피드백_가이드.md`
- 채점기준은 `문제 출제 예시.pdf`와 비슷한 상세 수준으로 수행준거별 4단계 점수 구간을 작성한다. 별도 지시가 없다면 배점 합계가 100점인지 확인한다.
- 편집 후 한글 인코딩, 상대 경로 및 내부 링크를 확인한다. 이 문서는 비전공 강사도 사용한다.

### 제작 검토 역할

서브에이전트는 `AGENTS.md`의 배정 기준과 `.agents/`의 역할 지침을 따른다.

- `ncs-source-analyst`: NCS 원본과 예시 PDF 전체를 읽고 페이지 근거와 함께 요구사항을 수행준거 ID에 연결한다. 파일은 수정하지 않는다.
- `frontend-exam-reviewer`: `문제 코드`와 `정답`을 비교하고 의도된 결함 3건의 재현 여부, 학생용 안내의 정답 노출 여부 및 HTML/CSS/JavaScript/GitHub 범위 준수 여부를 확인한다.
- `assessment-qa-reviewer`: 채점기준 총점, 강사용·학생용 자료의 분리 여부 및 필요한 경우 실제 등록 화면과 로컬 최종 자료의 일치 여부를 검수한다.

최종 판단은 주 에이전트가 담당하며, 서브에이전트의 결과를 사용자의 최신 요청과 대조하여 조정한다.

### 현행 `문제 코드`와 `정답`의 실습 구조

`예시 코드/`는 학생이 이미 학습한 작은 `brivyy` 헤더 예제이다. `정답/`과 `문제 코드/`는 같은 학습 방식을 사용해 MALBON GOLF 랜딩 페이지를 구현한다. `문제 코드/index.html`과 `정답/index.html`은 **동일한 HTML을 유지해야 한다**. 현재 실습의 수정 대상은 CSS이므로 마크업 내용을 변경해야 한다면 두 파일에 똑같이 반영해야 한다. 그렇지 않으면 `정답.png`와 비교하는 채점 방식이 깨진다.

#### CSS 연결 계층

다음 순서는 `예시 코드/css/`에서 사용하며, `정답/css/`에서는 8개 파일로 분리되고 `문제 코드/css/style.css`에서는 하나로 합쳐져 있다. CSS를 다시 연결할 때 이 순서를 유지한다.

| 순서 | 파일 | 역할 |
|---|---|---|
| 1 | `normal.css` | 글꼴 선언, 초기화, HTML 기본 요소 설정 |
| 2 | `root.css` | 색상, 글자 크기와 굵기, `--numN` 간격, 그리드 너비 등 기본 디자인 토큰 |
| 3 | `component.css` | `--main`, `--ink`, `--text-XS`, 여백, 아이콘, 모서리 값 등 페이지 구성요소용 의미 토큰 |
| 4 | `btn_cpn.css` | 버튼, 아이콘, 탭, 슬라이드 및 맨 위로 이동 제어 요소 |
| 5 | `item_cpn.css` | 글자와 색상 보조 클래스, 이미지 영역, 상품명, 가격, 색상 견본 항목 |
| 6 | `layout_cpn.css` | `.con` 컨테이너, `.grid-5/4/3/2`, 섹션 및 제목 배치 구조 |
| 7 | `style.css` | 헤더부터 푸터와 모바일 내비게이션까지 페이지 영역별 스타일 |
| 8 | `media.css` | 1600px, 1024px, 768px, 480px 반응형 재정의. 사용자 정의 속성은 `@media` 조건에서 사용할 수 없으므로 고정 px 값을 사용한다. |

`문제 코드/index.html`은 `css/style.css` 하나만 연결한다. 모든 CSS 규칙은 위 순서로 합쳐져 있다. 학생은 HTML 내용을 건드리지 않고 CSS를 위의 8개 파일로 다시 분리하면서 의도적으로 삽입한 결함 3건을 수정한다.

#### 의도된 결함 3건

다음 내용은 `문제 코드/css/style.css`, `문제 코드/강사용_정답_가이드.md`, `최종 결과 산출물/04_강사용_정답_및_채점표.md`에서 서로 일치해야 한다. 하나를 변경하면 세 파일을 모두 갱신한다.

| ID | 선택자 | 잘못된 선언 | 증상 | 수정 방법 |
|---|---|---|---|---|
| BUG-01 | `.con` | `max-width: var(--containner);` 사용자 정의 속성명 오타 | 값이 `none`으로 처리되어 넓은 화면에서 컨테이너가 가운데 정렬되거나 최대 너비로 제한되지 않는다. 1600px 이상, 특히 1920px에서 확인할 수 있다. | `var(--container)`로 수정 |
| BUG-02 | `.grid-5` | `grid-template-columns: repeat(5 1fr);` 쉼표 누락 | 값이 무효 처리되어 BEST PICKS 그리드가 한 열로 표시된다. | `repeat(5, 1fr)`로 수정 |
| BUG-03 | `body` | `min-width: 1600px;` | 미디어쿼리는 실행되지만 페이지가 1600px보다 작아질 수 없어 태블릿과 모바일 화면에 가로 스크롤이 생긴다. | 해당 선언 삭제 |

결함은 이전 제한사항에 따라 Flex 속성 오류로 만들지 않는다. HTML을 읽지 않고도 개발자 도구의 Computed와 Layout 패널로 진단할 수 있어야 한다. 학생용 파일의 결함 옆에 `/* [!] ... */` 형태의 힌트 주석을 추가하지 않는다. 학생은 주석이 아니라 `정답.png`와 화면을 비교하여 결함을 찾아야 한다.

### 로컬 미리보기

별도의 빌드 과정은 없다. 두 폴더를 정적 파일로 제공하여 결과를 비교한다.

```bash
python -m http.server 8792 --directory "국비/정답"
python -m http.server 8793 --directory "국비/문제 코드"
```

이 작업공간에서 사용하는 Playwright MCP 도구는 `file://` 이동을 차단하므로 항상 `http://localhost`로 제공한다. 평가 및 검증 화면 너비는 **1920px, 1600px, 1024px, 768px, 480px**이다. 각각 컨테이너 최대 너비, `.con` 여백 분기점, GNB와 햄버거 메뉴 전환점, 2열 그리드 분기점, 모바일 간격을 확인하기 위한 값이며 강사용 자료에서 학생에게 안내하는 정확한 시험 너비이다.

### `문제 코드/정답.png` 다시 생성하기

참고 화면은 결함을 수정한 `정답/`을 기준으로 1600px 컨테이너 최대 너비보다 넓은 화면에서 캡처한다. 기존 이미지는 1920px에서 만들었다. 정확히 1600px에서 캡처하면 컨테이너 최대 너비와 화면 너비가 같아져 BUG-01의 가운데 정렬 결함이 보이지 않는다.

## B. 채점 및 피드백 파이프라인

### 트리거와 대화 규칙

사용자가 **`채점 진행해줘`**라고 입력하면 이 파이프라인을 시작한다.

1. 트리거 메시지에 능력단위명이 함께 적혀 있어도 다른 작업을 시작하기 전에 `채점할 능력단위명을 입력해주세요.`라고 한 가지 질문만 하고 다음 답을 기다린다.
2. 사용자가 답한 문자열을 기준 능력단위명으로 고정한다. 철자·공백이 다른 유사 파일을 자동 선택하지 않는다.
3. 사용자의 다음 답을 받은 후에만 필수 파일 확인을 시작한다.
4. 이 트리거는 검증이 끝난 학생별 점수와 피드백을 아래 지정 사이트에 등록하는 요청도 포함한다. 다만 학생 매칭, 수행준거 또는 기존 점수와 충돌하면 해당 등록은 보류한다.

### 상태 1: 입력 파일 확인

`국비` 폴더에서 다음 세 파일을 정확히 확인한다.

| 파일 | 역할 |
|---|---|
| `피드백.md` | 공통 채점 원칙, 증빙 방법, 화면 피드백과 결과 형식 |
| `<능력단위명> 수행준거.txt` | 현재 능력단위의 수행준거 원문·순서·개수 |
| `평가_리포지터리_주소.txt` | `[학생 이름]`과 GitHub 저장소 URL의 매핑 |

- 파일이 없으면 비슷한 이름의 다른 능력단위 자료로 대체하지 않는다.
- 수행준거 파일이 여러 개면 기준 능력단위명과 정확히 일치하는 한 개만 사용한다.
- 저장소 목록은 `[학생 이름]` 다음에 나오는 첫 URL을 해당 학생의 저장소로 해석한다.
- 중복 학생명, 중복 URL, 잘못된 URL 형식, 이름만 있고 URL이 없는 행을 채점 전에 검출한다.

### 상태 2: `Exam.md` 재작성

`Exam.md`는 현재 채점의 단일 실행 기준이다. 이전 내용에 이어 쓰지 않고 현재 능력단위 기준으로 전체 재작성한다.

필수 구성:

1. 능력단위명, 작성일, 근거 파일명
2. 평가 범위와 제출물
3. 수행준거 원문과 문항 ID의 일대일 추적표
4. 수행준거별 정수 배점과 총점 100점
5. 수행준거마다 별도의 구체적인 4단계 점수 구간
6. 문항별 필수 증빙: 파일, 선택자, 화면 너비, 동작, 브라우저 패널, Git 기록 또는 화면 캡처
7. 같은 결함의 중복 감점 방지 규칙
8. 학생별 채점 결과와 화면 피드백 출력 형식
9. `평가_리포지터리_주소.txt`에서 읽은 평가 대상 학생명·저장소 URL·리포지터리 이름 매핑
10. 사이트 입력 전 검증 체크리스트

작성 규칙:

- 수행준거 수와 문항 수는 반드시 같다.
- 수행준거를 임의로 합치거나 나누거나 삭제하지 않는다.
- `피드백.md`의 기본 루브릭은 구조와 작성 수준의 참고자료이며, 현재 능력단위 수행준거에 맞게 문구와 증빙을 다시 작성한다.
- 과제 요구사항에서 중요도를 판단하여 배점을 정하고 근거를 남긴다. 모든 배점과 취득점은 정수로 한다.
- 하나의 공통 등급표를 모든 문항에 복사하지 않는다.
- 작성 후 수행준거 수, 문항 수, 점수 구간의 빈틈, 총점, 한글 UTF-8과 파일 링크를 검사한다.

### 상태 3: 학생 저장소 접속과 증빙 수집

학생별로 다음 순서를 반복한다.

1. `평가_리포지터리_주소.txt`에서 학생 이름, 저장소 URL과 URL의 리포지터리 이름을 읽는다.
2. 저장소의 기본 브랜치, 최신 제출 커밋 해시와 확인 시각을 기록한다.
3. 저장소를 읽기 전용 기준으로 다루고 학생 파일을 수정하거나 push하지 않는다.
4. HTML·CSS·JavaScript와 자산 경로를 정적으로 검토한다.
5. 필요한 경우 격리된 검토 환경에서 정적 서버로 실행한다. 학생 저장소의 설치·빌드 스크립트를 이유 없이 실행하거나 비밀정보가 있는 브라우저 프로필에서 학생 JavaScript를 열지 않는다.
6. `Exam.md`가 지정한 모든 화면 너비와 상호작용을 확인한다.
7. Console 오류, Network 404, 접근성 이름과 키보드 상태를 확인한다.
8. README, 커밋 기록, 배포 URL과 협업 증빙을 확인한다.
9. 목표 이미지가 있으면 같은 화면 너비와 상태에서 비교하되, 디자인 자유 영역의 단순 취향 차이는 감점하지 않는다.

증빙을 열지 못한 경우:

- 학생의 필수 제출 누락과 평가 환경 장애를 구분한다.
- 확인하지 못한 동작을 통과로 기록하지 않는다.
- 평가 환경 문제는 `평가 보류`로 남기고 0점으로 단정하지 않는다.

### 상태 4: 채점과 피드백 작성

1. `Exam.md` 문항 순서대로 직접 증빙을 4단계 기준에 대조한다.
2. 다른 학생과의 상대 순위가 아니라 해당 학생 증빙으로 절대평가 원점수를 결정한다.
3. 원점수는 0~100점으로 보존하고 등록총점은 `ROUND(60 + (원점수 × 0.4), 0)`으로 계산해 정수만 사용한다. 원점수 0점은 등록점수 60점, 원점수 100점은 등록점수 100점이다.
4. 문항별 이상적 환산값 `문항 배점 × 0.6 + 문항 원점수 × 0.4`는 중간 계산에만 사용한다. 각 값을 내림한 뒤 전체 정수 등록총점과의 차이를 소수 나머지가 큰 문항부터 1점씩 배분하고, 동률이면 앞선 문항 ID를 우선한다. 사이트에는 이 최대잔여법으로 확정한 문항별 정수만 입력한다.
5. 모든 원점수에 파일·선택자·화면·동작·Git 기록 중 하나 이상의 근거를 적는다.
6. 같은 원인으로 여러 문항을 감점하면 각 수행준거를 독립적으로 침해한 이유를 적는다. 이유가 없으면 한 문항에서만 감점한다.
7. 각 학생에게 코드 피드백과 화면 피드백을 모두 작성한다.
8. 사이트 입력용 피드백은 주요 결함 3~7개를 `학생 코드 → 최소 정답 코드 → 피드백` 형식으로 작성한다. 코드 앞에는 언어명만 한 줄로 쓰고 Markdown 백틱은 사이트 입력문에 넣지 않는다. 피드백 문장은 관찰 사실, 요구사항 차이, 영향, 수정 방향 순으로 쓴다.
9. 학생 공개용 사이트 피드백에는 원점수, 등록점수, 총점, 60~100점 환산 범위·공식·과정, 통과 여부, 순위 또는 내부 채점 판단을 적지 않는다. 점수는 내부 결과표와 사이트 점수 입력란에만 보존하며 마지막 문단은 개선 방향과 격려로 마무리한다.
10. 결함별 비교 다음에는 완성 영역, 미완성 영역, 빠른 구현 순서, 응용·재검증, 전체 정리와 격려의 5개 문단을 이어 쓴다.
11. 강사용 정답 전체를 복사하지 않고 학생이 스스로 수정할 수 있는 최소 코드만 제공한다.
12. 문항별 원점수 합계와 문항별 등록점수 합계를 각각 다시 계산한다.

### 상태 5: `채점 완료/<학생 이름>.txt` 생성

`채점 완료` 폴더가 없으면 만든다. 학생마다 UTF-8 텍스트 파일 하나를 생성하며 파일명은 정확히 `<학생 이름>.txt`로 한다.

파일 형식:

```text
[기본 정보]
능력단위명:
학생 이름:
저장소 URL:
리포지터리 이름:
채점 브랜치/커밋:
채점 시각:

[문항별 점수]
문항 ID / 수행준거 / 배점 / 원점수 / 등록점수 / 직접 증빙 / 판단 근거

[합계 및 판정]
원점수 합계:
등록점수(60~100점 환산):
통과 여부:
평가 보류:

[피드백]
잘한 점:
우선 수정 사항:
화면 피드백:
재검증 방법:

[사이트 입력용 코드 비교 피드백]
주요 결함 1~N: 학생 코드 / 최소 정답 코드 / 피드백
종합 문단 1: 완성 영역
종합 문단 2: 미완성 영역
종합 문단 3: 빠른 구현 순서
종합 문단 4: 응용·재검증
종합 문단 5: 전체 정리와 격려

[사이트 등록]
등록 상태: 대기/완료/보류/실패
저장 확인 시각:
비고:
```

사이트 등록 전 다음을 확인한다.

- 평가 대상 학생 수 = 유효 저장소 수 = 학생별 결과 파일 수
- 모든 학생 파일에 모든 문항의 배점, 원점수와 등록점수가 있음
- 학생별 문항 원점수 합계 = 원점수 총점
- 학생별 문항 정수 등록점수 합계 = `ROUND(60 + (원점수 총점 × 0.4), 0)`
- 화면 피드백 또는 화면 검토 보류 사유가 있음
- 사이트 입력용 피드백에 주요 결함별 코드 비교와 5개 종합 문단이 있음
- 사이트 입력용 피드백에 원점수·등록점수·총점·환산 방식·통과 여부·순위가 없음
- 저장소 URL, 리포지터리 이름과 학생 이름 매핑이 보존됨

### 상태 6: SBS아카데미 평가 사이트 등록

등록 주소:

`https://sbsartdj.maniaro.net/teacher/ver4/curri/appraisal/app/appraisal.php?Pcode=300002&Lcode=8&AppCode=AH`

자동화 제어가 가능한 로그인된 브라우저를 사용한다. 학생별 등록 순서는 다음과 같다.

1. 페이지의 과정·평가·능력단위가 현재 `Exam.md`와 일치하는지 확인한다.
2. `평가_리포지터리_주소.txt`의 `[학생 이름]`과 리포지터리 이름을 대조하여 학생을 하나로 확정한다.
3. 해당 학생 행의 **채점하기**를 클릭한다.
4. **평가점수 일괄등록**을 클릭한다.
5. 화면의 수행준거 문구와 `Exam.md`를 대조하며 문항별 등록점수를 입력한다. 단순히 화면의 행 순서만 믿지 않는다.
6. 입력된 점수 합계가 `채점 완료/<학생 이름>.txt`의 환산 등록점수와 같은지 확인한다.
7. **`이곳에 피드백을 입력하세요.`** 입력란에 결함별 코드 비교와 5개 종합 문단이 포함된 학생용 피드백 전체를 작성한다.
8. 최종 **채점하기**를 클릭한다.
9. 저장 완료 후 상세 화면을 다시 확인하여 학생명, 문항별 등록점수, 환산 총점, 피드백이 로컬 결과와 같은지 검증한다.
10. 성공 여부와 확인 시각을 학생 결과 파일의 `[사이트 등록]`에 반영한다.

### 사이트 등록 안전 규칙

- 로그인되지 않았거나 권한이 없으면 사용자 계정 정보를 추측하거나 입력하지 않는다.
- 학생이 0명 또는 2명 이상 매칭되면 해당 학생에게 아무 값도 등록하지 않는다.
- 사이트 수행준거 수·문구·총점이 `Exam.md`와 다르면 입력을 중단한다.
- 기존 점수나 피드백이 있고 새 로컬 결과와 다르면 덮어쓰기 전에 사용자에게 알린다.
- 한 학생의 결과를 다른 학생 행에 입력하지 않는다.
- 최종 버튼 클릭 후 저장 상세 화면을 확인하지 못한 건은 `완료`가 아니라 `확인 필요`로 기록한다.
- 일부 학생이 막혀도 다른 학생 매칭과 기준이 명확하면 계속 진행한다. 마지막에 완료·보류·실패 명단을 구분해 보고한다.
- 재개할 때는 학생 결과 파일의 등록 상태와 사이트 상세 화면을 먼저 비교하여 중복 등록을 방지한다.

다음을 모두 충족해야 전체 채점 완료로 보고한다.

- 현재 능력단위 기준 `Exam.md` 작성 및 검증 완료
- 모든 접근 가능한 학생 저장소의 코드·화면·Git 증빙 검토 완료

- 등록 가능한 모든 학생의 사이트 입력과 저장 결과 확인 완료
- 보류 또는 실패 학생의 이름, 원인, 필요한 사용자 조치 정리 완료
