# CLAUDE.md

이 파일은 Claude Code(claude.ai/code)가 이 저장소에서 작업할 때 따라야 하는 지침을 제공한다.

## 작업공간의 목적

이곳은 소프트웨어 제품 저장소가 아니라 `수정 보완(LM0802010406_13v1)` 능력단위의 **NCS(국가직무능력표준) 직업훈련 평가자료**를 작성하는 작업공간이다. 수업 범위는 HTML, CSS, JavaScript, Git, GitHub이며 백엔드는 사용하지 않는다. 이곳의 코드(`정답/`, `문제 코드/`, `예시 코드/`)는 제품 출시가 아니라 CSS 구조와 반응형 레이아웃 오류 수정 방법을 교육하고 평가하기 위한 것이다. Markdown 산출물과 HTML/CSS 실습 문제를 모두 평가 대상 산출물로 중요하게 다룬다.

이 폴더의 `AGENTS.md`가 작업 목적, 원칙 및 서브에이전트 배정을 정의하는 최상위 작업 지침이다. 중요한 변경을 수행하기 전에 해당 파일을 읽는다. 이 파일은 Claude Code에 필요한 세부 지침을 추가로 제공한다.

## 자료 우선순위

자료가 서로 충돌하면 `skills/ncs-exam-production/references/project-map.md`에 따라 다음 순서로 판단한다.

1. 사용자의 최신 요청
2. 현재 `문제 코드/`와 `정답/`의 파일
3. 해당 NCS 원본 PDF(`[5](수정 보완)LM...pdf`, 요약본은 `pdf요약결과.md`)
4. 등록 형식과 채점기준의 상세 수준을 확인하기 위한 `문제 출제 예시.pdf`
5. 기존에 작성된 Markdown 및 생성된 PDF

## 작업 원칙

- 편집하기 전에 현재 파일 구조를 확인하고 파일 배치를 추측하지 않는다.
- `문제 코드/`와 `정답/`을 현재 코드의 기준으로 삼는다. `강사_제공_산출물/`과 `학생_제출_산출물/`에는 이전의 상세 시나리오인 가상의 `EDU-PORTAL-2026` 프로젝트 자료 15개가 있다. 현재 사용하는 간결한 실습 문제는 `최종 결과 산출물/`의 문서 4개와 `문제 코드/`, `정답/`이다. 사용자가 요청하지 않으면 두 시나리오를 합치거나 일치시키지 않는다.
- 백엔드, 데이터베이스, 서버, 프레임워크 또는 배포 요구사항을 추가하지 않는다. 수업 범위는 HTML, CSS, JavaScript, Git, GitHub이다.
- 최종 자료는 `최종 결과 산출물/`에 간결하게 정리하고 명시적인 요청 없이 중복 출력 폴더를 만들지 않는다.
- 강사용 자료와 학생용 자료를 분리하고 학생용 파일에 정답을 노출하지 않는다.
  - 학생 제공 가능: `문제 코드/index.html`, `문제 코드/css/style.css`, `문제 코드/정답.png`, `최종 결과 산출물/02_학생용_과제안내서.md`, `최종 결과 산출물/03_학생_제출_산출물.md`, `강사_제공_산출물/01`~`10`
  - 강사 전용이며 평가 전에 배포 금지: `정답/`, `문제 코드/강사용_정답_가이드.md`, `최종 결과 산출물/01_강사용_수업진행안.md`, `최종 결과 산출물/04_강사용_정답_및_채점표.md`, `강사_제공_산출물/11_강사용_정답_및_피드백_가이드.md`
- 채점기준은 `문제 출제 예시.pdf`와 비슷한 상세 수준으로 수행준거별 4단계 점수 구간을 작성한다. 별도 지시가 없다면 배점 합계가 100점인지 확인한다.
- 편집 후 한글 인코딩, 상대 경로 및 내부 링크를 확인한다. 이 문서는 비전공 강사도 사용한다.

## 서브에이전트

서브에이전트는 `AGENTS.md`의 배정 기준과 `.agents/`의 역할 지침을 따른다.

- `ncs-source-analyst`: NCS 원본과 예시 PDF 전체를 읽고 페이지 근거와 함께 요구사항을 수행준거 ID에 연결한다. 파일은 수정하지 않는다.
- `frontend-exam-reviewer`: `문제 코드`와 `정답`을 비교하고 의도된 결함 3건의 재현 여부, 학생용 안내의 정답 노출 여부 및 HTML/CSS/JavaScript/GitHub 범위 준수 여부를 확인한다.
- `assessment-qa-reviewer`: 채점기준 총점, 강사용·학생용 자료의 분리 여부 및 필요한 경우 실제 등록 화면과 로컬 최종 자료의 일치 여부를 검수한다.

최종 판단은 주 에이전트가 담당하며, 서브에이전트의 결과를 사용자의 최신 요청과 대조하여 조정한다.

## `문제 코드`와 `정답`의 실습 구조

`예시 코드/`는 학생이 이미 학습한 작은 `brivyy` 헤더 예제이다. `정답/`과 `문제 코드/`는 같은 학습 방식을 사용해 MALBON GOLF 랜딩 페이지를 구현한다. `문제 코드/index.html`과 `정답/index.html`은 **동일한 HTML을 유지해야 한다**. 현재 실습의 수정 대상은 CSS이므로 마크업 내용을 변경해야 한다면 두 파일에 똑같이 반영해야 한다. 그렇지 않으면 `정답.png`와 비교하는 채점 방식이 깨진다.

### CSS 연결 계층

다음 순서는 `예시 코드/css/`에서 사용하며, `정답/css/`에서는 8개 파일로 분리되고 `문제 코드/css/style.css`에서는 하나로 합쳐져 있다. CSS를 다시 연결할 때 이 순서를 유지한다.

| 순서 | 파일 | 역할 |
|---|---|---|
| 1 | `normal.css` | 글꼴 선언, 초기화, HTML 기본 요소 설정 |
| 2 | `root.css` | 색상, 글자 크기와 굵기, `--numN` 간격, 그리드 너비 등 기본 디자인 토큰 |
| 3 | `component.css` | `--main`, `--ink`, `--text-XS`, 여백, 아이콘, 모서리 값 등 페이지 구성요소용 의미 토큰 |
| 4 | `btn_cpn.css` | 버튼, 아이콘, 탭, 슬라이드 및 맨 위로 이동 제어 요소 |
| 5 | `item_cpn.css` | 글자와 색상 보조 클래스, 이미지 영역, 상품명, 가격, 색상 견본 항목 |
| 6 | `layout_cpn.css` | `.con` 컨테이너, `.grid-5/4/3/2`, 섹션 및 제목 배치 구조 |
| 7 | `style.css` | 헤더부터 푸터와 모바일 내비게이션까지 페이지 영역별 스타일 |
| 8 | `media.css` | 1600px, 1024px, 768px, 480px 반응형 재정의. 사용자 정의 속성은 `@media` 조건에서 사용할 수 없으므로 고정 px 값을 사용한다. |

`문제 코드/index.html`은 `css/style.css` 하나만 연결한다. 모든 CSS 규칙은 위 순서로 합쳐져 있다. 학생은 HTML 내용을 건드리지 않고 CSS를 위의 8개 파일로 다시 분리하면서 의도적으로 삽입한 결함 3건을 수정한다.

### 의도된 결함 3건

다음 내용은 `문제 코드/css/style.css`, `문제 코드/강사용_정답_가이드.md`, `최종 결과 산출물/04_강사용_정답_및_채점표.md`에서 서로 일치해야 한다. 하나를 변경하면 세 파일을 모두 갱신한다.

| ID | 선택자 | 잘못된 선언 | 증상 | 수정 방법 |
|---|---|---|---|---|
| BUG-01 | `.con` | `max-width: var(--containner);` 사용자 정의 속성명 오타 | 값이 `none`으로 처리되어 넓은 화면에서 컨테이너가 가운데 정렬되거나 최대 너비로 제한되지 않는다. 1600px 이상, 특히 1920px에서 확인할 수 있다. | `var(--container)`로 수정 |
| BUG-02 | `.grid-5` | `grid-template-columns: repeat(5 1fr);` 쉼표 누락 | 값이 무효 처리되어 BEST PICKS 그리드가 한 열로 표시된다. | `repeat(5, 1fr)`로 수정 |
| BUG-03 | `body` | `min-width: 1600px;` | 미디어쿼리는 실행되지만 페이지가 1600px보다 작아질 수 없어 태블릿과 모바일 화면에 가로 스크롤이 생긴다. | 해당 선언 삭제 |

결함은 이전 제한사항에 따라 Flex 속성 오류로 만들지 않는다. HTML을 읽지 않고도 개발자 도구의 Computed와 Layout 패널로 진단할 수 있어야 한다. 학생용 파일의 결함 옆에 `/* [!] ... */` 형태의 힌트 주석을 추가하지 않는다. 학생은 주석이 아니라 `정답.png`와 화면을 비교하여 결함을 찾아야 한다.

## 로컬 미리보기

별도의 빌드 과정은 없다. 두 폴더를 정적 파일로 제공하여 결과를 비교한다.

```bash
python -m http.server 8792 --directory "국비/정답"
python -m http.server 8793 --directory "국비/문제 코드"
```

이 작업공간에서 사용하는 Playwright MCP 도구는 `file://` 이동을 차단하므로 항상 `http://localhost`로 제공한다. 평가 및 검증 화면 너비는 **1920px, 1600px, 1024px, 768px, 480px**이다. 각각 컨테이너 최대 너비, `.con` 여백 분기점, GNB와 햄버거 메뉴 전환점, 2열 그리드 분기점, 모바일 간격을 확인하기 위한 값이며 강사용 자료에서 학생에게 안내하는 정확한 시험 너비이다.

## `문제 코드/정답.png` 다시 생성하기

참고 화면은 결함을 수정한 `정답/`을 기준으로 1600px 컨테이너 최대 너비보다 넓은 화면에서 캡처한다. 기존 이미지는 1920px에서 만들었다. 정확히 1600px에서 캡처하면 컨테이너 최대 너비와 화면 너비가 같아져 BUG-01의 가운데 정렬 결함이 보이지 않는다.
