## 2. 핵심 요약

이 학습모듈은 디지털 디자인 구현 단계에서 생성된 산출물을 **심미적 디자인**, **콘텐츠 사용성**, **매체 기능**의 세 영역으로 나누어 리뷰하고, 결함을 수정·보완한 뒤 재검증하는 실무 절차를 다룬다.

전체 업무 흐름은 다음과 같다.

1. 기획서·요구사항정의서·스토리보드·명세서 등 산출물을 준비한다.
2. PM, PL, 디자인/개발 담당자 등으로 검토자와 리뷰 담당자를 구성한다.
3. 중요도와 우선순위가 포함된 체크리스트와 리뷰 시나리오를 작성한다.
4. 결함을 `F(결함)`, `C(경결함)`, `B(단순 결함)`, `A(결함 없음)`으로, 결과를 `Y(적합)`, `N(수정·보완)`, `A(수용)`로 기록한다.
5. 수정·보완 작업 목록과 계획서를 작성하고 우선순위에 따라 작업한다.
6. 작업자가 단위 테스트를 수행하고 조치 내역을 보고서로 남긴다.
7. 전체 산출물을 재검증하고, 필요하면 추가 수정·승인 절차를 반복한다.

## 3. 학습별 내용

### 학습 1. 심미적 디자인 요소 수정·보완

- 대상: 콘셉트, 내비게이션, 페이지 레이아웃, 아이콘, 폰트, 색상, UI 구조, 반응형·다크모드·접근성·인터랙션 요소
- 주요 검토: 그리드, 시각적 계층, 여백, 색 대비, CI/BI, 디바이스별 레이아웃, 화면 회전, 브랜드 일관성
- 핵심 산출물: 디자인 리뷰 체크리스트, 수정·보완 작업 목록, 계획서, 보고서
- 우선순위: 출시를 막는 치명적 문제(상) → UX·브랜드에 영향을 주는 문제(중) → 여건에 따라 개선할 문제(하)

### 학습 2. 콘텐츠 사용성 수정·보완

- 대상: 텍스트, 이미지, 오디오, 동영상, 문서 구조, 반응형/적응형 콘텐츠
- 주요 검토: 대체 텍스트, 자막·원고·수어, 논리적 순서, 표 구조, 깜빡임 제한, 제목, 색 이외의 정보 전달, 명암 대비, 이미지 맵 대체 링크
- 표준 관점: 웹 사용성, 웹 표준, KWCAG 2.2 기반 웹 접근성, 호환성·보안 지침
- 수정 예: 이미지 `alt` 제공, 동영상 동기화 자막, 의미에 맞는 HTML 태그, HTML/CSS 구조 분리, 디바이스·브라우저·해상도 대응

### 학습 3. 매체 기능적 요소 수정·보완

- 대상: 회원가입, 로그인/로그아웃, 게시판, 파일 업·다운로드, 입력값 검증, 세션, 로그, 응답 성능
- 주요 위험: SQL 인젝션, XSS, 세션 탈취, 잘못된 입력, 권한·로그 관리 미흡
- 수정 예: 자동 로그아웃, 입력·수정·삭제 활동 로깅, 서버 측 입력 검증, 브라우저 호환성 점검
- 프로그래밍 기초: JavaScript, jQuery, PHP/JSP/ASP.NET, DB, SQL, 웹 서버의 개념과 간단한 실습 예제

## 4. 교육·평가 구성

- 이론 설명 후 실제 산출물을 이용한 체크리스트 작성, 동료 리뷰, 수정, 재검증을 수행하는 프로젝트형 구성이다.
- 평가는 **작업 결과물**과 **작업 과정 관찰**로 나뉘며, 영역별 성취수준을 상·중·하로 판정한다.
- 활용 서식은 디자인·콘텐츠·기능 각 영역에 대해 리뷰 체크리스트, 환경 정보, 작업 목록, 계획서, 보고서의 5종씩 총 15종이 제공된다.

## 5. 문서의 강점

- 리뷰 → 우선순위 설정 → 수정 → 단위 테스트 → 재검증의 흐름이 일관되어 실무 프로세스 학습에 유용하다.
- 담당자, 일정, 중요도, 조치 내역, 산출물을 기록하게 해 협업과 변경 이력 추적을 강조한다.
- 심미성만이 아니라 사용성·접근성·호환성·보안을 포함해 디지털 산출물을 통합적으로 다룬다.
- 2025년 수정본에 반응형 UI, 다크모드, AI 기반 리뷰, 접근성, H.265·AV1·VP9 등 최근 키워드가 보강되었다.

## 6. 수정·보완이 필요한 사항

### 우선순위 상: 기술·보안 오류

1. **PHP/SQL 예제의 문법 오류와 SQL 인젝션 위험**(PDF 76쪽)
   - `VALUES ('$_POST[name])', '$_POST[age]')` 부분의 따옴표와 괄호가 잘못되어 실행되지 않는 코드이다.
   - 사용자 입력을 SQL에 직접 연결하여, 앞에서 설명한 SQL 인젝션 방지 원칙과 모순된다.
   - **권장:** `mysqli`/PDO 준비된 문장, 서버 측 검증, 오류 처리가 포함된 안전한 예제로 교체한다.

2. **클라이언트 검증에 의존하는 예제**(PDF 73~74쪽)
   - JavaScript 검증은 사용자 편의 기능일 뿐 보안 검증이 아니므로, 서버 측 검증을 반드시 병행해야 한다는 설명을 추가해야 한다.

3. **웹 접근성·보안 기준의 정확한 근거 부족**(PDF 52~55쪽)
   - KWCAG 2.2, 법적 의무, OWASP 취약점을 언급하지만 표준 번호, 고시명, 버전, 발행일, 원문 URL 등이 참고 자료에 충분히 연결되지 않았다.
   - `안전행정부`, `한국정보문화진흥원` 등 구 기관명을 현행 기관·지침명으로 검증할 필요가 있다.

### 우선순위 중: 최신성·정합성

4. **리뷰 환경 예시가 심각하게 노후함**(PDF 18, 39, 63쪽)
   - IBM S80, RS64 III/IV, 4GB 메모리, Oracle 8.1, JEUS 3.1 구성을 2025년 개정본에 반복 사용한다.
   - **권장:** 클라우드/컨테이너, 현행 LTS OS·DB·런타임, 모바일 실기기, 주요 브라우저 버전, 접근성 테스트 도구를 포함한 환경으로 갱신한다.

5. **Internet Explorer 기준의 호환성 테스트**(PDF 45, 66쪽)
   - 지원이 종료된 Internet Explorer를 주요 브라우저로 제시하고 있다.
   - **권장:** Chromium 계열, Firefox, Safari, 모바일 WebView와 자동화된 크로스 브라우저 테스트로 교체한다.

6. **프로그래밍 단원의 현재 실무 반영 부족**
   - `document.write`, 인라인 `onclick`, 전역 함수, jQuery 중심 설명, PHP/JSP/ASP.NET 나열은 현재의 모듈·이벤트·API 기반 개발 방식을 충분히 반영하지 못한다.
   - jQuery의 라이선스를 MIT/GPL v2 듀얼 라이선스로 설명한 부분도 현재 배포 정보와 일치하는지 확인이 필요하다.

7. **수치 기준의 근거 부족**
   - `동시 사용자 100명`, `30초 이내 응답`, `30분 미사용 시 접속 종료`, `6개월 미접속 시 차단`, `메인 메뉴 7개 이하` 등이 일반 기준처럼 제시되지만, 실제로는 프로젝트 요구사항과 위험 분석에 따라 정해야 한다.

## 7. 종합 평가

문서의 핵심 교육 구조는 타당하다. 특히 산출물을 리뷰하고 수정 이력을 남긴 뒤 재검증하는 순환 구조는 현장 훈련에 적합하다. 다만 2025년 수정·보완본임에도 2013년 예시와 노후한 장비·소프트웨어·브라우저가 다수 잔존하며, 보안을 설명하는 단원의 코드 예제 자체가 실행 불가 및 SQL 인젝션 취약성을 가진 점은 우선 수정이 필요하다.

따라서 최종본 품질을 높이려면 **① 보안 코드 예제 교체, ② 노후 환경·브라우저 갱신, ③ 표준·법령·기술 정보의 1차 출처 보강, ④ 오타와 용어 통일, ⑤ 반복 내용 재구성** 순으로 수정하는 것이 바람직하다.
