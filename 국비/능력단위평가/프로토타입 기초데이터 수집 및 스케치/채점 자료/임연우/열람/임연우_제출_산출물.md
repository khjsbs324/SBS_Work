## 2. 프로젝트 브리프

### 2.1 배경과 문제

- **프로젝트 배경:** `[프로젝트]` 스밈은 ‘스며들다’에서 출발한 가상 웰니스 브랜드다. 강하게 조이는 교정 장치보다 일상복 안에서 자연스럽게 사용하는 코어웨어와 디지털 케어를 연결하는 방향을 제시한다. 브랜드·서비스 원문은 제품, AI 케어, 오프라인 접점을 포함하지만 본 보고서의 범위는 웹사이트에서 제품을 이해하고 비교해 시착을 준비하는 과정으로 한정한다. 근거: D-01·D-02.
- **해결할 사용자 문제:** `[설계]` 제품명만으로 착용 부위와 구조를 구분하기 어렵고, 가격 외에 사용 장면·착용 방식·옵션을 확인할 정보가 부족하면 선택을 망설일 수 있다. 설명을 읽은 뒤에도 상품 목록과 장바구니 사이의 이동이 명확해야 한다.
- **대상 사용자와 사용 맥락:** `[프로젝트/미검증]` PC 작업 시간이 긴 직장인, 개발자·디자이너 등 데스크 업무 종사자, 출근복 안에 입을 제품을 비교하는 구매 예정자다. 업무 중 짧은 탐색이나 퇴근 후 모바일 비교를 가정한다. 이는 기존 기획의 타깃이며 실제 표본조사로 확정한 사용자 집단은 아니다.
- **프로젝트 목표:** 브랜드의 존재 이유를 먼저 이해시키고, 대표 3종과 전체 15종을 구분해 탐색하게 한다. 관심 상품에서는 구조·사용 순서·사이즈·관리 정보를 읽고 예시 리뷰를 확인한 뒤, 옵션을 선택해 장바구니 또는 시착 모달로 이동하도록 설계한다.
- **핵심 과업:** “데스크 업무에 사용할 어깨·경추 제품을 찾아 상세정보와 리뷰를 확인하고, 원하는 사이즈·색상으로 장바구니에 담은 뒤 시착 내용을 확인한다.” 실제 결제·배송·접수 완료는 성공 조건에 포함하지 않는다.

- 상세를 더 읽을 때: S-03 → 스크롤 또는 바로가기 → S-04.
- 다른 상품을 비교할 때: S-03·S-04 → 전체 상품으로 돌아가기 → S-02.
- 옵션을 선택하지 않았을 때: S-07 입력 오류 → S-03의 누락 옵션 선택 → S-05.
- 빠르게 개요만 볼 때: S-02 → S-08 퀵뷰 → 닫기 → S-02.
- 관심 상품을 보관할 때: 상품의 찜 아이콘 → S-10 찜 목록 팝업 → S-02 복귀 또는 S-06 시착. 수정 전 스케치에 그려진 보조 경로다.
- 브랜드를 더 알고 싶을 때: S-01 → S-09 브랜드 이야기 → S-02.
- 시착 제출은 알림을 보여주는 데모이며 실제 접수·문자 발송·배송을 수행하지 않는다.

**손그림에서 확인한 전후 흐름:** 수정 전은 `목록 → 퀵뷰·찜·장바구니 팝업 → 시착 접수 팝업`을 중심으로 그렸다. 수정 후는 `브랜드 제품 소개 → 전체 상품 목록 → 독립 상세페이지 → 상세정보·리뷰·옵션 확인`을 추가했다. 브랜드 제품 소개의 직접 시착 버튼은 제거하고 제품을 자세히 확인한 뒤 시착하도록 유도한다는 빨간 주석이 있다. 다만 현재 HTML에는 브랜드 이야기 마지막의 직접 시착 CTA가 남아 있어 이 의도는 U-07에서 별도로 추적한다.

### 9.3 프로젝트의 사용성 기준

아래 기준은 다음 실사용 점검을 위한 제안이며 달성 실적이 아니다.

- **효과성:** 진행자 조작 도움 없이 선택 상품의 사용법·리뷰를 찾고 올바른 옵션으로 장바구니 확인까지 완료하는지 기록한다. 실패 원인은 화면·상태 번호와 연결한다.
- **효율성:** 목록에서 상세 진입까지 60초, 상세에서 사용법·리뷰 찾기 각각 60초 이내를 1차 관찰 기준으로 제안한다. 실제 측정 뒤 기준의 적절성을 검토한다.
- **이해·학습 용이성:** 처음 본 사용자가 상세 클릭·퀵뷰·시착의 차이를 설명하고, 오류 후 누락 옵션을 스스로 수정하는지 확인한다.
- **만족 또는 신뢰:** 예시 리뷰와 실제 후기를 구분하고, 0원 시착 안내가 데모임을 이해하는지 묻는다. 탐색 편의 평가는 5점 척도로 수집하되 현재 점수는 없다.
