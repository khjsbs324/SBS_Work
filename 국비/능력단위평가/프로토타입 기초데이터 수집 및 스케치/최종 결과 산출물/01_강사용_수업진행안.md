# 강사용 수업진행안

## 1. 평가 개요

| 항목 | 내용 |
|---|---|
| 능력단위 | 프로토타입 기초데이터 수집 및 스케치 |
| 능력단위 코드 | `0802010413_16v2` |
| 평가 방식 | 개인 포트폴리오 및 편집 원본 평가 |
| 평가 시간 | 300분 |
| 입력자료 | 서비스 브리프, 사용자·콘셉트·정보구조 자료 |
| 필수 제출 | 보고서 PDF, 편집 가능한 원본 또는 공유 링크 |
| 문항·총점 | 10문항, 100점 |

## 2. 평가 목표

학생이 프로젝트 목적에 맞는 기초데이터와 레퍼런스를 출처와 함께 수집·분석하고, 디자인 기획을 스토리보드와 다안 스케치로 전환할 수 있는지 평가한다. 저충실도 결과물에 적합한 사용성 점검을 설계·실행하고 문제를 수정한 과정, 다른 제작자가 이해할 수 있는 구현 설명과 종합 패키지도 함께 확인한다.

## 3. 평가 전 준비

- [ ] 학생별 서비스 브리프 또는 이전 단계 결과가 준비되었는지 확인한다.
- [ ] 브리프에는 사용자, 문제, 목적, 핵심 기능과 대상 매체가 포함되어야 한다.
- [ ] 인터넷 검색, 캡처, 스캔·촬영과 디자인 도구 사용 환경을 점검한다.
- [ ] 강사가 지정한 동료 점검자 1명 이상을 평가 시간 안에 연결할 수 있도록 좌석·순서를 준비한다.
- [ ] 외부 자료의 출처·확인일·제작자·이용 조건을 기록하도록 안내한다.
- [ ] 공유 링크를 제출하는 경우 강사 열람 권한을 미리 안내한다.

## 5. 진행 중 관찰 포인트

- 학생이 검색 결과를 무작정 저장하지 않고 수집 목적과 이용 조건을 기록하는가.
- 레퍼런스에서 표면 스타일이 아니라 정보구조·내비게이션·인터페이스·비주얼 원리를 추출하는가.
- 첫 아이디어에 고정되지 않고 구조·위계·조작 방식이 다른 대안을 만드는가.
- 스토리보드 화면 번호와 스케치·시안 번호가 대응하는가.
- 저충실도 상태에서도 과업 수행자가 어디를 눌러야 하고 다음에 무엇이 일어나는지 이해할 수 있는가.
- 의견을 그대로 받아 적지 않고 관찰 사실·문제·우선순위·수정으로 판단하는가.

## 6. 강사 개입 범위

허용:

- 제출 규칙, 시간, 파일명과 도구 조작의 일반적인 안내
- 브리프의 용어 또는 평가 범위 확인
- 공유 권한·파일 열림·스캔 식별성 같은 제출 기술 문제 안내

금지:

- 학생 대신 레퍼런스를 선택하거나 장단점 결론을 정해 주는 행위
- 특정 레이아웃·색상·스케치를 정답으로 지시하는 행위
- 사용성 문제와 수정안을 대신 도출하는 행위

## 7. 회수와 채점 순서

1. PDF, 편집 원본 또는 공유 링크가 열리는지 확인한다.
2. 보고서의 자료 출처표와 원본의 데이터·레퍼런스 보드를 대조한다.
3. 스토리보드 화면 번호와 썸네일·세부 시안 번호를 대조한다.
4. 사용성 점검 원자료에서 수행자·과업·관찰 사실을 확인한다.
5. 문제-수정 대응표와 수정 전후 스케치를 확인한다.
6. `Exam.md`의 PS-01~PS-10에 직접 증빙 위치와 점수를 기록한다.
7. 같은 결함이 여러 문항에 영향을 줄 때 주된 문항에서만 감점한다.

- 링크 권한이나 파일 손상으로 열리지 않으면 제출 누락과 접근 장애를 구분해 기록한다.
- 손 스케치가 흐리거나 잘려 식별되지 않으면 확인 가능한 부분만 판단하고 재제출 범위를 적는다.
- 점검자 정보는 실명 대신 역할·번호로 기록해도 된다. 수행자 존재와 과업 기록을 확인할 수 있어야 한다.
- 미확인 증빙을 추측하여 인정하거나 자동 0점 처리하지 않는다.
