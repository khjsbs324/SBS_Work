# 강사용 정답 및 채점표

## 1. 정답의 성격

이 과제에는 하나의 고정된 화면 정답이 없다. 정답은 다음 연결이 제출물의 직접 증빙으로 성립하는 상태다.

`브리프 → 데이터·레퍼런스 → 적용 판단 → 스토리보드 → 다안 스케치 → 세부 시안 → 사용성 문제 → 수정 전후`

미려함이나 유행보다 자료의 적합성, 비교 근거, 대안 탐색, 화면 흐름, 구현 설명과 수정 추적성을 평가한다.

## 2. 접수 확인

- [ ] 보고서 PDF가 열리고 글·표·이미지를 식별할 수 있다.
- [ ] 편집 원본 또는 공유 링크를 열 수 있다.
- [ ] 손 스케치의 화면·대안 번호가 식별된다.
- [ ] 보고서와 원본에서 같은 화면 번호를 사용한다.
- [ ] 외부 자료의 원출처와 이용 조건이 기록되어 있다.
- [ ] 사용성 점검 원자료와 수정 전후가 있다.

## 3. 직접 증빙 확인 순서

1. 브리프 요약에서 사용자·목표·콘셉트·핵심 과업·대상 매체를 확인한다.
2. 데이터 출처표와 실제 적용 화면을 대조한다.
3. 레퍼런스 비교표에서 같은 기준과 적용·변형·제외 판단을 확인한다.
4. 스토리보드의 화면·전환·상태·모션을 확인한다.
5. 썸네일 대안의 실질적 차이와 선정 과정을 확인한다.
6. 세부 시안과 구현 주석을 스토리보드에 대조한다.
7. 사용성 점검 원자료에서 관찰 사실과 문제 정의를 확인한다.
8. 문제-수정 대응표와 수정 전후 스케치를 확인한다.

## 5. 문항 간 구분

- PS-01은 자료의 적합성·출처·비교분석을 본다. 화면 품질은 여기서 중복 감점하지 않는다.
- PS-02는 기획이 스케치 구성으로 전환되었는지 본다.
- PS-03은 다른 제작자가 이해할 구현 설명을 본다.
- PS-04는 핵심 과업의 시간 순서와 인터렉션·피드백을 본다.
- PS-05는 점검 설계와 실행 절차를, PS-06은 관찰에서 문제를 정의한 판단을 본다.
- PS-07은 문제와 수정 전후의 연결을 본다.
- PS-08은 복수 대안의 탐색 폭과 선택 과정을 본다.
- PS-09는 전달 매체에 맞춘 시각·모션의 구체성을 본다.
- PS-10은 전체 산출물의 대응과 패키지 활용성을 본다.

## 6. 경계 사례

- 화면 캡처가 많아도 출처와 비교 기준이 없으면 높은 수준의 레퍼런스 분석으로 보지 않는다.
- 종이에 그린 스케치도 화면 목적·흐름·대안 차이와 주석이 식별되면 동일하게 인정한다.
- 동일 구조에 색만 바꾼 시안은 구조·위계·조작 방식이 다른 대안으로 보지 않는다.
- 클릭 연결이 없어도 스토리보드와 화살표·주석으로 핵심 과업을 재현할 수 있으면 저충실도 평가에 인정한다.
- 점검자 칭찬만 기록한 경우 과업 기반 관찰 원자료로 보지 않는다.
- 테스트 의견을 모두 수용하지 않아도 영향·우선순위·보류 이유가 타당하면 감점하지 않는다.
- 완성형 코드나 고충실도 프로토타입이 있어도 직접 증빙이 없는 문항의 점수를 자동으로 높이지 않는다.

## 7. 중복 감점 방지

- 원본 링크 하나가 열리지 않아 여러 문항을 확인할 수 없는 경우 각 문항에 같은 사유를 반복 기재하지 말고 접근 장애 범위를 별도로 기록한다.
- 출처 누락은 자료 신뢰성의 주된 문항에서 처리하고 동일 이미지가 다른 화면에 쓰였다는 이유만으로 반복 감점하지 않는다.
- 스토리보드의 단일 연결 누락이 세부 시안에도 반복된 경우 흐름 문항을 중심으로 판단한다.
- 보고서 미관 자체는 평가하지 않는다. 가독성 때문에 증빙을 확인할 수 없는 범위만 기록한다.

## 8. 최종 확인

- [ ] 10개 문항 모두 PDF·원본·스케치의 직접 증빙 위치가 있다.
- [ ] 각 문항에 하나의 점수와 판단 메모가 있다.
- [ ] 같은 원인을 반복 감점하지 않았다.
- [ ] 미확인과 미제출을 구분했다.
- [ ] 학생 공개 피드백에 내부 ID와 점수 계산을 노출하지 않았다.
