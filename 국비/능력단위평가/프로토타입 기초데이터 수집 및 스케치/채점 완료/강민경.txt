브랜드 소개 손 스케치의 섹션 번호와 카테고리 손 스케치의 상품 선택·이동 화살표를 보고서의 화면 설명과 연결한 점이 좋았습니다. 브랜드를 이해한 뒤 자신의 기록 목적에 맞는 도구를 고르게 하려는 흐름이 읽히며, 웜 브라운·크림 색상과 기록 장면을 사용한 시각 방향도 프로젝트 콘셉트와 잘 어울렸습니다. 보고서 7.2절과 9.2절에서 검색, 미리보기, 결과 없음, 목록 복귀를 시작 상태와 행동·결과로 나누어 설명한 점은 다음 제작자가 설계를 이어받는 데 도움이 되는 부분입니다.

다만 6.2절의 대안 표는 실제 그림과 함께 보완하면 선택 근거가 더 명확해질 것 같습니다. 보고서에서도 손 스케치는 페이지당 1안이고, A/B는 기존 HTML의 사후 비교, C는 아직 제작하지 않은 제안이라고 구분하고 있습니다. 비교표가 상세하더라도 화면의 구조·위계·조작 방식이 어떻게 달라지는지 그림으로 확인하기에는 조금 더 보완이 필요합니다. 예를 들어 같은 상품 목록을 대상으로 ‘상품 유형을 먼저 고르는 안’과 ‘기록 목적을 먼저 고르는 안’을 작게 그려 비교하면 두 방식의 차이를 이해하기 쉬울 것입니다. 두 안에서 첫 선택, 상품을 좁히는 순서, 선택 결과가 보이는 위치를 표시하고 어느 쪽이 기록 초보자의 선택을 돕는다고 판단했는지 이유를 덧붙이면 대안을 선택한 과정도 잘 드러날 것 같습니다.

그림과 상태 설명을 연결할 때에는 미리보기 닫기와 검색 결과 없음의 회복 경로를 함께 보여주면 흐름이 더 명확해질 것 같습니다. 현재 보고서에는 설명이 있지만 기본 손 스케치에서는 해당 상태가 생략되어 있습니다. 목록 옆에 미리보기와 결과 없음 상태를 작은 도식으로 붙이고, 닫은 뒤 어떤 목록으로 돌아가는지, ‘전체 상품 보기’를 선택하면 어떤 조건이 초기화되는지를 화살표와 주석으로 연결하면 다음 행동을 파악하기 쉬울 것입니다. 새로운 화면을 크게 다시 그리거나 실제 구매 기능을 만들 필요는 없습니다.

9.1~9.2절의 과업과 성공 조건은 준비되어 있으나 실제 수행자 점검은 미실시로 적혀 있습니다. 자체 자료 대조로 파일·문구의 불일치를 찾은 것과, 다른 사람이 설계를 이해하고 과업을 마친 것은 구분해 정리할 필요가 있습니다. 점검자에게 ‘속지 한 개를 찾아 정보를 확인한 뒤 목록으로 돌아오기’를 맡기고, 처음 고른 항목과 멈춘 위치, 실제 발언, 도움 여부를 남기면 실제 사용 과정에서 보완할 부분을 찾는 데 도움이 될 것입니다. 손 스케치를 이용한다면 선택에 따라 다음 상태를 보여주는 방식으로 진행해도 됩니다. 관찰한 문제를 고친 뒤 같은 과업을 다시 확인하면 변경 이유와 결과가 연결됩니다.

전달 자료에서는 초안 .lnk를 실제 열 수 있는 원본으로 바꾸고, 보고서 11.2절의 파일명·상대경로를 제출 폴더와 맞추면 전달 자료도 더 안정적으로 정리될 것 같습니다. 보고서 PDF 안에서도 두 손 스케치의 작은 주석이 읽히는지도 함께 확인하면 좋겠습니다. 기존 자료를 다시 배치하고 연결을 정리하는 것이 우선이며, 리뷰·FAQ·다운로드처럼 범위 밖이거나 자료가 없는 영역은 보류 이유를 표시하면 됩니다.
