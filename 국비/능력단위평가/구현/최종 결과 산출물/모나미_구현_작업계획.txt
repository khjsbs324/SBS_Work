1. 목표와 기준

학생이 수업에서 배운 코드와 정답 코드를 쉽게 대조할 수 있도록, 모나미 메인 페이지의 섹션별 학습본과 전체 통합본을 제작한다.
화면 기준은 https://www.monami.com/index.php 이며, 구현 코드 기준은 https://github.com/khjsbs324/UIUXB_2610 이다.
사이트에서는 화면 구성·문구·이미지·배치를 확인하고, 구현 문법과 코드 패턴은 지정 리포지터리에서 가져온다.
사용자의 최신 지시인 모나미 구현 및 학생용 정답 제공을 이번 과제의 기준으로 삼는다.

확인한 소스:

2. 사용자 정정에 따른 코드 활용 범위

현재 리포지터리에는 모나미 소스·로고·상품 이미지·영상이 없고, JavaScript 파일도 없다.
기존 예제는 header/main/nav, div 기반 묶음, 이미지, 제목·문단, 목록·버튼, Flex 배치, 고정 폭 컨테이너, 간격·글자·색상·테두리, 이미지 맞춤, 아이콘 hover 등을 사용한다.
사용자 정정: 리포지터리 코드를 수정하라는 뜻이 아니라, 그 코드를 참고해서 로컬 구현 폴더에 모나미 사이트를 작성하라는 요청이다.
따라서 원격 리포지터리를 참고 자료로 사용하고, 로컬 결과물의 문구·이미지·클래스·크기·색상과 구조 조합을 모나미 화면에 맞게 작성한다.
원문을 한 글자도 바꾸지 못한다는 해석과 추가 확인 대기를 철회한다.
기존 원격 리포지터리와 수업 원본은 보존한다.
결과 위치: 최종 결과 산출물/모나미_구현_정답.
수업 HTML·CSS 배치 방식을 참고하고 JavaScript·외부 라이브러리는 추가하지 않는다.

3. 화면 분해와 원본 코드 대응

MON-01 상단 영역
- 언어·유틸리티 메뉴, 로고, 주 내비게이션을 구분한다.
- utility-menu, utility-con, main-header, brand, nav/ul/li, Flex 정렬 패턴을 대응한다.
- 원사이트의 전체 메뉴·드롭다운 등은 현재 허용 소스에 동작 패턴이 있는지 따로 표시한다.

MON-02 메인 비주얼
- 대표 이미지와 브랜드 문구의 배치, 높이와 이미지 잘림을 확인한다.
- banner, banner img의 이미지 크기·object-fit 및 기존 글자 스타일 패턴을 대응한다.
- 원사이트의 겹침 배치나 효과가 허용 코드로 재현되지 않으면 차이를 먼저 명시한다.

MON-03 NEW ARRIVALS
- 제목·설명과 신제품 이미지들의 크기, 배치 순서, 상품명 관계를 정리한다.
- products, products-header, product-list, product-card, product-image, product-info 패턴을 대응한다.
- 기존 Flex의 가로·세로 묶음과 크기 설정으로 가능한 배치 범위를 확인한다.

MON-04 BEST PRODUCT
- 제목·설명·카테고리 표시·상품 카드·현재 선택 표현을 구분한다.
- brand-tabs/active, product-list, product-card, 이미지·문구 패턴을 대응한다.
- 카테고리 전환, 드래그 스크롤, 슬라이드 동작은 JavaScript 없이 구현된 것으로 표시하지 않는다.

MON-05 브랜드 영상 영역
- 영상 자리의 이미지와 진입 표현을 확인한다.
- 허용된 이미지 패턴으로 표현 가능한 대표 화면을 우선 검토한다.
- video/iframe 또는 재생·닫기 로직이 허용 소스에 없으면 새로 작성하지 않고 미구현 기능으로 기록한다.

MON-06 하단 정보 영역
- MONAMI NEWS, INQUIRY, 공식 스토어 안내의 세 영역을 구분한다.
- 가로 Flex, 제목·문단·목록·이미지·버튼 패턴을 대응한다.
- 보도자료 제목·날짜와 안내 문구는 기준일의 사이트 내용과 대응한다.

MON-07 푸터
- 로고, 회사 안내, 고객지원, 저작권과 관련 표시를 구분한다.
- 기존 div·목록·이미지·글자·Flex 패턴을 활용한다.
- 문법 목록에 없는 태그나 선택·팝업 동작을 편의상 추가하지 않는다.

링크 이동, 전체 메뉴, 팝업, 영상 재생, 드래그, 탭 전환, 반응형 규칙은 각각 허용 코드 존재 여부를 확인한다.
원사이트에 보이는 모든 기능을 자동으로 구현 범위에 넣지 않는다. 가능한 화면 표현과 없는 기능을 구분한다.

4. 제작 순서

1단계: 원본 확정 및 대응표
- 사용할 커밋과 원본 파일·구간을 고정한다.
- 태그·CSS 속성·선택자·기존 효과·자산 목록을 만든다.
- 각 모나미 영역에 사용할 원본 블록과 허용된 교체 항목을 연결한다.
- 대응되는 코드가 없는 표현과 기능을 먼저 목록으로 남긴다.

2단계: 기준 화면 및 자산 정리
- 동일한 데스크톱 화면 크기에서 상단부터 푸터까지 화면을 기록한다.
- 이미지 순서, 너비·높이, 여백, 색상, 제목 크기와 정렬을 확인한다.
- 모나미 이미지 사용이 허용되면 로고·대표 이미지·상품 이미지 등을 원본 비율로 수집하고 파일명·출처·사용 위치를 기록한다.
- 허용 여부가 확인되지 않은 모나미 자산을 컬리 이미지나 임의 생성 이미지로 대체해 완료 처리하지 않는다.

3단계: 공통 코드와 학습 순서
- 원본에서 확인된 초기화·컨테이너·Flex·글자·이미지 규칙을 선정한다.
- 공통 규칙과 섹션 전용 규칙의 적용 범위를 주석으로 나눈다.
- 상단 → 비주얼 → 신제품 → 인기상품 → 영상 영역 → 하단 정보 → 푸터 순서로 진행한다.
- 주석에서 사용할 섹션 ID는 학습본·통합본·대응표에 동일하게 적용한다.

4단계: 섹션별 학습본
- 섹션마다 개별 index.html과 style.css를 제공하여 그 부분만 실행·확인할 수 있게 한다.
- 필요한 공통 CSS도 함께 제공하여 다른 섹션이 없어도 동일한 부분 화면이 표시되게 한다.
- 원본 코드 위치, HTML 포함 관계, CSS 적용 대상과 배치 이유를 설명한다.
- 학생이 내용을 바꿀 위치와 변경하면 다른 부분에 영향이 있는 위치를 구분한다.
- 미구현 기능과 정적인 표시를 주석에 명시한다.

5단계: 전체 통합본
- 학습본의 섹션들을 같은 순서로 조합한다.
- 공통 초기화와 공통 규칙은 한 번만 두고, CSS 순서와 선택자 충돌을 확인한다.
- 통합 과정에서 새 기능이나 다른 코드 기법을 추가하지 않는다.
- 기본 실행본은 index.html + style.css로 원본의 분리 방식을 유지한다.
- 전체 코드를 한 파일에서 읽을 수 있는 전체코드.html도 제공한다. 같은 CSS를 style 안에 모은 열람·실행용 사본으로 만들고, 내용을 별도로 바꾸지 않는다.

6단계: 협업 주석과 설명 자료
- HTML/CSS 주석에 영역 시작·끝, 목적, 원본 파일·구간, 공통 의존성, 자산, 치수·간격, 수정 가능 위치를 적는다.
- 공동 작업 시 영향을 받는 선택자·컨테이너·이미지 비율과 통합 시 중복 제거 지점을 설명한다.
- 담당·요청·결정·상태 기록이 필요한 곳에는 기입 양식을 제공하고, 실제로 없는 협의나 담당자 응답을 만들어 쓰지 않는다.
- 설명 주석과 기존 코드를 비활성화하는 주석을 혼동하지 않도록 구분한다.

주석 예시의 항목:
[MON-03 시작 / NEW ARRIVALS]
역할 / 원본 파일·구간 / 포함 관계 / 적용 CSS / 사용 이미지
공통 규칙 의존성 / 변경 가능 값 / 다른 섹션 영향 / 확인 방법
[MON-03 끝]

7단계: 비교와 최종 검증
- 모든 학습본을 각각 실행하고 같은 섹션의 통합본과 비교한다.
- 전체코드.html과 분리된 통합본이 같은 화면을 보여주는지 확인한다.
- 이미지 경로·대소문자·누락 파일·CSS 연결·문법 오류·줄바꿈·넘침을 확인한다.
- 기준 사이트와 동일한 화면 크기에서 배치·여백·이미지 크기·타이포그래피를 비교한다.
- 허용 코드에 없는 태그·CSS 속성·스크립트·추가 라이브러리가 섞이지 않았는지 원본 목록과 대조한다.
- 원본에서 가져온 부분, 콘텐츠·수치 교체, 반복·조합, 주석 추가를 변경 대응표에 남긴다.
- 동작을 실제 확인한 항목만 완료로 기록한다. 재현하지 못한 화면·기능과 외부 의존성은 별도로 남긴다.

6. 평가 문서와의 관계

기존 구현 Exam과 안내서는 개인 브랜딩 포트폴리오, JavaScript·모바일·상호작용 등을 포함하는 조건으로 작성되어 있다.
이번 모나미 과제는 최신 사용자 지시에 따라 별도 구현 범위와 수업 코드 활용 범위를 먼저 확정한다.
정답 코드가 완성되면 기존 문서에서 모나미 과제와 다른 부분을 목록으로 정리한다.
평가 안내·정답·제출물 조건을 정비할 때는 실제 정답 코드가 지원하지 않는 기능을 학생 필수 조건으로 남기지 않는다.
수행준거 원문·순서와 현재 9문항·100점은 과제 주제 변경만으로 임의 변경하지 않는다.
학생용 정답은 이번 사용자가 명시적으로 요청한 복습 자료로 제공한다.
이 계획 단계에서는 기존 시험 문서, 학생 점수, 사이트 평가 등록을 변경하지 않는다.

7. 완료 기준

- 섹션별 학습본과 전체 통합본을 학생이 각각 열어 비교할 수 있다.
- 모든 실행 코드의 근거를 지정 리포지터리에서 추적할 수 있다.
- 허용된 콘텐츠·수치 교체와 추가 주석을 확인할 수 있다.
- 각 섹션의 HTML·CSS 관계와 협업 시 유의점이 설명되어 있다.
- 구현된 화면과 실제 동작, 미구현 기능이 구분되어 있다.
- 통합본과 섹션별 학습본 사이에 의도하지 않은 차이가 없다.
- 사용자 정정에 따라 로컬 결과물에 구현하며 원격 리포지터리는 변경하지 않는다.
