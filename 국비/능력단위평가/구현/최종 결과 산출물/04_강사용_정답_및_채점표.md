# 구현 강사용 정답 및 채점표

## 정답 성격

이 과제에는 하나의 화면 형태나 특정 기술 스택만 정답으로 존재하지 않는다. 학생의 프로젝트 목적·콘텐츠·사용자와 기존 설계가 다르므로 다음 추적 관계가 성립하면 적합한 정답으로 판단한다.

`설계 자료 → 콘텐츠 구조·화면 흐름 → 기능 제안 → 코드·브라우저 구현 → 디자인 전달·협업 결정 → 수정·재검증 → 최적화 결과`

## 등록용 정답 문구

정답: 정보구조와 시각적 흐름, 멀티미디어 기능 제안, 매체 특성을 반영한 콘텐츠와 디지털 미디어 기능 요소, HTML·CSS·JavaScript 개발사항, 개발 전달 문서·협업 이슈·수정 및 최적화 결과가 포함된 실행 가능한 소스 ZIP 1개와 구현보고서 PDF 1개

## 필수 확인표

- [ ] ZIP 1개와 PDF 1개가 정상적으로 열린다.
- [ ] ZIP을 새 폴더에 풀어 외부 절대경로 없이 실행된다.
- [ ] 사이트맵·화면 ID·콘텐츠 우선순위가 실제 구현과 대응한다.
- [ ] 핵심 과업 흐름과 내비게이션을 완료할 수 있다.
- [ ] 기능 ID별 목적·상태·기술·오류 대안이 기록됐다.
- [ ] 데스크톱·모바일에서 핵심 콘텐츠와 기능이 안정적이다.
- [ ] 디자인 전달 문서의 수치·상태·자산 위치가 구체적이다.
- [ ] 실제 의견 또는 제공 이슈의 유형과 결정이 구분됐다.
- [ ] 수정 전후, 재검증과 남은 제약이 기록됐다.

## 판단 유의 사항

- 보고서에 정상이라고 적었다는 이유만으로 기능을 인정하지 않고 직접 실행한다.
- 특정 프레임워크·라이브러리를 사용하지 않았다는 이유로 감점하지 않는다.
- 기능 수가 많아도 콘텐츠 목적과 연결되지 않거나 불안정하면 상위 구간으로 평가하지 않는다.
- 외부 배포는 선택 사항이며 로컬 실행이 정상이라면 배포 부재를 감점하지 않는다.
- 제공 이슈를 사용한 학생에게 실제 협업자가 없다는 이유로 감점하지 않는다.
- 학생이 실제 의견 또는 제공 이슈를 분석하고 자신의 결정과 구현 결과를 남겼는지 판단한다.
- 동일한 경로 오류가 여러 화면에 나타나도 하나의 원인으로 처리하고 중복 감점하지 않는다.

상세 점수 구간은 `../Exam.md`의 IM-01~IM-09를 사용한다.
