# 구현 강사용 수업진행안

## 평가 목적

학생이 기존 기획·와이어프레임·스타일가이드를 실행 가능한 웹 콘텐츠로 전환하고, 기능 제안과 개발 전달, 검토 이슈의 협의·수정·재검증을 통해 결과물을 최적화하는 과정을 평가한다.

## 평가 조건

- 개인평가 / 240분 / 포트폴리오
- 입력 자료: 개인 브랜딩 기획·와이어프레임·스타일가이드 또는 강사 제공 브리프
- 제출: `이름_구현.zip`, `이름_구현보고서.pdf`
- 실행: 외부 배포 없이 로컬 브라우저 실행으로 평가 가능

## 사전 준비

1. 입력 자료와 시작용 프로젝트가 정상적으로 열리는지 확인한다.
2. 강사 제공 이슈 시나리오를 사용할 경우 학생별로 동일한 난이도의 이슈를 준비한다.
3. 최소 확인 환경을 안내한다: 데스크톱 1440px 내외, 모바일 390px 내외, 키보드 탐색.
4. 실제 외부 계정·서버·유료 API가 필요한 기능은 평가 범위에서 제외한다.

## 240분 진행

1. 0~20분 — 입력 자료 확인과 범위 확정
   - 프로젝트 목적·사용자·디자인 방향을 확인한다.
   - 핵심 화면·콘텐츠·과업 흐름과 제외 범위를 정한다.
2. 20~50분 — 구조와 기능 명세
   - 사이트맵, 화면 ID, 콘텐츠 우선순위와 핵심 흐름을 작성한다.
   - 기능 ID, 상태, 기술 선택, 제약과 오류 대안을 정한다.
3. 50~165분 — 콘텐츠·기능 구현
   - HTML·CSS·JavaScript와 자산을 연결한다.
   - 데스크톱·모바일 화면, 링크와 상호작용을 구현한다.
4. 165~195분 — 개발 전달과 이슈 검토
   - 디자인 전달 문서를 작성하고 파일·화면·기능 ID를 연결한다.
   - 실제 검토 의견 또는 강사 제공 이슈를 분석해 반영·보류·제외를 결정한다.
5. 195~225분 — 최적화와 재검증
   - 핵심 과업, 오류 상태, 키보드, 대체 텍스트, 로딩·자산 크기를 확인한다.
   - 수정 전후와 판정 결과, 남은 제약을 기록한다.
6. 225~240분 — 제출 점검
   - ZIP을 임시 폴더에 풀어 시작 파일부터 다시 실행한다.
   - PDF와 ZIP의 근거 ID, 파일명과 제출 개수를 확인한다.

## 강사 제공 이슈 예시

다음 예시는 학생의 프로젝트에 맞게 같은 난이도로 조정한다.

- 모바일 390px에서 프로젝트 목록의 제목과 버튼이 겹치므로 우선순위와 줄바꿈 규칙을 협의한다.
- 큰 이미지로 첫 화면 로딩이 지연되므로 화질·크기·대체 콘텐츠 기준을 정한다.
- 모달이 키보드로 닫히지 않으므로 포커스 이동과 종료 동작을 합의한다.
- 디자인 시안에 없는 오류·빈 상태가 필요하므로 문구·아이콘·다음 행동을 전달한다.

강사 제공 문구는 `제공 이슈`로 표시한다. 학생이 임의로 제3자의 응답을 만들어 실제 협업 기록처럼 제출하지 않도록 안내한다.

## 회수 및 검증 순서

1. ZIP을 별도 폴더에 풀고 시작 파일을 실행한다.
2. 외부 절대경로 없이 CSS·JavaScript·이미지가 연결되는지 확인한다.
3. 사이트맵·화면 ID와 실제 화면을 대조한다.
4. 핵심 과업을 데스크톱과 모바일에서 실행한다.
5. 기능 ID별 정상·오류·빈 상태와 키보드 동작을 확인한다.
6. 전달 문서의 수치·자산·상태가 코드와 화면에 대응하는지 확인한다.
7. 협업 이슈의 결정과 수정 전후, 재검증 결과를 대조한다.
8. `Exam.md` IM-01~IM-09에 직접 증빙을 연결해 채점한다.
