# 구현 포트폴리오 평가

## 과제 목표

기존에 만든 개인 브랜딩 기획, 와이어프레임과 스타일가이드를 바탕으로 포트폴리오 사이트의 핵심 콘텐츠와 기능을 실제 브라우저에서 작동하도록 구현합니다. 구현 결과뿐 아니라 무엇을 어떤 기준으로 만들었는지, 개발에 필요한 정보를 어떻게 전달하고 검토 의견을 어떻게 반영했는지도 함께 기록합니다.

## 평가 시간과 제출물

- 개인평가: 240분
- `이름_구현.zip` 1개
- `이름_구현보고서.pdf` 1개

외부 배포 URL은 선택 사항입니다. 제출 ZIP을 로컬에서 실행할 수 있어야 합니다.

## 구현 범위

프로젝트 목적에 맞는 핵심 흐름을 정합니다. 일반적인 개인 포트폴리오라면 홈, 프로젝트 목록, 프로젝트 상세와 연락·소개 중 필요한 영역을 포함할 수 있습니다. 화면 수보다 전체 콘텐츠의 연결과 핵심 과업의 완결성이 중요합니다.

다음 항목을 모두 수행합니다.

1. 프로젝트 목적·사용자·디자인 방향을 정리합니다.
2. 사이트맵, 콘텐츠 목록·우선순위, 화면 ID와 핵심 과업 흐름을 만듭니다.
3. 필요한 미디어·상호작용 기능에 ID를 부여하고 상태·기술·제약·오류 대안을 정합니다.
4. HTML·CSS·JavaScript와 이미지 등 자산을 이용해 실제 화면을 구현합니다.
5. 데스크톱과 모바일에서 콘텐츠, 링크와 기능을 점검합니다.
6. 개발에 필요한 디자인 정보와 파일 위치를 전달 문서에 정리합니다.
7. 실제 검토 의견 또는 강사 제공 이슈를 확인하고 반영·보류·제외를 결정합니다.
8. 수정 전후와 재검증 결과, 아직 남은 제약을 기록합니다.

## ZIP 기본 구조

프로젝트에 맞게 하위 구조를 바꿀 수 있으나 시작 파일과 자산 위치가 명확해야 합니다.

```text
이름_구현/
├─ index.html
├─ css/
├─ js/
├─ assets/
├─ docs/
│  ├─ 디자인_전달문서.md
│  └─ 이슈_및_결정기록.md
└─ README.md
```

`README.md`에는 실행 방법, 시작 파일, 구현 범위, 대상 브라우저, 알려진 제약을 적습니다.

## 보고서 작성

`03_학생_제출_산출물.md` 양식을 사용해 PDF로 제출합니다. PDF 안의 화면·기능·이슈 ID는 ZIP의 파일과 동일하게 사용합니다.

## 평가에서 중요하게 보는 내용

- 설계 자료와 실제 콘텐츠 구조의 일치
- 핵심 과업의 시각적 흐름과 내비게이션
- 프로젝트에 필요한 기능을 선택한 이유와 구현 상태
- 데스크톱·모바일 등 대상 매체에서의 안정성
- HTML·CSS·JavaScript와 자산의 로컬 실행 가능성
- 개발자가 해석하지 않아도 되는 구체적인 디자인 전달 정보
- 협업 이슈의 반영·보류·제외 이유와 최종 재검증

특정 프레임워크 사용, 외부 배포, 서버와 데이터베이스 구현은 필수가 아닙니다. 불필요한 효과를 많이 넣는 것보다 필요한 기능을 정확하고 안정적으로 구현하는 것이 중요합니다.
