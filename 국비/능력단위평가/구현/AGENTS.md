# 구현 평가 지침

## 평가 목적

이 폴더의 능력단위는 `구현(0802010418_16v3)`이다. 학생이 앞선 기획·리서치·와이어프레임·스타일가이드를 바탕으로 개인 브랜딩 포트폴리오 사이트의 콘텐츠와 기능을 실제 브라우저에서 작동하도록 구현하고, 개발 협업에 필요한 정보를 전달·조율하여 결과물을 최적화하는 능력을 평가한다.

## 원문 범위

- 원본은 `구현(0802010418_16v3)`과 `구현 응용(0802010419_16v3)`이 결합된 PDF다.
- 이 평가에서는 `0802010418_16v3`에 해당하는 수행준거 9개만 사용한다.
- `0802010419_16v3`의 활용·응용 수행준거는 이 평가에서 제외한다.
- 원문 순서대로 `IM-01`~`IM-09`에 연결한다. IM 번호는 내부 추적 ID이며 공식 NCS 수행준거 번호가 아니다.

## 평가 조건

- 개인평가, 240분, 포트폴리오 방식으로 진행한다.
- 학생의 기존 개인 브랜딩 기획, 와이어프레임과 스타일가이드 또는 강사가 제공한 대체 브리프를 입력 자료로 사용한다.
- 필수 제출은 `이름_구현.zip` 1개와 `이름_구현보고서.pdf` 1개다.
- ZIP에는 로컬에서 실행 가능한 HTML·CSS·JavaScript, 사용 자산과 협업 전달 문서를 포함한다.
- PDF에는 콘텐츠 구조·시각적 흐름·기능 명세, 구현 전후, 브라우저 점검, 협업 의견과 최적화 결과가 판독 가능해야 한다.
- 외부 배포 URL은 선택 사항이며 서버·데이터베이스·유료 서비스 연결을 필수로 요구하지 않는다.
- 실제 개발 협업자를 확보하기 어려운 경우 강사가 제공한 검토 의견 또는 이슈 시나리오를 사용할 수 있다. 실제 의견과 제공 시나리오를 구분하고 응답을 임의로 창작하지 않는다.

## 판단 원칙

- 화려한 효과보다 `설계 자료 → 콘텐츠 구조 → 화면 흐름 → 기능 구현 → 점검·협의 → 최적화`의 추적성을 우선한다.
- 정적인 시안 제출만으로 구현을 인정하지 않고, 제출 코드와 브라우저 동작을 함께 확인한다.
- 프레임워크 사용 여부보다 선택한 매체와 프로젝트 범위에 맞는 실행 가능성, 구조와 기능을 본다.
- 멀티미디어 기능은 이미지·영상·애니메이션·상호작용 중 프로젝트에 필요한 항목을 선택할 수 있다. 불필요한 효과를 많이 넣었다는 이유로 높은 점수를 주지 않는다.
- 협업은 실제 대화의 양보다 전달 정보의 명확성, 이슈와 결정의 추적성, 최종 반영 여부로 판단한다.
- 배포하지 않았다는 이유만으로 감점하지 않으며 로컬 실행과 브라우저 점검으로 확인할 수 있다.
- 같은 원인의 문제를 여러 문항에서 중복 감점하지 않는다.

- `Exam.md`의 `IM-01`~`IM-09`를 사용하며 총점은 100점이다.
- 모든 점수는 보고서 페이지·절·근거 ID, 제출 코드, 브라우저 화면, 이슈 기록 또는 파일 속성 중 하나 이상의 직접 증빙에 연결한다.
- 원문 수행준거 9개, 수행준거 TXT 9개, Exam 9문항의 문장·순서·개수를 대조한다.

- 학생용 자료에 강사용 최고점 판단 예시나 모범 정답을 노출하지 않는다.
