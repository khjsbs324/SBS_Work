### 1. 가상 클라이언트의 기본 정보 설정

  먼저 다음 내용을 정한다.

  - 프로젝트의 중심 주제
  - 제작 목적
  - 클라이언트가 제공한 자료
  - 필요한 정보와 기능
  - 중요도와 작업 우선순위
  - 적용 매체: 웹, 모바일, 스마트워치 등

  PDF에서 발주자가 제공하는 자료는 사전 자료, 참고 자료, 데이터셋 등으로 제시된다.

  ### 2. 클라이언트가 원하는 항목 수집

  클라이언트의 요구를 가능한 한 구체적인 항목으로 나눈다.

   번호    클라이언트 요청 내용    관련 자료    중요도
  ━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━  ━━━━━━━━━━━━━━━━
   1                                            높음·보통·낮음
  ──────  ──────────────────────  ───────────  ────────────────
   2                                            높음·보통·낮음
  ──────  ──────────────────────  ───────────  ────────────────
   3                                            높음·보통·낮음

  이 단계에서는 누락과 중복을 확인하고, 출처가 있는 정보는 신뢰성도 검토한다.

  ### 3. 요구사항을 정보 단위로 변환

  각 요청을 PDF에서 제시한 정보 유형과 구조에 맞춰 분해한다.

  - 정보 유형: 사실, 개념, 절차, 과정
  - 정보 단계: 주제 → 부주제 → 메뉴 → 콘텐츠
  - 화면 요소: 메뉴, 버튼, 이미지, 텍스트, 검색창 등
  - 이동 요소: 연결 페이지, 화면 전환, 링크

  작성 양식은 다음과 같이 구성할 수 있다.

   요청 원문            정보 유형              주제    부주제    메뉴    콘텐츠·기능
  ━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━  ━━━━━━  ━━━━━━━━  ━━━━━━  ━━━━━━━━━━━━━
   클라이언트의 요청    사실·개념·절차·과정

  ### 4. 비슷한 항목끼리 분류

  메모지나 협업 도구를 활용해 비슷한 요청끼리 그룹화한다.

  - 같은 목적의 정보는 하나로 묶는다.
  - 중복 항목은 통합한다.
  - 불필요한 항목은 제외한다.
  - 중요도에 따라 노출 순서를 결정한다.
  - 자료 유형에 따라 이미지, 영상, 텍스트, 데이터셋으로 구분한다.

  ### 5. 계층 구조 작성

  분류한 항목을 상위 메뉴에서 하위 콘텐츠로 연결한다.

  프로젝트 주제
  ├─ 상위 메뉴 1
  │  ├─ 하위 메뉴
  │  │  └─ 콘텐츠·기능
  ├─ 상위 메뉴 2
  │  └─ 콘텐츠·기능
  └─ 상위 메뉴 3
     └─ 콘텐츠·기능

  PDF의 권장 기준은 다음과 같다.

  - 한 단계의 메뉴 폭: 5~9개
  - 메뉴 깊이: 최대 5단계 이내

  너무 깊으면 접근성이 낮아지고, 너무 넓으면 한 화면이 복잡해진다.

  ### 6. 사용자가 이해하기 쉬운 이름 부여

  분류된 그룹과 메뉴에 레이블을 붙인다.

  레이블은 다음 기준으로 점검한다.

  - 이름만 보고 내용을 알 수 있는가?
  - 같은 단계의 명칭이 일관적인가?
  - 사용자가 현재 위치를 이해할 수 있는가?
  - 비슷한 항목이 서로 다른 이름으로 중복되지 않았는가?

  ### 7. 내비게이션으로 연결

  사용자가 각 항목을 찾는 경로를 설계한다.

  - 글로벌 내비게이션
  - 로컬 내비게이션
  - 브레드크럼
  - 검색창
  - 풀다운 메뉴
  - 사이트맵
  - 페이지 사이의 링크와 화면 전환

  각 메뉴는 단순히 존재하는 것이 아니라 사용자가 목표 정보에 도달할 수 있도록 연결되어야 한다.

  ### 8. 와이어프레임으로 표현

  정리한 항목을 화면 영역에 배치한다.

   화면 영역     작성할 항목
  ━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   헤더          로고, 주요 메뉴, 로그인, 검색 등
  ────────────  ──────────────────────────────────
   내비게이션    상위·하위 메뉴와 현재 위치
  ────────────  ──────────────────────────────────
   바디          핵심 텍스트, 이미지, 영상, 기능
  ────────────  ──────────────────────────────────
   어사이드      바로가기, 배너 등 보조 기능
  ────────────  ──────────────────────────────────
   푸터          기업 정보, 정책, 저작권, SNS 등

  이 단계에서는 색상이나 장식보다 다음을 우선한다.

  - 정보의 우선순위
  - 기능 요소의 위치
  - 사용자 행동 경로
  - 페이지 간 연결
  - 화면 전환 방식

  ### 9. 반복 검토

  마지막으로 클라이언트 요청과 설계 결과를 대조한다.

  - 요청한 항목이 모두 반영되었는가?
  - 중복되거나 빠진 정보가 있는가?
  - 사용자가 원하는 항목을 쉽게 찾을 수 있는가?
  - 메뉴 깊이가 지나치게 깊지 않은가?
  - 항목명이 일관적인가?
  - 구조 변경이 전체 내비게이션에 문제를 만들지 않는가?
  - 웹과 모바일에서도 정보 접근이 일관적인가?
