## 오류별 상세 기록

### ERR-01

- 발견 과정: 최신 HOME 스토리보드와 초안 HTML의 m01~m04를 순서대로 대조하고, 실제 사용자가 m01에서 m04까지 스크롤하는 시나리오에서 브랜드 목적→관점→4단계→투트랙 선택 의미를 연결할 수 있는지 확인한다. 한 Section만 읽어도 해당 Section의 목적과 앞뒤 연결 대상이 설명되는지 별도로 확인한다.
- 영향을 받는 사용자·화면·파일: 기록을 처음 시작하거나 중단된 기록을 다시 이어가려는 사용자, HOME m01~m04, `메인페이지_웹디자인_수정본.html`.
- 반복 발생 여부: Section을 개별적으로 읽을 때마다 발생 가능한 구조적 문제이며 Desktop·Tablet·Mobile 공통으로 확인한다. m04를 먼저 진입하는 Anchor 시나리오에서도 역할 차이를 확인한다.

- 수정 완료 조건: `ERR-01~20` 각각에 같은 번호의 `FIX-01~20`, 수정 위치, 검증 방법, 실제 결과와 증빙이 존재한다. 한 수정이 여러 ID와 관련되면 주 ID와 연관 ID를 명시하되 완료 조건은 개별 판정한다.
- 추적 항목 기준: 오류 ID, 원인, 수정 대상, 보존 조건, 담당, 우선순위, 선행 조건, 검증 폭·상태, 결과, 증빙 경로를 연결한다.
- 실패 판정: 대응 FIX·구현 위치·검증 결과 중 하나라도 없거나 정적 검사만으로 시각 검증까지 통과했다고 기록하면 미완료다.

### ERR-20

- 발견 과정: Header부터 Footer까지 모든 링크의 표시 문구·위치·`href`·도착 Section을 목록화하고 동일 목적지·유사 문구·Section별 행동 수를 대조한다.
- 영향을 받는 사용자·화면·파일: 기록 방식과 상품 정보를 탐색하며 다음 행동을 선택하는 HOME 사용자.
- 반복 발생 여부: m02~m06 각 Section 끝과 Header·Footer 이동에서 반복된다.
- 임시 대응 필요 여부: 핵심 Anchor를 삭제하지 않고 목적·중복·우선순위를 먼저 분류한다.
- 수정 완료 조건: Section마다 Primary 행동이 명확하고 Secondary 행동은 시각적으로 보조된다. 동일 목적지는 동일한 명칭을 사용하고 링크 문구가 도착 내용을 정확히 설명한다.
- 유지 기준: 반복 링크라도 긴 페이지에서 복귀·다음 단계에 실질적으로 필요하면 유지할 수 있다. 이 경우 Header·본문·Footer 중 각 위치의 역할이 달라야 한다.
- 정리 기준: m03 경험 인덱스는 빠른 탐색, m04 링크는 방식 비교 후 대표상품 연결, m05 링크는 상품 확장, m06은 최종 다음 행동으로 역할을 제한한다.
- 실패 판정: 한 Section에 동등한 Primary CTA가 여러 개이거나 동일 목적지 링크명이 다르거나 링크 문구와 도착 내용이 맞지 않아 다음 행동을 예측할 수 없으면 미완료다.
