# 디지털디자인 사후관리 평가 지침

## 평가 목적

완료된 디지털디자인 프로젝트를 지속적으로 관리하는 능력을 평가한다. 학생은 오류 모니터링, 원인 분석과 수정, 클라이언트 요청 조율, 피드백 반영, 재검증, 내부 리뷰, 소스 데이터 백업과 버전 관리를 수행한다.

## 평가 대상

- 학생이 직접 완료한 디지털디자인 프로젝트 한 건
- 원본, 수정 전 결과물, 수정 후 결과물과 편집 가능한 소스
- 웹 프로젝트인 경우 코드와 브라우저 화면을 추가 증빙으로 사용할 수 있으나 코드는 필수 조건이 아니다.

## 판단 원칙

- 디자인 취향이나 결과물의 화려함보다 사후관리 절차와 판단 근거를 우선한다.
- 오류, 요구사항, 수정 내용과 재검증 결과가 서로 추적되어야 한다.
- 클라이언트 요청을 무조건 수용했는지가 아니라 범위·일정·비용·영향을 검토했는지 평가한다.
- 수정하지 않은 요청도 보류 또는 제외 근거가 타당하면 인정한다.
- 학생이 작성하지 않은 클라이언트 의도나 사용자 반응을 추측하지 않는다.
- 데이터베이스 관리를 백엔드 구축으로 확대하지 않고 소스·산출물·버전·백업 관리로 판단한다.
- 학생용 자료에 강사용 판단 예시나 최고점 답안을 노출하지 않는다.

## 평가 범위 예외와 가상 클라이언트

- 홈·상품·브랜드 이동처럼 시험에서 제작·제출을 요구하지 않은 화면을 참조하는 상대 링크는 평가 범위에서 제외한다.
- 위 상대 링크의 대상 파일이 제출 ZIP에 없거나 독립 실행 환경에서 이동이 완결되지 않아도 결함 또는 감점 근거로 사용하지 않으며, 학생 공개용 피드백에도 언급하지 않는다.
- 시험 대상 화면 내부의 필수 앵커, 평가 대상 기능 또는 필수 제출물의 누락은 위 예외에 포함하지 않는다.
- 클라이언트 관련 수행은 가상 클라이언트 시나리오로 진행할 수 있으며, 실제 제3자와의 질문·답변·메신저·이메일·승인 증빙을 필수로 요구하지 않는다.
- 가상 클라이언트라는 사실이나 실제 커뮤니케이션 증빙이 없다는 이유만으로 감점하거나 개선점으로 제시하지 않는다.
- 가상 시나리오 안에서 학생이 작성한 요구사항, 확인 질문·답변, 작업 범위·일정·비용·영향, 승인·보류·제외 판단과 피드백 반영 기록의 구체성 및 추적성을 평가한다.

## 제출 검증

- 학생 제출 서식 10종
- 수정 전·후 결과물
- 편집 가능한 최종 소스
- 산출물 인덱스
- 버전별 백업과 복구 확인 기록
- 내부 공유용 프로젝트 사후리뷰

## 채점

- Exam.md의 DM-01~DM-16을 사용한다.
- 수행준거 1개당 문항 1개로 평가하고 총점은 100점이다.
- 모든 점수에 학생 문서, 수정 전후 이미지, 디자인 소스, 파일 속성, 버전 기록 또는 복구 결과 중 하나 이상의 직접 증빙을 연결한다.
- 동일 결함을 여러 문항에서 설명 없이 중복 감점하지 않는다.
