# 강사용 수업진행안

## 1. 평가 개요

| 항목 | 내용 |
|---|---|
| 능력단위 | 디지털디자인 사후관리 |
| 능력단위 코드 | 0802010408_13v1 |
| 평가 방식 | 포트폴리오 및 작업 결과물 평가 |
| 작업 형태 | 개인평가 |
| 권장 시간 | 5시간 |
| 평가 대상 | 학생이 완료한 디지털디자인 프로젝트 한 건 |
| 필수 제출 | 서식 10종, 수정 전후 결과물, 편집 가능한 최종 소스, 백업과 복구 증빙 |
| 총점 | 16문항 100점 |

## 2. 평가 목적

완료된 프로젝트를 단순히 다시 디자인하는 것이 아니라, 오류와 개선 필요 사항을 모니터링하고 원인을 분석하여 수정한 뒤 클라이언트와 사용자의 피드백을 반영하고 재검증하는 전 과정을 평가한다. 프로젝트 종료 후의 리뷰, 산출물 정리, 백업, 버전 관리와 복구 가능 여부도 함께 평가한다.

## 3. 평가 대상 프로젝트 선정 기준

- 학생이 직접 참여하여 완료한 디지털디자인 프로젝트여야 한다.
- 원본과 편집 가능한 소스가 있어야 한다.
- 수정 전과 수정 후를 비교할 수 있어야 한다.
- 클라이언트 또는 의뢰인 역할과 사용자 대상을 설명할 수 있어야 한다.
- 웹, 앱, 이미지, 영상, 디지털 브랜딩 등 프로젝트 유형은 제한하지 않는다.
- 웹이 아닌 프로젝트에 코드 또는 브라우저 증빙을 요구하지 않는다.

프로젝트가 위 조건을 충족하지 않으면 평가 시작 전에 다른 프로젝트로 변경하게 한다.

## 4. 평가 전 준비

- [ ] 학생별 대상 프로젝트와 원본 버전을 확정한다.
- [ ] 원본이 수정되지 않도록 별도 사본 또는 백업을 확보한다.
- [ ] 클라이언트 역할과 요청 전달 방식을 정한다.
- [ ] 사용자 피드백 수집 방법 또는 제공 자료를 정한다.
- [ ] 학생에게 02번, 03번 문서와 서식 10종만 배포한다.
- [ ] 강사용 채점표와 Exam.md가 학생에게 공개되지 않았는지 확인한다.

## 5. 평가 진행

### 1단계. 프로젝트 확정과 원본 보존 — 20분

학생 이름, 프로젝트명, 결과물 유형, 원본 버전과 편집 가능한 소스 존재 여부를 확인한다. 학생은 수정 전 원본을 별도 위치에 보존한다.

### 2단계. 모니터링과 오류 식별 — 50분

학생은 프로젝트 특성에 맞는 점검 영역을 선정하고 01번 체크리스트를 작성한다. 오류와 개선 사항은 위치, 발생 조건, 실제 상태와 증빙을 포함해 02번 요구서에 기록한다.

강사는 단순 감상평이 아니라 확인 가능한 오류·불편·관리 문제인지 관찰한다.

### 3단계. 원인 분석과 수정 계획 — 40분

학생은 오류의 표면 증상과 직접·근본 원인을 구분하고, 다른 산출물에 미치는 영향을 검토하여 03번 계획서를 작성한다.

### 4단계. 클라이언트 요구 파악과 범위 조율 — 50분

강사 또는 지정된 역할자가 클라이언트 요청을 전달한다. 학생은 요청 목적과 완료 조건을 확인하고 계약 범위, 유상·무상, 일정, 난이도와 영향에 따라 반영·보류·제외를 결정한다.

모든 요청을 수용하도록 유도하지 않는다. 조율 근거의 타당성을 본다.

### 5단계. 수정·최적화와 피드백 반영 — 90분

학생은 승인된 오류와 요청을 결과물에 반영한다. 사용자와 클라이언트 피드백을 유형·빈도·영향으로 분석하고 필요한 사항을 추가 수정한다.

강사는 작업 과정에서 원본 보존, 파일 버전과 수정 위치가 관리되는지 관찰한다.

### 6단계. 재검증 — 40분

학생은 수정 항목뿐 아니라 연관 영역을 다시 점검하고 통과·실패·추가조치를 04번 보고서에 기록한다. 수정 전후 증빙을 같은 조건으로 비교하도록 안내한다.

### 7단계. 내부 리뷰 — 40분

학생은 기획부터 사후관리까지 성공점과 아쉬운 점을 분석하고 인사이트, 재발 방지책과 공유할 노하우를 08번 서식에 작성한다.

### 8단계. 인덱싱·백업·복구 — 30분

학생은 편집 가능한 소스와 출력물을 정리하고 09번 산출물 인덱스와 10번 버전관리표를 완성한다. 지정 버전의 실제 복구 여부를 확인한다.

## 6. 과정 관찰 항목

- 모니터링 항목을 프로젝트 특성에 맞게 선정하는가
- 오류 현상과 원인을 구분하는가
- 클라이언트 요청을 질문으로 구체화하는가
- 요청 범위를 근거로 조율하는가
- 원본을 보존하면서 수정하는가
- 피드백의 빈도와 영향에 따라 우선순위를 정하는가
- 수정 후 연관 영역까지 재검증하는가
- 파일명, 폴더, 버전과 백업 위치가 일관되는가
- 복구 결과를 실제로 확인하는가

## 7. 회수 순서

1. 제출 폴더명과 학생 정보를 확인한다.
2. 서식 10종이 모두 존재하는지 확인한다.
3. 수정 전과 수정 후 결과물을 같은 조건에서 비교한다.
4. 오류·요청·피드백 ID가 수정 및 재검증 문서까지 이어지는지 확인한다.
5. 편집 가능한 최종 소스와 연결 파일이 열리는지 확인한다.
6. 산출물 인덱스와 실제 파일을 대조한다.
7. 백업에서 지정 버전이 복구되는지 확인한다.
8. Exam.md의 DM-01~DM-16에 직접 증빙을 연결해 채점한다.

## 8. 운영 유의사항

- 결과물이 예쁘거나 화려하다는 이유만으로 높은 점수를 주지 않는다.
- 학생의 취향과 다른 디자인이라는 이유로 감점하지 않는다.
- 반영하지 않은 요청은 보류·제외 근거가 타당한지 확인한다.
- 코드, 데이터베이스, 특정 프로그램 사용을 공통 필수조건으로 추가하지 않는다.
- 동일 결함을 설명 없이 여러 문항에서 반복 감점하지 않는다.
