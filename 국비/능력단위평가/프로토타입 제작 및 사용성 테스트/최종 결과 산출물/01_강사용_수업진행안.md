## 2. 평가 목표

학생이 준비된 디자인 자료를 실제 과업과 유사한 작동 프로토타입으로 통합하고, 분석 방향에 맞는 참여자를 선정해 표준화된 과업 테스트를 수행할 수 있는지 평가한다. 관찰 원자료에서 인사이트와 개선 방향을 도출하고 기간·중요도·공수에 따라 수정 범위를 결정하여 전후와 재확인 결과를 관리하는 능력도 확인한다.

## 3. 평가 전 준비

- [ ] 학생별 선행 결과물 또는 동일 난이도의 입력자료를 준비한다.
- [ ] 프로토타입 제작·공유 도구와 테스트 기기를 점검한다.
- [ ] 목표 사용자 조건과 가까운 동료 참여자 2명 이상을 교차 배정한다.
- [ ] 같은 학생의 결과를 아는 참여자가 과도하게 힌트를 주지 않도록 안내한다.
- [ ] 참여자에게 실명·연락처를 요구하지 않고 코드로 기록하도록 한다.
- [ ] 촬영·녹음은 선택이며 사전 동의가 없으면 관찰지로만 기록하도록 한다.
- [ ] 네트워크 장애 시 사용할 로컬 파일·화면 순서 자료를 준비한다.

## 5. 테스트 통제

- 모든 참여자에게 같은 시작 상태, 과업 문장과 성공 조건을 적용한다.
- 진행자는 조작 위치를 알려 주거나 평가 결과를 유도하지 않는다.
- 참여자가 막혔을 때 도움을 제공해야 한다면 시점·내용과 이후 결과를 기록한다.
- 테스트 중 프로토타입을 즉시 수정하지 않는다. 기준 버전을 유지하고 모든 참여자의 1차 테스트 후 수정한다.
- 참여자의 능력을 평가하는 것이 아니라 프로토타입을 평가한다는 점을 알린다.
- 참여자별 자료에는 `P01`, `P02`처럼 코드를 사용한다.

## 6. 관찰 포인트

- 프로토타입이 시작·진행·완료와 오류 회복까지 실제로 조작되는가.
- 화면 요소·아이콘·서체·모션 또는 사운드가 일관되고 기능적 피드백을 제공하는가.
- 참여자 선정 기준이 테스트 목표와 연결되는가.
- 과업 성공, 시간, 오류, 이동 경로, 도움, 발언이 원자료에 남는가.
- 사용성 문제와 선호 의견을 구분하는가.
- 중요도뿐 아니라 공수와 남은 시간을 고려해 수정 범위를 정하는가.
- 수정 후 같은 핵심 과업을 재확인하는가.

## 7. 강사 개입 범위

허용:

- 평가 범위, 시간, 제출 규칙과 개인정보 최소 수집 안내
- 도구 사용의 일반적인 기능과 링크 권한 문제 안내
- 참여자 순서와 테스트 공간 배정

금지:

- 학생 대신 프로토타입 연결·문제 분석·수정 우선순위를 결정하는 행위
- 테스트 중 참여자에게 정답 경로나 조작 위치를 알려 주는 행위
- 특정 시각안 또는 개선안을 정답으로 지시하는 행위
