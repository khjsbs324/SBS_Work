# 학생공개용 채점기준

## 평가에서 보는 흐름

이 평가는 화면을 만든 것만으로 끝나지 않습니다. 다음 과정이 직접 증빙으로 연결되는지를 봅니다.

`입력자료 → 프로토타입 제작 → 참여자·테스트 설계 → 실행 기록 → 결과 분석 → 개선 대상 → 수정 범위·순서 → 수정 전후·재확인 → 관리 지침`

## 평가 영역

### 1. 제작 자료와 화면 구성

확인 내용:

- 프로토타입에 필요한 자료를 목적에 맞게 준비했는가
- 외부 자료의 출처와 이용 조건, 직접 제작·가공 내역이 있는가
- 화면 요소·아이콘·서체·애니메이션을 비교하고 근거 있게 선택했는가

### 2. 작동 프로토타입

확인 내용:

- 핵심 과업의 시작·진행·완료가 실제로 조작되는가
- 과업에 필요한 정상·오류·빈·로딩·성공 상태가 있는가
- 모션 또는 사운드가 조작 결과와 상태를 이해하는 데 도움을 주는가
- 테스트 시작점과 기준 버전을 식별할 수 있는가

### 3. 분석 방향과 참여자

확인 내용:

- 사용성과 선호도에서 확인할 질문을 구분했는가
- 목표 사용자 조건과 연결된 포함·제외 기준이 있는가
- 참여자의 관련 경험·숙련도와 선정 이유가 기록됐는가
- 소규모 테스트의 한계를 알고 결론 범위를 제한했는가

### 4. 테스트 방법과 원자료

확인 내용:

- 과업과 성공·부분 성공·실패 조건이 명확한가
- 모든 참여자에게 같은 시작 상태와 진행 절차를 적용했는가
- 행동·시간·오류·경로·도움·발언과 사후 의견이 기록됐는가
- 참여자의 개인정보를 최소한으로 다뤘는가

### 5. 분석과 적용 대상

확인 내용:

- 참여자별 원자료와 결과 집계가 일치하는가
- 반복 패턴과 예외, 관찰 사실과 해석을 구분했는가
- 인사이트와 개선 방향이 직접 근거에 연결되는가
- 사용성 문제와 선호 의견을 구분하여 적용 화면·UX를 정했는가

### 6. 수정 범위·우선순위·관리

확인 내용:

- 기간·자원·공수·의존성을 고려해 이번 반영과 보류 범위를 정했는가
- 영향도·빈도·시급성·공수로 중요도와 적용 순서를 정했는가
- 문제와 수정 전후·재확인 결과가 연결되는가
- 버전 이력과 향후 점검 조건을 관리 지침으로 남겼는가

## 공통 4수준 성취기준

| 수준 | 판단 기준 |
|---|---|
| 매우 충실 | 필요한 증빙이 빠짐없이 있고 프로토타입이 작동합니다. 테스트 원자료에서 분석·수정·재확인까지 근거와 버전이 명확히 연결됩니다. |
| 충실 | 주요 동작과 과정은 확인되지만 일부 상태·원자료·분석·범위 판단·재확인 또는 관리 정보가 부족합니다. |
| 부분 충실 | 결과물은 있으나 핵심 경로가 일부 끊기거나 테스트와 수정의 연결이 약해 추가 설명이 많이 필요합니다. |
| 미충족 | 작동 프로토타입, 신뢰할 수 있는 테스트 기록 또는 수정 관리의 핵심 증빙을 확인하기 어렵습니다. |

## 작업할 때 기억할 점

- 화면을 많이 만드는 것보다 핵심 과업과 필요한 상태를 완결하세요.
- 참여자에게 정답을 알려 주지 말고 도움을 줬다면 기록하세요.
- 만족도만 묻지 말고 실제 행동·시간·오류·경로를 관찰하세요.
- 관찰한 사실과 자신의 해석, 문제와 해결안을 분리하세요.
- 모든 문제를 고치기보다 기간과 영향에 맞는 수정 범위를 설명하세요.
- 수정본만 보여 주지 말고 문제·수정 전후·재확인을 같은 번호로 연결하세요.

실제 서비스 코드, 백엔드와 배포는 이 평가의 필수 대상이 아닙니다.
