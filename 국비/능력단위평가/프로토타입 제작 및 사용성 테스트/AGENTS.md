# 프로토타입 제작 및 사용성 테스트 작업 지침

상위 `국비/AGENTS.md`, `능력단위평가/AGENTS.md`와 `ncs-exam-production` 절차를 먼저 따른다. 이 문서는 통합 학습모듈에서 두 번째 능력단위만 분리하여 평가할 때의 차이를 정한다.

## 기준 범위

- 능력단위: 프로토타입 제작 및 사용성 테스트
- 능력단위 코드: `0802010414_16v2`
- 원본 PDF는 `0802010413_16v2`와 `0802010414_16v2`를 함께 수록한 통합 모듈이다.
- PDF 13쪽의 내용체계 중 대상 능력단위요소 3개와 PDF 45~90쪽의 학습 3·4만 사용한다.
- 평가목표는 PDF 65쪽의 3개와 PDF 89쪽의 7개를 문장·순서의 기준으로 사용한다.
- `PT-01`~`PT-10`은 내부 추적 ID이며 NCS 공식 코드가 아니다.

## 평가 조건

- 별도 지시가 없으면 개인 포트폴리오형 평가, 300분, 총점 100점으로 운영한다.
- 이전 능력단위에서 작성한 데이터·스토리보드·스케치·저충실도 시안 또는 강사 제공 자료를 입력으로 사용한다.
- 필수 결과는 편집 가능한 화면 디자인, 핵심 과업 프로토타입, 테스트 계획·원자료, 결과 분석, 수정 우선순위, 반영 전후와 관리 지침이다.
- 교실 내 테스트 참여자는 목표 사용자 조건과 가까운 동료 2명 이상으로 운영할 수 있다. 소규모 결과를 전체 사용자로 일반화하지 않는다.
- 촬영·녹음은 필수가 아니다. 실시할 경우 사전 동의와 최소 수집 원칙을 적용하며, 보고서에는 실명 대신 참여자 코드를 사용한다.
- 실제 서비스 코드, 백엔드, 운영 데이터 연동과 배포는 필수로 요구하지 않는다.

## 판단 원칙

- 프로토타입은 핵심 과업의 시작·진행·완료와 필요한 오류·빈·로딩·성공 상태를 직접 조작해 확인할 수 있어야 한다.
- 시각 완성도만 보지 않고 화면 요소·아이콘·서체·애니메이션 또는 사운드의 목적과 일관성, 비교·선택 근거를 확인한다.
- 테스트는 참여자 적합성, 과업·성공 조건, 진행 절차, 관찰 원자료, 결과 분석이 연결되어야 한다.
- 관찰 사실과 해석, 선호와 사용성 문제, 발견 문제와 해결안을 구분한다.
- 수정은 모든 의견의 반영 여부가 아니라 영향도·빈도·시급성·공수와 평가 기간을 고려한 우선순위와 범위 판단을 본다.
- 동일 원인으로 여러 문항을 반복 감점하지 않는다. 확인하지 못한 링크·동작을 추측하여 인정하거나 0점 처리하지 않는다.

## 문서 분리와 검증

- 학생용 문서에는 내부 문항 ID, 문항별 점수 계산, 강사용 판단 예시를 노출하지 않는다.
- 강사용 문서는 PDF·원본 프레임·프로토타입 경로·테스트 원자료·수정 이력에 연결해 판단할 수 있도록 작성한다.
- 변경 후 `국비` 폴더에서 `python -B scripts/harness.py check --records`를 실행한다.
- 실제 배포용 PDF 생성, 외부 사이트 등록과 학생별 채점은 사용자가 별도로 요청할 때만 수행한다.
