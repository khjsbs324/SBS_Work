# 구현 응용 강사용 수업진행안

## 운영 조건

- 개인평가 240분
- 입력: 기존 개인 브랜딩 포트폴리오 구현 결과 또는 강사 제공 시작 소스
- 제출: 실행 가능한 소스 ZIP 1개, 구현 응용 보고서 PDF 1개
- 외부 배포·특정 프레임워크·서버·데이터베이스는 필수가 아님

## 사전 준비

- 입력 소스의 로컬 실행 방법과 시작 상태를 학생·강사가 함께 확인한다.
- 개인 구현물이 없는 학생에게는 같은 결함과 요구를 가진 시작 소스를 제공한다.
- 데스크톱 1440px, 태블릿 768px, 모바일 390px 또는 과제에서 정한 대체 기준을 공지한다.
- 실제 개발진이 없는 개인평가를 위해 반응형·접근성·성능·기능 충돌을 포함한 강사 제공 협업 이슈를 준비한다.

## 시간 운영

1. 0~25분: 입력 구현 진단, 본래 의도·문제·응용 목표·근거 ID 설정
2. 25~65분: 콘텐츠 모델·공통 구성요소·데이터와 핵심 과업의 시각 흐름 재구성
3. 65~105분: 영역별 멀티미디어 기능 제안, 기술·제약·대안과 실제 활용
4. 105~155분: HTML 의미 구조, 디자인 토큰, 반응형·접근성·파일 규칙 표준화
5. 155~190분: 미디어 기능·공통 CSS·JavaScript·상태·예외의 재사용 구현
6. 190~215분: 협업 이슈 검토, 디자인 전달 문서, 결정과 수정 반영
7. 215~230분: 세 화면 너비·키보드·Console·Network·성능·접근성 재검증
8. 230~240분: ZIP·PDF 정리, 파일명·실행·누락·열림 확인

## 운영 유의 사항

- 기능을 새로 추가하기 전에 기존 구현의 반복·불일치·장애와 본래 의도를 먼저 기록하게 한다.
- 표준화는 체크리스트만 작성하지 않고 실제 코드의 의미 구조·토큰·브레이크포인트·상태와 연결하게 한다.
- 라이브러리·프레임워크 사용 여부는 자유지만 사용 목적, 의존성, 실행 방법과 대체 가능성을 기록하게 한다.
- 협업 상대가 없으면 강사 제공 이슈를 사용한다. 가상의 동료 이름·응답·회의 내용을 만들지 않게 한다.
- 외부 배포 여부보다 압축 해제 후 로컬 실행과 직접 동작 검증을 우선한다.

## 회수·검증 순서

1. ZIP·PDF 파일명과 열림, 압축 해제 후 실행 방법을 확인한다.
2. 보고서의 근거 ID와 코드·화면·개발 문서가 대응하는지 확인한다.
3. 콘텐츠 모델·공통 구성요소가 홈·목록·상세 등에서 재사용되는지 확인한다.
4. 마우스·키보드로 핵심 과업 흐름과 미디어 기능의 상태·오류 대안을 실행한다.
5. 데스크톱·태블릿·모바일에서 겹침·잘림·가로 스크롤·탐색·입력을 확인한다.
6. HTML 의미 구조, CSS 표준·토큰, JavaScript 상태·예외와 자산·경로를 확인한다.
7. 협업 이슈→결정→코드 변경→수정 전후→재검증 연결을 확인한다.
8. Console 오류와 Network 404, 키보드 포커스, 대체 텍스트와 주요 성능 기록을 확인한다.
9. `Exam.md` IA-01~IA-09에 직접 증빙을 연결해 채점한다.
