# 구현 응용 포트폴리오 평가

## 시험 문제

개인 브랜딩 포트폴리오 사이트의 콘텐츠·기능 요소를 표준화하여 응용 구현하고, 협업을 통해 최적화한 결과물을 제출해 주세요.

## 과제 목표

기존에 구현한 개인 브랜딩 포트폴리오 사이트를 여러 화면과 환경에서 활용 가능한 구조로 발전시킵니다. 콘텐츠와 기능을 재사용하고 웹 표준·반응형·접근성·성능 기준을 적용하며, 개발 전달 문서와 검토 이슈를 바탕으로 본래 디자인 의도에 맞게 결과물을 최적화합니다.

## 작업 순서

1. 기존 구현의 본래 의도, 반복 코드, 불일치, 기능·접근성·성능 문제와 응용 목표를 정리합니다.
2. 홈·프로필·프로젝트 목록·상세·문의의 콘텐츠를 공통 모델·구성요소·데이터로 구성해 활용합니다.
3. 핵심 과업의 시작·탐색·선택·완료·예외 흐름을 화면과 상호작용으로 구현합니다.
4. 영역별 멀티미디어 기능을 제안하고 기술·제약·대안을 정한 뒤 실제 화면에 활용합니다.
5. 의미 있는 HTML, 디자인 토큰, 반응형·접근성·자산·파일 규칙을 정하고 코드에 적용합니다.
6. 목적이 다른 두 종류 이상의 미디어 기능을 상태·키보드·대체 콘텐츠·오류 처리와 함께 제작합니다.
7. CSS·JavaScript·컴포넌트·유틸리티를 여러 화면에서 재사용하고 세 화면 너비에서 확인합니다.
8. 실제 검토 의견 또는 강사 제공 이슈를 분석해 반영·보류·제외 결정을 내리고 코드에 반영합니다.
9. 디자인 전달 문서와 수정 전후, 기능·성능·접근성·Console·Network 재검증을 정리합니다.

## 필수 화면·환경

- 화면: 프로젝트 목적에 필요한 홈, 프로필, 프로젝트 목록, 프로젝트 상세, 문의
- 기준 폭: 데스크톱 1440px, 태블릿 768px, 모바일 390px
- 다른 화면 또는 기준 폭을 사용한다면 프로젝트 목적과 선택 이유를 보고서에 적습니다.
- 핵심 흐름은 마우스와 키보드로 확인 가능해야 합니다.

## 협업 자료 규칙

- 실제 동료·강사 검토 또는 강사가 제공한 이슈를 사용할 수 있습니다.
- 자료 유형, 요청·질문·대안·결정·반영 상태를 표시합니다.
- 실제로 존재하지 않는 동료 응답이나 회의 내용을 만들면 안 됩니다.
- AI를 사용했다면 코드·문서 생성 위치와 직접 확인·수정한 내용을 기록합니다. 실행하지 않은 코드를 정상이라고 적으면 안 됩니다.

## 제출물

```text
이름_구현응용.zip
이름_구현응용보고서.pdf
```

ZIP에는 HTML·CSS·JavaScript, 이미지·폰트 등 사용 자산, 실행 안내와 개발 전달 문서를 포함합니다. PDF에는 응용 목표, 표준 기준, 콘텐츠·기능 활용, 협업 결정, 수정 전후와 재검증 결과를 근거 ID로 정리합니다.

## 평가에서 중요한 내용

- 콘텐츠·구성요소·데이터를 여러 화면과 상태에서 활용한 구조
- 콘텐츠 특성에 맞게 실제 구현된 시각적 흐름
- 제안에서 끝나지 않고 실제 화면에 활용된 멀티미디어 기능
- 웹 표준·반응형·접근성·성능과 일관된 코드·자산 규칙
- 목적에 맞고 대체·오류 상태가 있는 디지털 미디어 기능
- 공통 CSS·JavaScript·컴포넌트·유틸리티의 재사용
- 협업 이슈와 실제 코드 변경의 추적성
- 개발자가 구현·검수할 수 있는 디자인 전달 문서
- 본래 의도를 유지한 수정 전후와 최종 재검증
