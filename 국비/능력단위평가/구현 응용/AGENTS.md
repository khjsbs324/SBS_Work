# 구현 응용 평가 지침

## 평가 목적

이 폴더의 능력단위는 `구현 응용(0802010419_16v3)`이다. 학생이 이미 구현된 개인 브랜딩 포트폴리오 사이트를 바탕으로 콘텐츠와 기능을 재사용 가능한 구조로 발전시키고, 웹 표준·반응형·접근성·성능 기준을 적용하며, 개발 협업과 문서화를 통해 본래 디자인 의도에 맞는 최적화 결과물을 도출하는 능력을 평가한다.

## 원문 범위

- 원본은 `구현(0802010418_16v3)`과 `구현 응용(0802010419_16v3)`이 결합된 PDF다.
- 평가는 응용 코드 `0802010419_16v3`의 수행준거 9개만 사용한다.
- 기본 구현 코드 `0802010418_16v3`의 대응 수행준거는 이 평가에서 제외한다.
- 응용 수행준거를 원문 순서대로 `IA-01`~`IA-09`에 연결한다. IA 번호는 내부 추적 ID이며 공식 NCS 수행준거 번호가 아니다.

## 평가 조건

- 개인평가, 240분, 포트폴리오 방식으로 진행한다.
- 입력 자료는 학생의 기존 개인 브랜딩 포트폴리오 구현 결과 또는 강사가 제공한 시작 소스다.
- 필수 제출은 `이름_구현응용.zip` 1개와 `이름_구현응용보고서.pdf` 1개다.
- ZIP에는 로컬에서 실행 가능한 HTML·CSS·JavaScript, 자산, 실행 안내와 개발 전달 문서를 포함한다.
- PDF에는 입력 자료, 표준화 기준, 콘텐츠·기능 활용, 협업 이슈, 수정 전후, 테스트·최적화 결과와 근거 ID가 판독 가능해야 한다.
- 외부 배포·특정 프레임워크·서버·데이터베이스는 필수 조건이 아니다.

## 판단 원칙

- 새로운 효과의 수보다 기존 구현을 구조화·표준화·재사용·최적화한 근거를 우선한다.
- `입력 구현 → 문제·목표 → 표준·명세 → 응용 구현 → 협업 결정 → 수정 전후 → 재검증`의 추적성을 평가한다.
- 보고서의 주장만으로 기능을 인정하지 않고 제출 소스를 로컬에서 실행해 브라우저 동작을 확인한다.
- 웹 표준·접근성·반응형·성능은 체크리스트 작성 여부보다 실제 코드·화면·측정 결과를 함께 본다.
- 실제 동료 검토와 강사 제공 이슈를 모두 인정하되 가상의 협업 응답을 임의로 창작하지 않는다.
- 같은 원인의 문제를 여러 문항에서 중복 감점하지 않는다.

## 채점과 검증

- `Exam.md`의 `IA-01`~`IA-09`를 사용하며 총점은 100점이다.
- 모든 점수는 PDF 페이지·근거 ID, 코드 파일·선택자·함수, 브라우저 화면·동작·테스트 기록 중 하나 이상의 직접 증빙에 연결한다.
- 원문 9문장, 수행준거 TXT 9개, Exam 9문항과 영역별 32·34·34점, 총 100점을 대조한다.
- 개인평가 240분, ZIP 1개·PDF 1개 조건이 모든 문서에 일치하는지 확인한다.
