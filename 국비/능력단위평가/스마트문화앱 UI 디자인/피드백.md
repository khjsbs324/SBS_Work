# 스마트문화앱 UI 디자인 피드백 기준

## 작성 방식

[공통 피드백 작성 지침](../피드백.md)의 말투와 근거 원칙을 적용한다. 학생의 보고서 PDF, 편집 가능한 디자인 원본과 프로토타입을 대조하여 작성한다. 정적 화면만 확인한 내용과 실제 프로토타입으로 조작한 내용을 구분한다.

12개 평가항목은 모두 검토해 교사용 기록에 남기되 학생 공개문은 사용자 과업에 가장 큰 영향을 주는 문제를 중심으로 구성한다. 내부 UI 번호, 원점수 계산, 순위와 강사용 판단 예시는 공개하지 않는다.

## 반드시 확인할 내용

- UX 전략의 사용자·문제·가치·콘텐츠·핵심 과업이 디자인 콘셉트에 연결되는가.
- 포지셔닝의 비교 대상·축·차별 방향과 디자인 결정이 연결되는가.
- 업무 플로우 단계별 화면 목적·콘텐츠 위계·상태와 스타일 방향이 정의됐는가.
- 무드 보드와 레퍼런스에서 관찰한 원리가 실제 화면에 적용됐는가.
- 컬러·서체·간격·레이아웃·아이콘·컴포넌트·상태·접근성 규칙이 명확한가.
- 선택 플랫폼의 공식 지침 URL·확인일·적용 또는 변형 근거가 있는가.
- 콘텐츠·콘셉트·스타일 가이드가 핵심 화면에서 일관되게 조합되는가.
- 심미성이 정보 위계·가독성·조작 명확성과 충돌하지 않는가.
- 프로토타입에서 핵심 과업과 정상·오류·빈·로딩·성공 상태를 확인할 수 있는가.
- 관계자 의견의 출처·쟁점·판단·반영·보류와 수정 전후가 추적되는가.

## 판단 범위

- 평가자의 디자인 취향, 특정 유행, 화면 수나 장식량으로 점수를 정하지 않는다.
- 공식 플랫폼 컴포넌트와 다르다는 사실만으로 감점하지 않는다. 변형 이유, 일관성, 사용성, 접근성과 구현 가능성을 함께 판단한다.
- 디자인 도구의 종류, 유료 플랜 사용, AI 사용 여부는 점수 기준이 아니다.
- 코드·실제 앱 빌드·스토어 배포가 없다는 이유로 감점하지 않는다.
- 프로토타입에서 확인하지 못한 동작을 정상이라고 추정하지 않는다. 링크 접근 장애와 제출 누락을 구분한다.
- 같은 원인으로 여러 화면에 반복된 문제는 주된 평가항목에서 설명하고 중복 감점하지 않는다.

## 실행 가능한 개선 안내

- 콘셉트가 추상적이면 어떤 사용자 문제와 과업에서 해당 키워드가 필요한지, 어느 요소에 어떻게 반영할지 연결하도록 안내한다.
- 포지셔닝이 약하면 비교 축과 경쟁·유사 앱의 실제 특성을 다시 대조하고 차별 방향이 화면에서 보이는지 확인하게 한다.
- 스타일 가이드 불일치는 토큰·컴포넌트·상태 중 어느 규칙을 수정해야 하는지 구체적으로 짚는다.
- 화면 위계 문제는 사용자가 먼저 보고 행동해야 할 콘텐츠, 주요 행동과 보조 행동을 구분해 수정하도록 안내한다.
- 플랫폼 문제는 학생이 선택한 공식 지침의 관련 절과 화면 조건을 대조하도록 한다. 고정된 과거 수치를 정답처럼 제시하지 않는다.
- 프로토타입 문제는 시작 화면, 조작 대상, 전환 결과, 오류·회복 중 끊긴 위치와 재검증 순서를 설명한다.
- 관계자 의견은 모두 반영하게 하지 않고 사용자·콘텐츠·개발 제약에 따라 선택·수정·보류 이유를 기록하게 한다.

## 공개 전 확인

- 학생명·앱명·대상 플랫폼·최종점수와 실제 자료가 일치하는가.
- 정적 화면 관찰과 프로토타입 동작 확인을 구분했는가.
- 확인한 공식 지침의 시점과 범위를 넘어서 단정하지 않았는가.
- 같은 문제를 반복 설명하거나 중복 감점하지 않았는가.
- 학생이 수정할 화면·컴포넌트·상태와 재검증 조건을 찾을 수 있는가.
- 다른 학생 또는 다른 능력단위의 결과가 섞이지 않았는가.
- 마지막에 공개 가능한 최종점수와 가장 먼저 수정할 항목을 짧게 안내했는가.
