# 스마트문화앱 UI 디자인 평가 지침

## 평가 목적

이 폴더의 능력단위는 `스마트 문화 앱 UI 디자인(0803020912_18v3)`이다. 학생이 기존 UX 전략과 앱 콘텐츠·업무 플로우를 바탕으로 디자인 콘셉트와 포지셔닝을 수립하고, 선택한 플랫폼의 현재 공식 지침을 참조하여 스타일 가이드와 핵심 화면 시안을 제작한 뒤 관계자 의견에 따라 보완하는 전 과정을 평가한다.

## 기준 자료

1. 사용자의 최신 지시
2. `Exam.md`
3. `스마트문화앱 UI 디자인 수행준거.txt`
4. 원본 NCS 학습모듈 PDF와 `pdf요약결과.md`
5. `최종 결과 산출물/`의 운영·제출 문서

원문의 문장·순서·개수는 수행준거 TXT를 기준으로 하고, 평가 방식·배점·제출 조건은 현재 `Exam.md`를 따른다. `UI-01`~`UI-12`는 내부 추적 ID이며 공식 NCS 수행준거 번호가 아니다.

## 평가 조건

- 개인평가, 300분, 포트폴리오 방식으로 진행한다.
- 기존 스마트 문화 앱 콘텐츠 기획·사용자 조사·UX 설계 결과 또는 강사가 제공한 앱 브리프 한 건을 입력 자료로 사용한다.
- 학생은 주 대상 플랫폼과 기기 범위를 먼저 정하고, 해당 플랫폼의 현재 공식 디자인 지침 URL·확인일·적용 항목을 기록한다.
- 필수 제출은 UI 디자인 보고서 PDF, 편집 가능한 디자인 원본 또는 접근 가능한 공유 링크, 핵심 과업 한 건을 확인할 수 있는 프로토타입이다.
- 앱 코드, 빌드 파일, 백엔드, 앱스토어 등록과 실제 배포는 필수 조건이 아니다.
- Figma, Sketch, Adobe XD, Photoshop, Illustrator 등 도구의 종류 자체는 점수 기준이 아니다.

## 현재 플랫폼 지침 적용

원본은 2019년 발행 자료이므로 당시 OS 화면 예시나 수치를 현재 공통 규격으로 고정하지 않는다. 학생이 선택한 플랫폼과 기기 범위에 맞는 최신 공식 자료를 적용한다.

- Apple Human Interface Guidelines: <https://developer.apple.com/design/human-interface-guidelines/>
- Android UI Design: <https://developer.android.com/design/ui>
- Material Design 3: <https://m3.material.io/>

공식 지침의 모든 요소를 복제하는 것이 아니라 프로젝트에 적용한 레이아웃·내비게이션·컴포넌트·상태·접근성 규칙과 변형 이유를 확인한다. 브랜드 표현을 위해 변형한 경우 일관성, 사용성, 구현 가능성을 설명하면 인정한다.

## 판단 원칙

- 결과물의 유행성이나 평가자 취향보다 UX 전략, 콘텐츠, 업무 플로우, 콘셉트, 스타일 가이드와 화면 시안의 연결을 본다.
- 포지셔닝은 형용사 나열이 아니라 비교 축·경쟁·유사 서비스 근거와 선택한 디자인 방향으로 판단한다.
- 무드 보드와 레퍼런스는 이미지 수보다 관찰한 원리와 자기 디자인에 적용·배제한 이유를 본다.
- 스타일 가이드는 색·서체·간격·레이아웃·아이콘·컴포넌트·상태·접근성 규칙이 실제 화면에 반복 적용되는지 확인한다.
- 플랫폼 지침과 다른 디자인도 사용자·브랜드·기술 근거가 있고 핵심 사용성을 해치지 않으면 인정한다.
- 심미성은 장식의 양이 아니라 위계·균형·대비·가독성·콘텐츠 적합성·브랜드 일관성으로 판단한다.
- 프로토타입은 앱 전체 구현이 아니라 핵심 과업의 시작·진행·완료와 필요한 오류·빈·로딩·성공 상태를 검토하기 위한 증빙이다.
- 관계자 의견을 모두 반영했는지가 아니라 의견의 출처·판단·반영·보류 이유와 수정 결과를 평가한다.
- 동일한 원인은 주된 문항에서만 감점하고 다른 문항에서는 관련 근거로 참조한다.

## 직접 증빙

- UX 전략·타깃 사용자·콘텐츠·핵심 과업과 업무 플로우
- 콘셉트 키워드, 포지셔닝 근거, 레퍼런스·무드 보드와 적용 원리
- 플로우 단계별 디자인·스타일 정의
- 플랫폼 공식 지침의 URL·확인일·적용 또는 변형 항목
- 컬러·타이포그래피·간격·레이아웃·아이콘·컴포넌트·상태·접근성 스타일 가이드
- 스타일 가이드가 적용된 핵심 화면과 화면별 콘텐츠 위계
- 핵심 과업 프로토타입과 정상·오류·빈·로딩·성공 상태
- 관계자 검토 기록, 판단, 수정 전후와 최종안

확인하지 못한 프로토타입 동작을 정상이라고 추정하지 않는다. 링크 접근 실패와 학생 제출 누락을 구분하고, 확인 불가 범위와 재확인 조건을 기록한다.

## 채점과 피드백

- `Exam.md`의 UI-01~UI-12를 사용하고 모든 점수에 PDF 페이지·절, 디자인 원본의 프레임·컴포넌트, 프로토타입 화면·상태 중 하나 이상의 직접 증빙을 연결한다.
- 학생 공개용 피드백은 실제 화면·요소·상태를 근거로 강점, 주요 문제, 사용자에게 미치는 영향, 수정 방법과 재확인 조건을 설명한다.
- 공개문에 내부 UI 번호, 원점수 환산 과정, 순위, 강사용 판단 예시와 다른 학생 정보를 넣지 않는다.

## 검증

국비 폴더에서 다음을 실행한다.

```powershell
python -B scripts/harness.py check --records
```

원문 12문장, Exam 12문항, 강사용 채점표와 학생 공개용 기준의 대응, 총점 100점, 4단계 점수 구간, 300분과 필수 제출 조건을 함께 확인한다. 학생용 자료에 강사용 채점기준이 노출되지 않았는지도 검토한다.
