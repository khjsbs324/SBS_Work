# 강사용 기준 및 채점표

평가 종료 전 학생에게 공개하지 않습니다.

## 1. 모범 수행의 연결 구조

이 평가에는 학생이 복제해야 하는 하나의 앱 화면이나 시각적 정답이 없다. 다음 연결 관계가 모범 수행의 기준이다.

```text
UX 전략·사용자·콘텐츠·핵심 과업
→ 디자인 콘셉트와 포지셔닝
→ 업무 플로우별 화면·상태 계획
→ 레퍼런스 분석과 무드 보드
→ 대상 플랫폼 공식 지침
→ 재사용 가능한 스타일 가이드
→ 핵심 화면과 프로토타입
→ 관계자 의견과 판단
→ 수정 전후·변경 이력·최종안
```

## 2. 직접 증빙 확인표

- [ ] UX 전략에서 디자인 키워드와 콘셉트가 도출됐다.
- [ ] 경쟁·유사 앱 비교와 포지셔닝 축·목표 위치가 있다.
- [ ] 핵심 업무 플로우의 화면 목적·콘텐츠 위계·상태가 정의됐다.
- [ ] 레퍼런스에서 추출한 원리와 적용·배제 이유가 있다.
- [ ] 대상 OS·기기와 공식 지침 URL·확인일·관련 절이 기록됐다.
- [ ] 컬러·서체·간격·레이아웃·아이콘·컴포넌트·상태·접근성 규칙이 있다.
- [ ] 스타일 가이드와 핵심 화면의 요소·상태가 일치한다.
- [ ] 핵심 과업 프로토타입을 직접 조작할 수 있다.
- [ ] 필요한 오류·빈·로딩·성공·회복 상태가 표현됐다.
- [ ] 관계자 의견, 반영·수정·보류 판단과 수정 전후가 추적된다.

## 4. 영역별 빠른 검수

### 디자인 콘셉트 수립 — 32점

UX 전략·사용자·콘텐츠·핵심 과업에서 디자인 콘셉트와 포지셔닝이 도출되고, 업무 플로우별 화면·상태 계획과 무드 보드에 연결되는지 확인한다.

### 스타일 가이드 제작 — 32점

시각·기능 요소, 플랫폼 공식 지침, 토큰·레이아웃·컴포넌트·상태·접근성 규칙과 관계자 검토 기록을 확인한다.

### 시안 디자인 제작·검토 — 36점

콘텐츠·콘셉트·가이드가 핵심 화면에 일관되게 적용됐는지, 프로토타입으로 과업과 필요한 상태를 확인할 수 있는지, 의견이 최종안에 추적되는지 확인한다.

## 5. 화면과 프로토타입 검토

- 보고서의 정적 화면과 편집 원본의 프레임 이름·버전을 대조한다.
- 프로토타입의 시작 화면을 확인하고 핵심 과업을 직접 수행한다.
- 정상 경로 외에 프로젝트에 필요한 오류·빈·로딩·성공·회복 상태를 확인한다.
- 선택 플랫폼과 화면 범위에서 레이아웃·안전 영역·내비게이션·상태·접근성 적용을 검토한다.
- 확인하지 못한 상호작용은 정적 화면만으로 정상이라고 판단하지 않는다.

## 6. 감점 및 보류 원칙

- 특정 디자인 취향이나 공식 컴포넌트와의 시각적 차이만으로 감점하지 않는다.
- 화면 수·레퍼런스 수·장식량을 독립 점수로 사용하지 않는다.
- 같은 토큰·컴포넌트 문제의 반복은 주된 문항에서만 감점한다.
- 의견을 보류한 근거가 타당하면 모두 반영하지 않았다는 이유로 감점하지 않는다.
- 앱 코드·실제 빌드·배포가 없다는 이유로 감점하지 않는다.
- 원본·프로토타입 링크가 열리지 않으면 권한·네트워크 문제와 제출 누락을 구분하고 확인 불가 범위를 기록한다.
