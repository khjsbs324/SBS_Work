# 강사용 수업진행안

## 1. 평가 개요

| 항목 | 내용 |
|---|---|
| 능력단위 | 스마트 문화 앱 UI 디자인 |
| 능력단위 코드 | `0803020912_18v3` |
| 평가 방식 | 개인 포트폴리오 및 디자인 원본·프로토타입 평가 |
| 평가 시간 | 300분 |
| 평가 대상 | 기존 스마트 문화 앱 UX 설계 또는 강사 제공 브리프 한 건 |
| 필수 제출 | 보고서 PDF, 편집 원본 또는 공유 링크, 핵심 과업 프로토타입 |
| 문항·총점 | 12문항, 100점 |

## 2. 평가 목적

학생이 UX 전략과 업무 플로우를 사용자 중심의 시각 언어로 전환하고, 현재 플랫폼 환경에 맞는 스타일 가이드와 핵심 화면을 제작할 수 있는지 평가한다. 스타일 가이드가 실제 화면과 프로토타입에 일관되게 적용되는지, 관계자 의견을 판단하여 최종안으로 보완하는지도 함께 본다.

## 3. 평가 전 준비

- [ ] 학생별 앱 주제와 기존 UX 설계·콘텐츠 자료를 확정한다.
- [ ] 목표 사용자, 핵심 과업과 업무 플로우가 준비됐는지 확인한다.
- [ ] 대상 OS·기기 범위와 공식 지침 확인 방법을 안내한다.
- [ ] 디자인 원본·공유 링크와 프로토타입을 열람할 수 있는 환경을 준비한다.
- [ ] 학생에게 02·03·05번 문서만 배포한다.
- [ ] 강사용 채점표와 `Exam.md`가 학생 자료에 포함되지 않았는지 확인한다.

## 4. 300분 진행

### 1단계. 프로젝트·플랫폼 범위 확정 — 20분

앱의 사용자·문제·가치·콘텐츠·핵심 과업, 대상 OS와 기기 범위를 확정한다. 공식 지침 URL·확인일·적용할 절을 기록한다.

### 2단계. 콘셉트와 포지셔닝 — 45분

UX 전략에서 디자인 키워드를 도출하고 경쟁·유사 앱의 특성과 비교 축을 정하여 포지셔닝을 설정한다. 선택·배제한 방향의 이유를 기록한다.

### 3단계. 플로우별 스타일과 콘셉트 시각화 — 45분

핵심 업무 플로우를 단계별로 나누고 화면 목적·콘텐츠 위계·필요 상태를 정한다. 레퍼런스와 무드 보드에서 적용할 원리를 추출한다.

### 4단계. 스타일 가이드 제작 — 70분

컬러·서체·간격·레이아웃·이미지·아이콘·컴포넌트·상태·접근성 규칙을 정의한다. 선택 플랫폼의 공식 지침과 앱 개발 범위를 반영해 재사용 가능한 구조로 정리한다.

### 5단계. 핵심 화면과 프로토타입 제작 — 80분

핵심 과업의 시작·진행·완료 화면과 필요한 오류·빈·로딩·성공 상태를 제작한다. 스타일 가이드와 콘텐츠 위계를 적용하고 주요 연결을 프로토타입으로 구성한다.

### 6단계. 관계자 검토와 시안 보완 — 30분

기획·개발·디자인·사용자 관점의 의견을 수렴한다. 의견을 반영·수정·보류하고 그 이유와 수정 전후를 기록한다.

### 7단계. 제출 점검 — 10분

보고서 PDF의 가독성, 원본·프로토타입 접근, 파일명, 링크 권한과 최종 버전을 확인한다.

## 5. 과정 관찰 항목

- UX 전략을 단순 형용사가 아닌 화면 결정으로 전환하는가.
- 포지셔닝 비교 축과 경쟁 근거가 적절한가.
- 업무 플로우에 따라 화면 목적과 상태를 빠짐없이 정의하는가.
- 레퍼런스를 복제하지 않고 원리를 추출하여 적용하는가.
- 스타일 가이드가 실제 컴포넌트와 화면에 재사용되는가.
- 플랫폼 지침을 프로젝트 범위에 맞게 적용·변형하는가.
- 프로토타입이 핵심 과업과 오류 회복을 설명하는가.
- 관계자 의견을 근거로 판단하고 변경 이력을 남기는가.

## 6. 회수 및 채점 순서

1. 학생명·앱명·대상 플랫폼과 필수 제출물 접근 상태를 확인한다.
2. UX 전략·콘셉트·포지셔닝과 업무 플로우를 대조한다.
3. 스타일 가이드의 토큰·컴포넌트·상태와 주요 화면을 대조한다.
4. 공식 플랫폼 지침의 URL·확인일·적용 범위를 확인한다.
5. 프로토타입에서 핵심 과업과 필요한 상태를 직접 조작한다.
6. 관계자 의견, 판단, 수정 전후와 최종안을 연결한다.
7. `Exam.md`의 UI-01~UI-12에 PDF·프레임·프로토타입 직접 증빙을 기록한다.
8. 동일한 문제를 여러 문항에서 반복 감점하지 않았는지 확인한다.

## 7. 운영 유의사항

- 특정 디자인 도구·유료 플랜·AI 사용을 공통 필수조건으로 추가하지 않는다.
- 앱 구현·코드·백엔드·스토어 배포를 요구하지 않는다.
- 화면 수나 장식량보다 핵심 과업과 상태의 완전성, 일관성을 본다.
- 플랫폼 공식 가이드는 평가일 현재 자료를 사용하고 과거 PDF의 규격을 고정 정답으로 쓰지 않는다.
- 외부 링크가 열리지 않으면 학생 누락인지 권한·네트워크 문제인지 구분한다.
