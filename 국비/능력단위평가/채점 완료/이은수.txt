## 사이트 입력용 피드백

1. 컨테이너 변수명

css
/* 학생 코드 */
.con {
  max-width: var(--containner);
}

css
/* 정답 코드 */
.con {
  max-width: var(--container);
}

피드백:
component.css에 선언한 --container와 사용한 --containner의 철자가 다릅니다. Chrome에서 1920px과 1600px의 max-width가 none으로 계산되어 컨테이너가 기준보다 넓어졌습니다. 토큰 이름을 일치시켜야 대화면 중앙 정렬이 정상화됩니다.

2. 데스크톱 5열 Grid

css
/* 학생 코드 */
.grid-5 {
  grid-template-columns: repeat(5 1fr);
}
.product-grid { display: flex; }

css
/* 정답 코드 */
.grid-5 {
  display: grid;
  grid-template-columns: repeat(5, 1fr);
}
.product-grid { margin-top: var(--num4); }

피드백:
1024px 이하에서는 미디어쿼리가 display:grid를 다시 적용해 일부 정상처럼 보이지만, 기본 데스크톱 선언은 쉼표 누락과 Flex 덮어쓰기로 여전히 무효입니다. 1920px 실측에서 display:flex와 columns:none이 확인되므로 기본 5열부터 정확히 고쳐야 합니다.

3. 480px 최소 폭

css
/* 학생 코드 */
body {
  min-width: 480px;
}

css
/* 정답 코드 */
body {
  word-break: keep-all;
}

피드백:
1600px을 480px로 줄인 것은 개선이지만 최소 폭 자체가 남아 있어 480px 테스트의 실제 콘텐츠 폭 465px보다 body가 큽니다. 그 결과 480px 화면에서 가로 스크롤이 생깁니다. 고정 최소 폭은 값만 줄이지 말고 제거해야 합니다.

4. 테스트 결과의 실제값 반영

text
<!-- 학생 보고서 -->
1920px부터 480px까지 가로 스크롤 없이 통과

text
<!-- 실제 Chrome 결과 -->
1920px 컨테이너 max-width none
1920px Grid display flex
480px documentWidth 480, clientWidth 465

피드백:
보고서의 전 구간 통과 주장과 실제 최종 HEAD 계산값이 다릅니다. 완료 문구를 먼저 적기보다 각 너비에서 Computed의 max-width·display와 scrollWidth·clientWidth를 기록하고 그 값으로 최종 검증 결과를 결정해야 합니다.

CSS를 8개 역할로 분리하고 1024px 3열, 768px 2열 전환이 실제로 동작하도록 구성한 점은 좋았습니다. HTML 콘텐츠와 접근성 속성도 그대로 유지했습니다.

다만 데스크톱 기본 Grid와 컨테이너 토큰 오류가 남았고 body 최소 폭을 480px로 바꾼 방식은 480px 실측에서 여전히 가로 스크롤을 만듭니다. 보고서의 통과 결과도 이 실제 상태와 일치하지 않습니다.

빠르게 보완하려면 body 최소 폭을 완전히 제거하고, --container 철자를 고친 뒤, product-grid의 display:flex를 제거하면서 repeat(5, 1fr)를 적용하세요. 기본 데스크톱을 먼저 고치면 기존 미디어쿼리 전환도 자연스럽게 이어집니다.

반응형 검증은 화면 표시만 보지 말고 각 너비에서 .con의 max-width, .grid-5의 display와 columns, 문서 scrollWidth를 표로 남겨 보세요. 같은 값과 화면을 PR에 연결하면 보고서와 실제 코드가 달라지는 문제를 줄일 수 있습니다.
