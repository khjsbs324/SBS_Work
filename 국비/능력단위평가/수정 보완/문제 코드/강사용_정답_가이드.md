# 강사용 정답 가이드 (CSS 분리 · 오류 수정 실습)

> 평가 종료 전 비공개. 학생에게는 `index.html`, `css/style.css`, `정답.png`만 제공한다.

## 실습 목표

1. `css/style.css` 한 파일에 뒤섞여 있는 스타일을 "정답 코드" 폴더와 동일하게
   `normal.css / root.css / component.css / btn_cpn.css / item_cpn.css / layout_cpn.css / style.css / media.css`
   8개 파일로 분리하고 `index.html`의 `<link>`를 다시 연결한다.
2. 아래 3곳의 오답 코드를 찾아 `정답.png`와 동일한 레이아웃이 되도록 수정한다.

## 의도적 결함 3곳

| 결함 ID | 위치(선택자) | 오답 코드 | 증상 | 정답 코드 |
|---|---|---|---|---|
| BUG-01 | `.con` | `max-width: var(--containner);` (오타, 미정의 변수) | `max-width`가 `none`으로 무효 처리되어 헤더·섹션 콘텐츠가 가운데 정렬되지 않고 화면 전체 폭으로 늘어남 | `max-width: var(--container);` |
| BUG-02 | `.grid-5` | `grid-template-columns: repeat(5 1fr);` (콤마 누락) | 값이 무효 처리되어 BEST PICKS 상품 목록이 5단 그리드가 아닌 1단으로 세로로 쌓임 | `grid-template-columns: repeat(5, 1fr);` |
| BUG-03 | `body` | `min-width: 1600px;` (불필요한 최소 너비, flex와 무관) | 화면을 1600px보다 좁게 줄이면(태블릿·모바일 포함) `body`가 줄어들지 않아 전 구간에서 가로 스크롤이 발생함. 미디어쿼리 자체는 정상 동작하므로 "반응형 클래스는 바뀌는데 화면은 안 줄어드는" 혼란스러운 증상으로 나타남 | `min-width` 선언 삭제(또는 관련 규칙 자체를 제거) |

## 채점 포인트

- 파일 분리: 8개 파일에 규칙이 논리적으로 배치되어 있는지(색상·타이포 변수 → root.css, 버튼/아이콘 → btn_cpn.css 등), `index.html`의 `<link>` 순서가 정답 코드와 동일한 캐스케이드 순서를 유지하는지 확인한다.
- 결함 수정: 세 곳 모두 `정답.png`와 시각적으로 일치해야 통과. 특히 BUG-01은 뷰포트 폭이 1600px보다 넓을 때(예: 1920px) 좌우 여백 대칭 여부로 확인하는 것이 가장 명확하다.
- 진단 힌트:
  - BUG-01/02: 개발자 도구 Elements > Computed 탭에서 `max-width`가 `none`으로, `grid-template-columns`가 무효로 표시되는지 확인하도록 지도한다.
  - BUG-03: 브라우저 창을 1600px보다 좁게 줄였을 때 하단에 가로 스크롤바가 생기는지로 바로 확인 가능하다. 학생이 원인을 못 찾으면 Elements 패널에서 `<body>`를 선택해 Computed 탭의 `min-width` 값을 확인하도록 지도한다. flex 관련 속성(`flex`, `flex-basis`, `flex-shrink` 등)이 원인이 아님을 먼저 배제시키는 것이 이 문제의 핵심이다.
