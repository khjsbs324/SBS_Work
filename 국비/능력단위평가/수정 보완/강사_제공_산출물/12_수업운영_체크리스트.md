# 수업 운영 체크리스트

## 수업 전

- [ ] 과제 HTML이 열리고 CSS·JS·이미지 상대 경로가 정상이다.
- [ ] GitHub 저장소, 브랜치 규칙, Pull Request 권한이 준비되었다.
- [ ] 테스트 계정은 가상 데이터만 사용한다.
- [ ] 요구사항, 스타일 가이드, 스토리보드의 버전이 일치한다.
- [ ] 의도적 결함과 정답표가 학생 배포 파일에서 제외되었다.
- [ ] 브라우저와 보조기술 환경을 확인했다.
- [ ] 제출 폴더·파일명·마감 시각을 공지했다.

## 수업 중

- [ ] 학생이 리뷰 전 원본 버전을 기록했다.
- [ ] 역할과 검토 책임을 분담했다.
- [ ] 결함에 요구사항 근거와 증빙을 연결했다.
- [ ] 우선순위 결정 이유를 토론했다.
- [ ] JavaScript 테스트는 제공된 정적 교육 사이트에서만 수행한다.
- [ ] 실제 개인정보, 이메일, 개인 액세스 토큰을 기록하지 않는다.
- [ ] 폼이 실제 네트워크 전송을 하지 않는지 확인한다.

## 수업 후

- [ ] 제출 파일 수와 필수 항목을 확인했다.
- [ ] GitHub 저장소·PR·Pages URL이 열리는지 확인했다.
- [ ] 우선순위 `상` 결함의 수정·재검증 여부를 확인했다.
- [ ] 문서 간 결함 ID와 요구사항 ID가 일치한다.
- [ ] 평가 루브릭에 따라 점수와 근거를 기록했다.
- [ ] 개인별·팀별 피드백을 분리해 제공했다.
- [ ] 예시 파일과 평가 결과를 보존 정책에 따라 정리했다.
