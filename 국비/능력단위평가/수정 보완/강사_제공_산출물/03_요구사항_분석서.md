# 요구사항 분석서

## 사용자 과업

| 사용자 | 과업 | 주요 위험 | 성공 기준 |
|---|---|---|---|
| 모바일 사용자 | 메뉴를 열어 강좌로 이동 | 겹침·메뉴 미닫힘 | 360px에서 전 링크 사용 |
| 키보드 사용자 | 메뉴·탭·모달·폼 조작 | 포커스 손실 | Tab/Enter/Space/Escape로 완료 |
| 학습자 | 강좌 진도 체크 | 새로고침 후 상태 소실 | 비민감 진도만 복원 가능 |
| 문의 작성자 | 폼 입력 오류 수정 | 오류 위치 불명확 | 첫 오류 이동·해결 안내 |
| 협업자 | 변경 검토·배포 | 충돌·누락·경로 오류 | PR과 Pages에서 확인 가능 |

## 인수 조건

### FUN-001 모바일 메뉴

- Given: 화면 너비가 360px이고 메뉴가 닫혀 있다.
- When: 메뉴 버튼을 누른다.
- Then: 메뉴가 열리고 `aria-expanded="true"`가 되며 첫 메뉴 링크로 이동할 수 있다.
- When: Escape를 누른다.
- Then: 메뉴가 닫히고 메뉴 버튼으로 포커스가 돌아온다.

### FUN-003/004 문의 폼

- 빈 이름 또는 잘못된 이메일은 제출되지 않고 필드별 메시지를 표시한다.
- 정상 예시 입력은 네트워크 전송 없이 성공 데모를 표시한다.
- 실제 개인정보를 입력하지 말라는 안내가 폼 시작 부분에 있다.

### GH-004 GitHub Pages

- 저장소 하위 경로에서도 CSS, JS, 이미지가 로드된다.
- 대소문자가 다른 파일 참조가 없고 내부 링크가 404를 만들지 않는다.
- 배포 페이지에서 콘솔 오류가 없다.
