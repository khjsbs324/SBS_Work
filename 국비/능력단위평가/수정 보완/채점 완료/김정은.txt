## 사이트 입력용 피드백

1. 컨테이너 CSS 변수명

css
/* 학생 코드 */
.con {
  max-width: var(--containner);
}

css
/* 정답 코드 */
.con {
  max-width: var(--container);
}

피드백:
component.css에는 --container가 선언되어 있지만 layout_cpn.css에서는 --containner를 사용하고 있습니다. 정의되지 않은 변수를 참조해 max-width가 무효가 되고, Chrome 실측에서도 1920px에서 계산값이 none으로 확인되었습니다. 변수명을 선언부와 정확히 맞추면 1600px 최대 폭과 중앙 여백이 적용됩니다.

2. BEST PICKS 5열 Grid

css
/* 학생 코드 */
.grid-5 {
  display: grid;
  grid-template-columns: repeat(5 1fr);
}
.product-grid { display: flex; }

css
/* 정답 코드 */
.grid-5 {
  display: grid;
  grid-template-columns: repeat(5, 1fr);
}
.product-grid { margin-top: var(--num4); }

피드백:
repeat()의 두 인수 사이에 쉼표가 없어 5열 선언이 무효이며, product-grid의 display:flex가 Grid를 다시 덮어씁니다. 실제 계산값도 데스크톱에서 display:flex와 columns:none으로 나타났습니다. 임시 Flex 우회를 제거하고 유효한 Grid 문법을 적용해야 미디어쿼리의 3열·2열도 이어서 동작합니다.

3. body 고정 최소 폭

css
/* 학생 코드 */
body {
  min-width: 1600px;
}

css
/* 정답 코드 */
body {
  word-break: keep-all;
}

피드백:
body의 1600px 최소 폭 때문에 1024px·768px·480px에서 문서 폭이 모두 1600px로 유지되었습니다. 이 선언을 제거해야 뷰포트가 실제 화면 너비까지 줄고 반응형 규칙이 정상 적용됩니다.

피드백:
결함 분석 문서는 구체적이지만 여섯 테스트가 모두 자리표시자로 남았고 실제 Pull Request도 없습니다. 다섯 너비의 캡처, Network와 Console 결과, 변경 이유를 PR에 연결해야 재검증과 협업 기록을 확인할 수 있습니다.

CSS 파일 8개를 모두 만들고 로드 순서를 맞췄으며, HTML 콘텐츠와 기존 접근성 속성을 보존한 점은 좋았습니다. 특히 보고서에서 세 핵심 오류가 남아 있다는 사실을 숨기지 않고 정리한 태도도 좋습니다.

다만 분석한 --container 오타, repeat() 쉼표, body 최소 폭 수정이 최종 코드에 적용되지 않았습니다. 그 결과 컨테이너 최대 폭, 5열 Grid, 작은 화면의 가로 스크롤이 동시에 완성되지 않았습니다.

빠르게 보완하려면 먼저 body의 min-width를 제거하고, 다음으로 변수명을 --container로 맞춘 뒤, 마지막으로 product-grid의 Flex 우회를 지우고 repeat(5, 1fr)를 적용하세요. 한 건씩 새로고침하면 원인과 결과를 분리해서 확인할 수 있습니다.

재사용할 때는 데스크톱 5열을 먼저 완성한 후 1024px 3열, 768px과 480px 2열 순서로 확인하세요. 각 너비에서 documentElement.scrollWidth와 clientWidth가 같은지 기록하고 Network·Console 캡처를 PR에 함께 남기면 검증 정확도가 높아집니다.

오류를 찾고 설명하는 능력과 CSS 역할 분리 방향은 잘 잡았습니다. 다음에는 보고서에 적은 수정안을 최종 HEAD 코드와 실제 화면까지 일치시키면 완성도가 크게 올라갑니다. 고생하셨습니다^^
