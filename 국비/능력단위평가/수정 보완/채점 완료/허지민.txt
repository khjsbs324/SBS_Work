## 사이트 입력용 피드백

1. 컨테이너 변수명

css
/* 학생 코드 */
.con {
  max-width: var(--containner);
}

css
/* 정답 코드 */
.con {
  max-width: var(--container);
}

피드백:
보고서에는 오타 수정 완료라고 적혀 있지만 최종 layout_cpn.css는 여전히 --containner를 사용합니다. 실제 1920px 계산값도 max-width:none이므로 component.css에 선언된 --container와 사용명을 맞춰야 합니다.

2. Grid를 Flex로 바꾼 상태

css
/* 학생 코드 */
.grid-5 {
  /* display: grid; */
  display: flex;
  grid-template-columns: repeat(5 1fr);
}

css
/* 정답 코드 */
.grid-5 {
  display: grid;
  grid-template-columns: repeat(5, 1fr);
}

피드백:
Grid를 주석 처리하고 Flex로 바꿔 데스크톱에서 상품이 가로로 보이게 했지만 media.css의 3열·2열 규칙과 연결되지 않습니다. 실제 계산값도 display:flex와 columns:none입니다. 유효한 repeat() 문법과 display:grid를 함께 복구해야 합니다.

3. body 최소 폭

css
/* 학생 코드 */
body {
  min-width: 1600px;
}

css
/* 정답 코드 */
body {
  word-break: keep-all;
}

피드백:
normal.css에 1600px 최소 폭이 남아 있어 1024px·768px·480px에서 문서가 화면에 맞춰 줄지 않습니다. 이 선언을 제거한 뒤 각 너비에서 scrollWidth와 clientWidth가 같은지 확인해야 합니다.

4. 키보드 포커스

css
/* 학생 코드 */
button {
  outline: none;
}

css
/* 정답 코드 예 */
button:focus-visible,
a:focus-visible {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}

피드백:
기본 outline을 제거했지만 키보드 사용자를 위한 대체 focus-visible 스타일이 없습니다. 링크와 버튼을 Tab으로 이동했을 때 현재 위치를 볼 수 있도록 명확한 포커스 표시를 제공해야 접근성과 사용성이 유지됩니다.

피드백:
테스트 표가 미완성이고 실제 PR이 없으며 커밋 메시지만으로 변경 내용을 구분하기 어렵습니다. 실패를 포함한 실제 결과를 먼저 기록하고 목적 중심 커밋과 PR로 연결해야 분석·재검증 과정을 추적할 수 있습니다.

8개 CSS 파일을 만들고 세 결함의 원인을 보고서에서 정확히 설명했으며 HTML 콘텐츠와 이미지 대체텍스트를 보존한 점은 좋았습니다. 문제를 찾는 이론적 방향은 맞았습니다.

다만 수정 완료라고 기록한 세 사항이 최종 HEAD에는 반영되지 않았고 Grid를 Flex로 우회했습니다. body 고정 폭 때문에 모바일 화면이 잘리며 대체 포커스 없이 outline도 제거되어 있습니다.

빠르게 보완하려면 --container 철자, repeat(5, 1fr), display:grid, body 최소 폭 제거를 한 번에 묶지 말고 한 건씩 수정하세요. 각 단계에서 Computed 값과 화면 폭을 확인하면 어디서 문제가 풀렸는지 알 수 있습니다.
