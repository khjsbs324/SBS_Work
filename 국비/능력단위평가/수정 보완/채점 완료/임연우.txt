## 사이트 입력용 피드백

1. 컨테이너 수정 위치

css
/* 학생 코드 */
.con {
  max-width: var(--containner);
}
@media screen and (max-width: 1920px) {
  .con { max-width: var(--container); }
}

css
/* 정답 코드 */
.con {
  max-width: var(--container);
}

피드백:
media.css에서 올바른 변수를 다시 선언해 현재 1920px 계산값은 1600px으로 보완됐습니다. 그러나 원래 결함은 layout_cpn.css에 그대로 있고 모든 화면에 적용할 기본 규칙을 미디어쿼리로 우회했습니다. 원인 위치의 철자를 직접 고치면 불필요한 덮어쓰기 없이 같은 결과를 얻을 수 있습니다.

2. BEST PICKS Grid

css
/* 학생 코드 */
.grid-5 {
  grid-template-columns: repeat(5 1fr);
}
.product-grid {
  display: flex;
}

css
/* 정답 코드 */
.grid-5 {
  display: grid;
  grid-template-columns: repeat(5, 1fr);
}
.product-grid { margin-top: var(--num4); }

피드백:
상품을 가로로 놓기 위해 Flex를 사용했지만 과제의 핵심은 유효한 5열 Grid와 미디어쿼리 열 전환입니다. 실제 계산값이 데스크톱에서 display:flex와 columns:none이므로 쉼표를 추가하고 Flex 우회를 제거해야 합니다.

3. body 최소 폭

css
/* 학생 코드 */
body {
  min-width: 1600px;
}

css
/* 정답 코드 */
body {
  word-break: keep-all;
}

피드백:
보고서에서는 삭제 또는 auto 적용을 제안했지만 최종 normal.css에는 1600px 최소 폭이 남았습니다. Chrome에서 1024px·768px·480px 모두 documentWidth가 1600px으로 확인되므로 원인 선언을 완전히 제거해야 합니다.

4. 테스트와 PR 증빙

text
<!-- 학생 제출 기록 -->
1024px, 768px 결과 [통과/실패]
Pull Request .../pulls

text
<!-- 정답 제출 형태 -->
각 너비의 확정 결과와 실제 캡처 링크
.../pull/번호 형태의 실제 PR 주소

피드백:
두 테스트 결과가 미정 상태이고 /pulls는 PR 목록 주소일 뿐 제출한 Pull Request가 아닙니다. 실제 계산값과 캡처로 통과·실패를 확정하고 변경 목적과 검증 결과가 있는 개별 PR을 제출해야 합니다.

8개 CSS 파일을 모두 만들고 세 결함의 원인을 보고서에서 구체적으로 설명했습니다. 컨테이너 문제를 media.css로 보완해 1920px에서 실제 1600px 중앙 정렬을 만든 시도도 확인됩니다.

다만 원인 위치의 변수 오타는 남아 있고, Grid는 Flex로 우회했으며 body 최소 폭도 제거되지 않았습니다. 그래서 1600px 이하 네 화면에서 가로 스크롤과 잘림이 계속 발생합니다.

빠르게 보완하려면 layout_cpn.css의 변수명을 먼저 고쳐 media.css 우회를 지우고, Grid 쉼표와 display를 바로잡은 뒤 body 최소 폭을 제거하세요. 근본 선언을 한 곳씩 수정하면 캐스케이드가 단순해집니다.
