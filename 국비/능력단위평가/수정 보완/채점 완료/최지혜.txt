## 사이트 입력용 피드백

1. component.css 첫 주석 문법

css
/* 학생 코드 */
* ------ 지역 디자인 토큰 ------ */
:root {
  --container: var(--GW-XL);
}

css
/* 정답 코드 */
/* ------ 지역 디자인 토큰 ------ */
:root {
  --container: var(--GW-XL);
}

피드백:
파일 첫 줄에 주석 시작 기호의 슬래시가 빠져 브라우저가 component.css를 유효한 규칙으로 파싱하지 못합니다. CSSOM 검사에서도 이 파일의 규칙 수가 0으로 확인됐습니다. 첫 줄을 올바른 주석으로 바꿔야 --container를 포함한 의미 토큰들이 선언됩니다.

2. 파일명 오타

html
<!-- 학생 코드 -->
<link rel="stylesheet" href="./css/nomar.css">
<link rel="stylesheet" href="./css/layuit_cpn.css">

html
<!-- 정답 코드 -->
<link rel="stylesheet" href="./css/normal.css">
<link rel="stylesheet" href="./css/layout_cpn.css">

피드백:
현재 링크와 실제 파일명은 서로 맞아 요청 자체는 성공하지만 수업 기준 파일명 normal.css와 layout_cpn.css에 오타가 있습니다. 보고서에서도 오타를 알고 있었으므로 파일과 링크를 함께 표준 이름으로 변경해야 유지보수와 자동 검사가 안정적입니다.

3. 컨테이너와 Grid

css
/* 학생 코드 */
.con { max-width: var(--containner); }
.grid-5 { grid-template-columns: repeat(5 1fr); }
.product-grid { display: flex; }

css
/* 정답 코드 */
.con { max-width: var(--container); }
.grid-5 {
  display: grid;
  grid-template-columns: repeat(5, 1fr);
}

피드백:
변수 오타, repeat() 쉼표 누락, Flex 덮어쓰기가 함께 남아 있습니다. 실제 1920px에서 max-width는 none, 상품 목록은 Flex와 columns:none으로 계산됩니다. 세 선언을 원인 위치에서 바로잡아야 최대 폭과 5열 Grid가 정상화됩니다.

4. body 고정 최소 폭

css
/* 학생 코드 */
body {
  min-width: 1600px;
}

css
/* 정답 코드 */
body {
  word-break: keep-all;
}

피드백:
nomar.css에 1600px 최소 폭이 남아 있어 1024px·768px·480px에서도 문서 폭이 1600px입니다. 이 선언을 제거해야 모바일 화면이 뷰포트 안으로 줄어들고 미디어쿼리 열 수도 실제로 확인할 수 있습니다.

5. 중복 style.css와 미완성 증빙

html
<!-- 학생 코드 -->
<link rel="stylesheet" href="./css/style.css">
<link rel="stylesheet" href="./css/media.css">
<link rel="stylesheet" href="./css/style.css">

text
<!-- 정답 제출 형태 -->
style.css는 한 번만 연결
5개 너비 테스트에 실제 결과와 캡처 링크 작성

피드백:
style.css가 media.css 뒤에서 다시 연결되어 반응형 캐스케이드를 흐릴 수 있고, 테스트 표는 모두 [통과/실패]와 [링크] 상태입니다. 중복 링크를 제거한 뒤 실제 화면과 계산값으로 결과를 확정해야 합니다.

8개 파일 구조를 만들고 세 핵심 오류의 원인을 보고서에서 정확히 설명하려 한 점은 좋았습니다. HTML 콘텐츠와 이미지 대체텍스트도 그대로 보존했습니다.

다만 component.css의 첫 주석 문법 때문에 의미 토큰 전체가 파싱되지 않으며, 핵심 결함 3건과 파일명 오타·중복 링크가 최종 코드에 남았습니다. 보고서의 수정 완료 설명과 실제 HEAD가 일치하지 않습니다.

빠르게 보완하려면 component.css 주석부터 고쳐 토큰을 복구하고, 파일명 두 개와 링크를 함께 정리하세요. 이후 body 최소 폭, --container, repeat(5, 1fr), Flex 우회 순서로 수정하면 화면 변화가 명확합니다.

재사용할 때는 Network의 성공 여부만 보지 말고 document.styleSheets의 규칙 수와 Computed 값도 함께 확인하세요. 파일이 200으로 로드돼도 이번 component.css처럼 내부 파싱 오류로 규칙이 0개일 수 있으므로 Console·CSSOM·화면을 함께 보는 습관이 중요합니다.
