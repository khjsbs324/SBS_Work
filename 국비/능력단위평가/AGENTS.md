# 국비 작업공간 에이전트 지침

## 목적

이 작업공간은 HTML, CSS, JavaScript, Git, GitHub 범위의 NCS 평가 업무를 다음 두 흐름으로 수행한다.

1. **능력단위평가 코딩 문제 제작**: NCS 원문, 문제 코드, 정답 코드 및 예시 자료를 근거로 강사용·학생용 평가자료를 제작하고 검증한다.
2. **채점 및 피드백**: 학생 저장소를 수행준거별로 채점하고, 학생별 결과 파일을 만든 뒤 SBS아카데미 평가 사이트에 점수와 피드백을 등록하고 저장 결과를 확인한다.

강사용 정답과 학생용 안내를 분리하며, 원본 자료·코드·채점 결과·사이트 등록 결과의 추적성을 유지한다.

## 필수 스킬과 기준 파일

- PDF 분석, 시험 출제, 산출물 생성, 채점기준 작성, 학생 코드 채점 또는 사이트 등록 검증에는 `skills/ncs-exam-production/SKILL.md`를 사용한다.
- 자료 우선순위와 출력 위치는 `skills/ncs-exam-production/references/project-map.md`를 따른다.
- 채점 방법과 학생별 출력 형식은 `피드백.md`를 기준으로 한다.
- 사용자의 최신 지시가 기존 문서와 충돌하면 최신 지시를 우선하되, 충돌 사실과 적용한 판단을 기록한다.

## A. 능력단위평가 코딩 문제 제작

기존 `문제 코드`, `정답`, PDF, 강사용·학생용 산출물 관련 작업은 모두 이 업무에 속한다.

### 제작 절차

1. 편집 전에 현재 파일 구조, `AGENTS.md`, 관련 NCS 원본, `문제 코드`, `정답`을 확인한다.
2. `문제 코드`를 학생 시작 코드, `정답`을 강사용 구현 기준으로 삼아 파일과 동작을 함께 비교한다.
3. 해당 능력단위 수행준거를 문제 요구사항과 일대일로 연결한다.
4. 수행준거마다 확인할 증빙과 구체적인 4단계 점수 구간을 작성한다. 수행준거를 임의로 합치거나 나누지 않는다.
5. 사용자가 다른 총점을 지정하지 않으면 문항별 배점은 정수, 합계는 100점으로 한다.
6. 강사용 정답과 학생용 안내를 분리하고 학생용 자료에 정답을 노출하지 않는다.
7. 최종 전달 자료는 `최종 결과 산출물`에 간결하게 정리한다. 요청 없이 중복 산출물 폴더를 만들지 않는다.
8. 실제 문제를 사이트에 등록하거나 수정할 때는 허가된 항목만 변경한다. 저장 후 제목, 설명, 정답, 채점기준, 사용 설정, 수행준거 수 및 총점을 상세 화면에서 확인한다.

### 제작 범위와 품질

- 별도 지시가 없으면 HTML, CSS, JavaScript, Git, GitHub만 사용한다.
- 백엔드, 데이터베이스, 서버, 프레임워크 또는 실제 인증 요구사항을 임의 추가하지 않는다.
- `문제 출제 예시.pdf`와 비슷한 상세 수준으로 작성하되, 현재 문제 코드와 정답을 우선한다.
- 관련 없는 파일을 보존하고 한글 UTF-8, 경로, 링크, 총점, 코드 연결 순서와 학생용·강사용 분리를 검증한다.

## B. 채점 및 피드백 파이프라인

### 트리거

사용자가 **`채점 진행해줘`**라고 입력하면 채점 파이프라인을 시작한다.

1. 트리거를 받으면 같은 메시지에 다른 정보가 있더라도 먼저 `채점할 능력단위명을 입력해주세요.`라고 묻고 사용자의 다음 답을 기다린다.
2. 사용자가 능력단위명을 입력하면 이후 모든 파일 탐색, `Exam.md`, 학생별 결과 및 사이트 등록에 그 문자열을 기준 능력단위명으로 사용한다.
3. 다음 답의 능력단위명이 모호하거나 서로 다른 이름의 자료가 여러 개면 추측하지 말고 정확한 이름을 다시 확인한다.

### 필수 입력

능력단위명을 받은 뒤 다음 파일을 확인한다.

- `피드백.md`
- `<능력단위명> 수행준거.txt`
- `평가_리포지터리_주소.txt`

하나라도 없으면 임의 대체하지 않는다. 찾은 파일과 누락 파일을 보고하고, 안전하게 진행할 수 있는 부분만 수행한다.

### 1단계: `Exam.md` 재작성

1. `피드백.md`의 증빙 중심 채점 원칙과 출력 형식을 읽는다.
2. `<능력단위명> 수행준거.txt`의 수행준거 원문, 순서, 개수를 고정한다.
3. 기존 `Exam.md`가 있더라도 현재 능력단위 기준으로 전체를 재작성한다. 문서 첫머리에 능력단위명과 사용한 근거 파일을 기록한다.
4. 수행준거 1개당 채점 문항 1개를 만든다. 문항 수를 임의로 늘리거나 줄이지 않는다.
5. 사용자가 다른 총점을 지정하지 않으면 정수 배점 합계를 100점으로 만든다.
6. 각 문항에 직접 증빙, 과제에 맞춘 구체적인 4단계 점수 구간, 감점 기준, 브라우저 확인 방법을 작성한다.
7. `평가_리포지터리_주소.txt`에서 평가 대상 학생명, 저장소 URL과 리포지터리 이름의 매핑을 추출해 `Exam.md`에 포함한다.
8. `피드백.md`의 학생별 최종 출력 형식과 최종 품질 검증 항목을 `Exam.md`에 포함한다.
9. 수행준거 수, 문항 수, 학생 수, 4단계 구간, 총점 100점, UTF-8을 확인한 뒤에만 학생 채점으로 이동한다.

### 2단계: 학생 저장소 채점

1. `평가_리포지터리_주소.txt`에서 `[학생 이름]`과 바로 아래 저장소 URL을 한 쌍으로 읽는다.
2. 저장소 URL의 리포지터리 이름과 학생 이름의 연결을 채점 및 사이트 매칭의 기준으로 보존한다.
3. 각 저장소의 기본 브랜치와 채점한 커밋 해시를 기록하고 학생 코드를 수정하지 않는다.
4. 소스 구조, HTML·CSS·JavaScript 정확성, 웹표준, 시맨틱 구조, 접근성, 불필요한 코드, 반응형 화면, 필수 상호작용, 콘솔·네트워크 오류, README와 Git 기록을 확인한다.
5. `Exam.md`의 문항 순서와 4단계 기준으로 절대평가 원점수를 계산한다. 다른 학생의 순위만으로 점수를 만들지 않는다.
6. 원점수는 0~100점으로 보존하고 실제 평가·사이트 등록 총점은 `ROUND(60 + (원점수 × 0.4), 0)`으로 계산해 정수만 사용한다. 따라서 원점수 0점은 등록점수 60점, 원점수 100점은 등록점수 100점이다.
7. 문항별 이상적 환산값은 `문항 배점 × 0.6 + 문항 원점수 × 0.4`로 계산하되 소수는 중간 계산에만 사용한다. 모든 이상적 환산값을 내림한 다음, 전체 정수 등록총점과의 차이만큼 소수 나머지가 큰 문항부터 1점씩 배분한다. 나머지가 같으면 문항 ID가 앞선 문항을 우선하며, 이 최대잔여법으로 모든 문항 등록점수를 정수로 만든다.
8. 문항별 정수 등록점수의 합계는 전체 정수 등록총점과 같아야 하며 각 문항 만점을 초과할 수 없다.
9. 모든 점수에는 파일, 선택자, 화면 너비, 동작, 커밋 또는 캡처 중 하나 이상의 직접 근거를 연결한다.
10. 모든 학생에게 코드 피드백과 화면 피드백을 작성한다. 화면을 열지 못했으면 피드백을 생략하지 말고 원인과 필요한 재검토 자료를 적는다.
11. 사이트 입력용 피드백은 주요 결함 3~7개를 선정해 `학생 코드 → 최소 정답 코드 → 구체적인 피드백` 순서로 작성한다. 코드 앞에는 `html`, `css`, `javascript`, `text` 언어명만 한 줄로 쓰고 사이트에 문자로 보이는 Markdown 백틱은 넣지 않는다. 이어서 완성 영역, 미완성 영역, 빠른 구현 순서, 응용·재검증 방법, 전체 정리와 격려의 5개 문단을 작성한다.
12. **학생이 보는 사이트 입력용 피드백에는 원점수, 등록점수, 총점, 60~100점 환산 범위·공식·과정, 통과 여부, 순위 또는 내부 채점 판단을 적지 않는다.** 점수 정보는 내부 결과표와 사이트 점수 입력란에만 보존한다. 마지막 종합 문단은 개선 방향과 격려로만 마무리한다.
13. 비교 코드에는 해당 결함에 필요한 최소 줄만 사용한다. 강사용 정답 파일 전체를 학생 피드백에 노출하지 않는다.
14. 저장소 접근 실패, 기본 브랜치 부재, 실행 불가 또는 필수 증빙 누락은 학생별로 구분하여 기록하고 추측으로 원점수를 채우지 않는다.

### 3단계: 학생별 결과 파일 생성

1. `채점 완료` 폴더가 없으면 생성한다.
2. 학생마다 `채점 완료/<학생 이름>.txt`를 UTF-8로 생성한다.
3. 각 파일에는 다음을 포함한다.
   - 능력단위명, 학생 이름, 저장소 URL·리포지터리 이름·커밋 해시
   - 문항별 배점, 원점수, 등록점수, 직접 증빙과 판단 근거
   - 원점수 합계, 60~100점 환산 등록점수와 통과 여부
   - 잘한 점, 우선 수정 사항, 화면 피드백, 재제출 체크리스트
   - 주요 결함별 학생 코드·최소 정답 코드 비교와 5개 종합 문단으로 구성된 사이트 입력용 피드백
   - 평가 보류 항목과 사유
   - 사이트 등록 상태와 저장 확인 시각
4. 학생 수, 저장소 수, 생성된 결과 파일 수가 일치하는지 확인한다.
5. 사이트 등록 전에 모든 학생 파일의 문항별 원점수 합계와 원점수 총점, 문항별 등록점수 합계와 환산 등록점수가 각각 일치하는지 다시 계산한다.

### 4단계: SBS아카데미 평가 사이트 등록

로컬 채점 결과가 완성되고 검증된 학생만 다음 주소에 등록한다.

`https://sbsartdj.maniaro.net/teacher/ver4/curri/appraisal/app/appraisal.php?Pcode=300002&Lcode=8&AppCode=AH`

자동화 제어가 가능한 브라우저에서 학생별로 다음 순서를 지킨다.

1. 페이지가 로그인된 강사 계정인지, 현재 평가의 능력단위명이 `Exam.md`와 일치하는지 확인한다.
2. `평가_리포지터리_주소.txt`의 학생 이름과 리포지터리 이름을 이용해 해당 학생을 찾는다.
3. 같은 이름이 여러 명이거나 리포지터리와 학생 매칭이 불명확하면 등록하지 않고 사용자에게 확인한다.
4. 해당 학생의 **채점하기**를 클릭한다.
5. **평가점수 일괄등록**을 클릭한다.
6. 사이트의 수행준거 문구를 `Exam.md`와 대조한 뒤 문항별 **등록점수**를 입력한다. 화면 순서만 믿지 말고 수행준거 문구로 매칭한다.
7. 입력한 문항별 등록점수의 합계가 학생 결과 파일의 환산 등록점수와 같은지 확인한다.
8. **`이곳에 피드백을 입력하세요.`** 입력란에 학생 결과 파일의 코드 비교형 피드백 전체를 작성한다. 결함별 학생 코드·최소 정답 코드·피드백과 5개 종합 문단을 포함하되 내부 강사용 정답 전체와 원점수·등록점수·총점·환산 방식·통과 여부는 넣지 않는다.
9. 최종 **채점하기**를 클릭한다.
10. 저장 완료 후 다시 열린 상세 화면에서 학생명, 문항별 등록점수, 환산 총점, 피드백이 로컬 결과 파일과 같은지 확인한다.
11. 확인 시각과 등록 성공 여부를 `채점 완료/<학생 이름>.txt`에 기록한다.

`채점 진행해줘` 트리거는 위 학생 목록의 검증된 점수와 피드백을 등록하는 권한으로 본다. 다만 기존 등록값이 비어 있지 않고 새 결과와 다르거나, 수행준거 수·총점·학생 매칭이 다르면 덮어쓰지 말고 사용자에게 보고한다.

### 중단 및 재개 기준

- 로그인 필요, 권한 없음, 비공개 저장소 접근 불가, 학생 매칭 불명확, 사이트 수행준거 불일치 또는 기존 점수 충돌 시 해당 학생의 등록을 중단한다.
- 막힌 학생의 점수를 추측하거나 다른 학생 행에 대신 등록하지 않는다.
- 다른 학생이 명확히 구분되면 계속 진행하고, 완료·보류·실패 학생을 마지막에 각각 보고한다.
- 등록 도중 오류가 나면 마지막으로 저장 검증이 끝난 학생부터 재개하며 이미 확인된 학생을 중복 등록하지 않는다.

## 완료 검증

- `Exam.md`의 능력단위명, 수행준거 수, 문항 수와 총점이 원본 수행준거 파일과 일치한다.
- 모든 저장소가 학생 이름과 연결되고 채점 커밋이 기록되었다.
- 모든 학생에게 문항별 점수, 총점, 직접 증빙, 코드 피드백과 화면 피드백이 있다.
- 모든 학생의 사이트 피드백이 주요 결함별 코드 비교와 5개 종합 문단 형식을 충족한다.
- 모든 학생의 사이트 피드백에 원점수, 등록점수, 총점, 환산 방식, 통과 여부 또는 순위가 노출되지 않는다.
- `채점 완료`의 학생 파일 수가 평가 대상 학생 수와 같다.
- 사이트에 등록한 학생명, 문항별 점수, 총점과 피드백이 로컬 결과와 같다.
- 한글 인코딩, 경로, 링크 및 관련 파일 존재 여부를 확인했다.
