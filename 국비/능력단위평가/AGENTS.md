# 능력단위평가 공통 에이전트 지침

## 목적과 폴더 원칙

이 폴더는 NCS 능력단위평가의 문제 제작, 채점, 피드백 및 결과 관리를 위한 공통 작업공간이다.

- 루트에는 모든 평가에 공통인 지침, 스킬, 출제 예시, 학생 저장소 목록과 피드백 기준만 둔다.
- 평가별 하위 폴더에는 해당 평가의 NCS 원본, 수행준거, 문제·정답 코드, `Exam.md`, 시험지, 산출물과 채점 결과를 둔다.
- 서로 다른 평가의 원본, 코드, 정답과 채점 결과를 섞지 않는다.
- 평가별 지침이 필요하면 공통 문서를 해당 평가 폴더로 복제한 뒤 그 복제본만 구체화한다.

## 적용 우선순위

1. 사용자의 최신 지시
2. 선택한 평가 폴더의 `AGENTS.md`, `CLAUDE.md`, `피드백.md`
3. 선택한 평가의 NCS 원본과 수행준거
4. 선택한 평가의 문제 코드와 정답
5. 루트 공통 지침과 `skills/ncs-exam-production/`
6. `문제 출제 예시.pdf` 등 참고 자료

충돌이 있으면 상위 항목을 우선하고 판단을 결과에 기록한다.

## 작업 시작 절차

1. 사용자가 지정한 능력단위명과 일치하는 하위 폴더를 확정한다.
2. 이름이 모호하거나 후보가 여러 개면 추측하지 말고 확인한다.
3. 해당 평가 폴더의 구조와 전용 지침을 먼저 읽는다.
4. PDF 분석, 시험 출제, 채점 또는 사이트 등록에는 `skills/ncs-exam-production/SKILL.md`를 사용한다.
5. 선택하지 않은 다른 평가 폴더는 수정하지 않는다.

## 문제 제작 공통 원칙

- 수행준거 원문, 순서와 개수를 보존하고 요구사항 및 채점 문항과 일대일로 연결한다.
- 수행준거마다 직접 증빙과 구체적인 4단계 점수 구간을 작성한다.
- 별도 지시가 없으면 문항별 배점은 정수이며 합계는 100점이다.
- 학생 시작 코드와 강사용 정답을 분리하고 학생용 자료에 정답을 노출하지 않는다.
- 같은 평가 폴더의 코드와 원본만 기준으로 사용한다.
- 요구되지 않은 백엔드, 데이터베이스, 서버, 프레임워크 또는 배포 조건을 추가하지 않는다.
- 한글 UTF-8, 상대 경로, 내부 링크, 파일 존재 여부와 코드 연결 순서를 검증한다.

## 채점 트리거와 입력

사용자가 `채점 진행해줘`라고 입력하면 먼저 `채점할 능력단위명을 입력해주세요.`라고 묻고 다음 답을 기다린다.

능력단위명이 확정되면 다음 자료를 확인한다.

- 해당 평가 폴더의 수행준거 파일
- 해당 평가 폴더의 `Exam.md` 또는 시험 제작 자료
- 루트 또는 평가 폴더의 `피드백.md`
- 루트 또는 평가 폴더의 `평가_리포지터리_주소.txt`

필수 자료가 없으면 다른 평가 자료로 대체하지 말고 누락 항목을 보고한다.

## 채점 공통 원칙

1. 학생명, 저장소 URL, 리포지터리명, 기본 브랜치와 채점 커밋을 기록한다.
2. 학생 저장소는 읽기 전용으로 검토하고 학생 코드를 수정하거나 push하지 않는다.
3. 수행준거별 직접 증빙을 수집하고 `Exam.md`의 기준으로 절대평가한다.
4. 확인하지 못한 동작은 통과로 추정하지 않고 보류 사유를 기록한다.
5. 동일한 결함을 여러 문항에서 중복 감점하지 않는다.
6. 모든 학생에게 코드 피드백과 화면 피드백을 작성한다.
7. 학생 공개용 피드백에는 내부 점수 산식, 순위 또는 강사용 정답 전체를 노출하지 않는다.
8. 결과는 해당 평가 폴더의 `채점 완료/<학생 이름>.txt`에 저장한다.

평가별 규칙이 없으면 다음 공통 환산식을 사용한다.

```text
등록총점 = ROUND(60 + (원점수 × 0.4), 0)
문항별 이상적 등록점수 = 문항 배점 × 0.6 + 문항 원점수 × 0.4
```

문항별 점수는 이상적 등록점수를 내림한 뒤 최대잔여법으로 배분하며 합계가 등록총점과 같아야 한다.

## 사이트 등록 안전 원칙

- 로컬 결과가 완성되고 검증된 학생만 등록한다.
- 사이트 과정명, 능력단위명, 수행준거와 학생명을 로컬 자료와 대조한다.
- 학생 매칭, 수행준거 수, 기존 점수 또는 권한이 불명확하면 저장하지 않는다.
- 입력 후 상세 화면에서 학생명, 문항별 점수, 총점과 피드백을 다시 확인한다.
- 확인 시각과 결과를 해당 평가의 학생별 결과 파일에 기록한다.

## 완료 검증

- 선택한 능력단위명과 작업한 하위 폴더가 일치한다.
- 수행준거 수와 문항 수가 일치하고 배점 합계가 정확하다.
- 모든 점수에 직접 증빙 또는 미확인 사유가 있다.
- 학생 수, 저장소 수와 결과 파일 수가 일치한다.
- 학생용과 강사용 자료가 분리되어 있다.
- 다른 능력단위평가의 자료가 변경되지 않았다.
- 한글 인코딩, 경로, 링크와 파일 존재 여부를 확인했다.

## 검토 역할

- NCS 원문 및 수행준거 추적성: `.agents/ncs-source-analyst.md`
- 프론트엔드 문제·정답 및 학생 코드: `.agents/frontend-exam-reviewer.md`
- 산출물, 총점, 피드백 및 등록 결과: `.agents/assessment-qa-reviewer.md`

최종 판단과 외부 사이트 등록 책임은 주 에이전트가 맡는다.

## `문제 등록` 트리거

사용자가 `문제 등록`이라고 요청하면 아래 파이프라인을 실행한다.

- 요청에 능력단위명이 있으면 정확히 일치하는 하위 폴더를 선택한다.
- 능력단위명이 없으면 현재 작업 폴더명 또는 대화에서 마지막으로 확정된 능력단위명을 사용한다.
- 능력단위명을 확정할 수 없거나 후보가 여러 개면 `등록할 능력단위명을 입력해주세요.`라고 묻는다.
- 다른 능력단위의 자료를 섞거나 비슷한 이름을 임의로 선택하지 않는다.

## 문제 등록 파이프라인

### 1. 등록 자료 확정

선택한 능력단위 폴더에서 다음 자료를 순서대로 확인한다.

1. 전용 `AGENTS.md`, `CLAUDE.md`, `피드백.md`
2. 수행준거 원문 파일
3. `Exam.md`
4. 학생용 과제안내서와 제출 양식
5. 강사용 정답·채점표
6. NCS 원본 PDF 또는 요약 문서

위 자료에서 문제명, 설명, 정답 또는 제출물 기준, 학생 공개용 채점기준, 능력단위요소별 수행준거, 수행준거별 배점, 업로드·링크 기능 사용 여부를 정리한다. `Exam.md`가 있으면 배점과 판단 기준은 이를 우선하며 별도 지시가 없으면 총점은 100점으로 맞춘다.

### 2. 사이트 대상 검증

교사용 사이트에서 과정명, 교과목, 능력단위명, 평가도구와 평가 회차를 로컬 자료와 대조한다. 능력단위명이 다르거나 동일 이름의 후보가 여러 개면 등록하지 않는다.

### 3. 등록 화면 진입

기본 이동 순서는 다음과 같다.

```text
능력단위평가
→ 관련 능력단위 행의 평가내역
→ 전체점수 옆 평가도구 탭
→ 평가문제등록
→ 문제등록
```

평가도구 탭은 포트폴리오, 구두발표 등 해당 능력단위 설정과 일치해야 한다.

### 4. 평가기준 설정

등록 화면 위쪽 `평가기준` 영역에서는 다음만 수행한다.

1. 모든 능력단위요소를 차례로 선택한다.
2. 각 능력단위요소의 수행준거를 전부 선택한다.
3. `추가하기`로 모든 수행준거를 등록한다.
4. `Exam.md`와 대응하는 배점을 입력한다.

평가기준 작성 시 다음을 반드시 지킨다.

- 수행준거는 NCS 원문이므로 수정·요약·재작성하지 않는다.
- 수행준거 선택 시 자동 입력된 문구를 상세 루브릭으로 교체하지 않는다.
- 수행준거의 원래 순서와 개수를 보존한다.
- 등록 전에 배점 합계가 정확히 100점인지 계산한다.

### 5. 문제등록 영역 작성

화면 아래쪽 `문제등록` 영역은 다음처럼 작성한다.

- `문제`: 학생이 알아볼 수 있는 능력단위 평가명
- `설명`: 과제 목표, 작업 순서와 필수 조건
- `정답`: 제출물 목록, 파일명·형식과 필수 작성 내용
- `채점기준`: 학생에게 공개 가능한 상세 점수 기준

학생 공개용 `채점기준`은 다음 규칙을 따른다.

- `DC-01`, `DC-12` 같은 내부 관리 코드를 넣지 않는다.
- `증빙:`, 내부 판정 메모, 자동화 과정이나 도구 사용 흔적을 넣지 않는다.
- 제목은 `기본 스타일가이드 요소 분석 — 8점`처럼 자연어로 작성하고 굵게 표시한다.
- 제목 아래에는 최고점부터 최저점까지 구체적인 4단계 점수 구간을 작성한다.
- 학생이 제출물에서 무엇을 보여주어야 하는지 이해할 수 있게 작성한다.
- 정답 이미지 복제보다 설계의도, 대상 사용자, 브랜드, 리서치, 와이어프레임, 스타일가이드와 결과물의 연결을 평가한다.
- 같은 문제를 여러 항목에서 반복 감점하지 않는다고 안내한다.
- 총점 제목도 굵게 표시한다.

### 6. 기능 설정과 저장

- 파일 제출이 필요하면 업로드 기능을 `사용`으로 설정한다.
- 출처나 배포 URL 제출이 필요하면 링크 기능을 `사용`으로 설정한다.
- 동일한 문제가 이미 있으면 중복 등록하지 말고 `수정하기`로 갱신한다.
- 내용, 수행준거 수와 배점 합계를 확인한 뒤 `등록하기` 또는 `수정하기`를 실행한다.

### 7. 저장 후 상세 검증

성공 메시지만으로 완료 처리하지 않는다. 상세정보를 열어 다음을 확인한다.

- 문제명이 정확하다.
- 설명·정답·채점기준이 각 입력란에 올바르게 저장됐다.
- 평가기준의 수행준거 원문이 변형되지 않았다.
- 모든 능력단위요소와 수행준거가 포함됐다.
- 수행준거별 배점과 총점이 맞고 `100 / 100`이 표시된다.
- 학생용 채점기준에 내부 코드와 `증빙:` 표기가 없다.
- 모든 채점 항목 제목과 총점 제목이 굵게 표시된다.
- 업로드·링크 설정이 의도와 일치한다.
- 같은 문제가 중복 등록되지 않았다.

검증에 실패하면 저장된 문항의 `수정하기`로 들어가 잘못된 입력란만 고친 뒤 다시 검증한다.

## 문제 등록 수정 안전 규칙

- `채점기준` 수정 요청을 `평가기준` 수정으로 해석하지 않는다.
- 데이터 길이 오류가 발생해도 평가기준을 축약하거나 덮어쓰지 않는다. 입력 위치가 맞는지 먼저 확인한다.
- 기존 문제 수정 중 오류가 발생하면 상세정보에서 기존 데이터가 보존됐는지 확인한 뒤 재시도한다.
- 완료 보고에는 능력단위명, 문제명, 수행준거 수, 총점, 기능 설정, 평가기준 원문 보존, 학생용 채점기준 서식과 상세정보 재검증 결과를 포함한다.
