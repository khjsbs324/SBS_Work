# AI 기획과 발상 비NCS 실기평가 피드백 지침

상위 공통 피드백 원칙을 따르며, 이 평가에서는 학생의 자기 근거, AI 활용 과정, 선택·수정 판단과 사이트 적용의 연결을 중심으로 작성한다.

## 학생 공개 피드백 구성

1. 잘된 점: 자기 근거·프롬프트·대안·화면에서 직접 확인한 강점 1~2개
2. 보완할 점: 브랜드 신뢰도나 사이트 전달력에 가장 큰 영향을 주는 문제 1~2개
3. 다음 행동: 다음 제작 단계에서 바로 실행할 구체적인 수정 1~2개

페이지·프레임·프롬프트 번호·생성안 번호·수정 버전을 근거로 적는다. 내부 문항 ID, 문항별 원점수 계산과 강사용 판단 메모는 학생 공개 피드백에 쓰지 않는다.

## 권장 표현

- “자기분석의 실제 프로젝트 사례가 슬로건과 프로젝트 분류까지 이어져 브랜드 근거가 분명합니다.”
- “프롬프트 P-03은 목표 사용자와 금지 조건이 추가되면서 결과 차이를 확인할 수 있습니다.”
- “Firefly 생성안의 손·문자 오류를 직접 보정하고 이미지 사용 영역을 제한한 판단이 적절합니다.”
- “참고 사이트와 메뉴 이름뿐 아니라 섹션 순서와 시각 모티프도 달리해 본인의 작업 흐름을 보여 주세요.”

피할 표현:

- “AI를 잘 썼다”처럼 목적·프롬프트·판단 근거가 없는 표현
- “감각이 없다”, “촌스럽다”처럼 취향이나 인격을 평가하는 표현
- AI가 만든 문구·이미지를 학생의 직접 창작이라고 단정하는 표현
- 외부 자산의 권리 상태를 확인하지 않고 사용 가능하다고 보증하는 표현

## 중점 피드백

### 자기분석과 브랜드 방향

- 성향 형용사가 실제 경험·행동·작업물로 입증되는지 본다.
- 목표 사용자가 사이트에서 확인할 정보와 학생이 전달할 인상이 연결되는지 본다.
- 슬로건이 과장된 약속이 아니라 실제 강점과 작업 방식을 설명하는지 본다.

### ChatGPT와 Firefly 활용

- 첫 결과를 그대로 사용하지 않고 맥락·제약·비교 기준을 추가해 발전시켰는지 본다.
- AI 출력, 학생 선택, 직접 수정과 최종 결과를 구분했는지 본다.
- 생성 이미지의 오류·유사성·사용 맥락을 검토하고 필요한 후편집을 했는지 본다.

### 포트폴리오 사이트 적용

- 브랜드가 장식에 머물지 않고 정보구조·카피·프로젝트 분류와 화면 위계에 적용됐는지 본다.
- 참고 사이트를 복제하지 않고 본인의 작업물과 목표에 맞게 재구성했는지 본다.
- 공개하지 않아야 할 개인정보와 확인되지 않은 경력·자격이 제거됐는지 본다.

## 점수와 피드백 일치

- 높은 성취: 실제 사이트 구현 단계에서 검증할 반응형·접근성·콘텐츠 위험을 제시한다.
- 중간 성취: 이미 확보된 브랜드 자원과 가장 큰 연결 공백을 함께 적는다.
- 낮은 성취: 자기 근거 3개, 대안 3개, 핵심 화면 1개처럼 먼저 완성할 최소 단위를 제시한다.
- 미확인 자료: 링크 접근 불가·생성 기록 누락·원본 누락 범위와 재제출 조건을 구체적으로 기록한다.
