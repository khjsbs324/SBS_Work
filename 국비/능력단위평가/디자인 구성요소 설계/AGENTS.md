# 디자인 구성요소 설계 평가 지침

## 평가 목적

이 폴더의 능력단위는 `디자인 구성요소 설계(0802010415_23v3)`이다. 학생이 개인 브랜딩 포트폴리오 사이트의 정보를 구조화하고 스토리보드·와이어프레임, 디자인 가이드, 사용성을 고려한 UI 구성요소와 디바이스별 표준을 설계하는 전 과정을 평가한다.

## 원문 범위

- 원본: `디자인 구성요소 설계(LM0802010415_23v3)` PDF, 75쪽.
- PDF 평가 준거의 학습목표 12개를 `DS-01`~`DS-12`로 연결한다. DS 번호는 내부 추적 ID이며 공식 NCS 수행준거 번호가 아니다.
- PDF 15쪽 내용체계의 `0802010415_23v3.4` 요소명은 `매체성 구성요소 설계하기`로 표기되어 있지만, 학습 4 제목과 평가 문맥은 `매체별 구성요소 설계하기`를 사용한다. 원문 표기 차이를 숨기지 않고 `pdf요약결과.md`에 기록한다.

## 평가 조건

- 개인평가, 240분, 포트폴리오 방식으로 진행한다.
- 학생의 개인 브랜딩·포트폴리오 콘텐츠 또는 강사가 제공한 브랜드 브리프 중 한 건을 입력 자료로 사용한다.
- 필수 제출은 `이름_디자인구성요소설계.pdf` 1개와 `이름_디자인구성요소설계_원본.zip` 1개다.
- PDF에는 프로젝트 요소 목록, 정보구조·사이트맵·사용자 흐름, 와이어프레임, 트렌드 분석, 디자인 가이드, UI 구성요소 상태, 디바이스별 사양과 점검 결과가 판독 가능해야 한다.
- ZIP에는 편집 가능한 설계 소스와 사용한 자산을 포함한다.
- 설계 능력단위이므로 HTML·CSS·JavaScript 구현, 배포, 백엔드를 필수로 요구하지 않는다.

## 판단 원칙

- 시각적 화려함보다 프로젝트 목표→정보구조→와이어프레임→디자인 가이드→UI 상태→디바이스 규칙의 추적성을 우선한다.
- 와이어프레임은 시각 시안이 아니라 정보 위계, 흐름, 레이아웃과 기능을 판단하는 설계 증빙으로 본다.
- 트렌드는 단순히 최신 표현을 따라 했는지가 아니라 서비스 성격·사용자·콘텐츠에 맞는 전략으로 선택했는지 판단한다.
- 사용성은 정상 상태만이 아니라 포커스, 선택, 오류, 비활성, 로딩, 빈 상태와 복구 흐름을 함께 본다.
- 디바이스별 설계는 크기 축소가 아니라 정보 우선순위, 입력 방식, 탐색, 터치 영역과 브레이크포인트 적응을 판단한다.
- 취향 차이만으로 감점하지 않고 학생이 작성한 의도와 실제 설계물을 대조한다.

## 채점과 검증

- `Exam.md`의 `DS-01`~`DS-12`를 사용하며 총점은 100점이다.
- 모든 점수는 PDF 페이지·절·프레임 ID, 설계 소스 또는 점검 기록 중 하나 이상의 직접 증빙에 연결한다.
- 같은 원인을 여러 문항에서 중복 감점하지 않는다.
- 원문 12문장, 수행준거 TXT 12개, Exam 12문항과 영역별 25점, 총 100점을 대조한다.
- 개인평가 240분, PDF 1개·원본 ZIP 1개 조건이 모든 문서에 일치하는지 확인한다.
