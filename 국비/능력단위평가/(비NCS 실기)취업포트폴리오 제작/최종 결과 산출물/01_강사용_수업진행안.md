# 강사용 수업진행안

## 1. 평가 개요

| 항목 | 내용 |
|---|---|
| 평가 구분 | 비NCS 실기평가·기관 자체 기준 |
| 교과목 | 취업포트폴리오 제작 |
| 시험 문제 | 웹디자인 과정에서 제작한 모든 프로젝트를 정리하여 취업용 포트폴리오를 제출해 주세요. |
| 평가 방식 | 개인 실기 및 포트폴리오 평가 |
| 평가 시간 | 300분 |
| 필수 제출 | 통합 PDF, 편집 원본 또는 공유 링크, 프로젝트별 결과물·링크 |
| 문항·총점 | 10문항, 100점 |

## 2. 평가 목표

학생이 과정 중 제작한 웹디자인 프로젝트를 누락 없이 정리하고, 프로젝트의 목적·타깃·본인 역할·과정·결과를 취업 관점에서 설명할 수 있는지 평가한다. 취업 목표에 맞는 콘셉트와 스타일 가이드, 무드보드, 정보구조, 와이어프레임과 주요 화면 시안을 통합하고 ChatGPT 활용 결과를 사실에 맞게 편집한 뒤 전체 결과물을 검수·보완하는 능력도 확인한다.

## 3. 평가 전 준비

- [ ] 과정 중 필수 제출 프로젝트의 정확한 목록과 명칭을 확정한다.
- [ ] 팀 프로젝트는 학생별 역할과 직접 제작 범위를 사전에 확인할 수 있게 한다.
- [ ] 학생에게 기존 프로젝트 파일·링크·이미지를 평가 전에 준비하도록 안내한다.
- [ ] 디자인 원본, PDF 내보내기, 링크 확인 환경을 점검한다.
- [ ] ChatGPT 프롬프트와 수정 결과를 기록할 템플릿을 배포한다.
- [ ] 개인정보·비공개 고객자료·확인되지 않은 성과를 공개하지 않도록 안내한다.
- [ ] 네트워크 장애 시 제출할 로컬 결과 파일을 준비하게 한다.

| 프로젝트 분석·콘셉트 | 40분 | 목적·타깃·역할·문제·취업 목표·방향 정리 | 설명과 콘셉트에 근거가 있는가 |
| 스타일 가이드·무드보드 | 45분 | 컬러·서체·그리드·이미지·요소와 시각 방향 | 실제 프로젝트에 적용 가능한가 |
| 정보구조·와이어프레임 | 45분 | 분류·순서·콘텐츠 위계·주요 화면 흐름 | 채용 관점의 탐색이 쉬운가 |

| ChatGPT 활용·문구 보완 | 25분 | 아이디어·문구·구조 검토와 사실 기반 수정 | AI 출력과 학생 편집이 구분되는가 |
| 전체 QA·수정 | 30분 | 일관성·가독성·오탈자·이미지·링크·권한 점검 | 발견 문제와 수정이 연결되는가 |
| 최종 패키지 | 15분 | PDF·원본·결과물·목록·버전 정리 | 제출물과 권한을 확인했는가 |
| 합계 | 300분 |  |  |

## 5. 진행 중 관찰 포인트

- 강사 확정 목록과 학생 인벤토리가 일치하는가.
- 프로젝트별 목적·타깃·문제와 본인 역할이 결과 화면에 연결되는가.
- 대표 프로젝트의 노출 우선순위가 취업 목표에 맞는가.
- 스타일 가이드가 프로젝트마다 실제로 반복 적용되는가.
- 무드보드의 원리가 와이어프레임·최종 시안으로 이어지는가.
- ChatGPT 문구에 과장된 역할·성과·수치가 없는가.
- 프로젝트 이미지 해상도, 오탈자, 링크와 접근 권한을 직접 점검하는가.

## 6. 강사 개입 범위

허용:

- 확정 프로젝트 목록, 평가 범위, 시간과 제출 규칙 안내
- 도구의 일반 기능, 파일명과 링크 권한 문제 안내
- 개인정보·팀 역할·사실 확인과 출처 기록 방법 안내

금지:

- 학생 대신 대표 프로젝트·콘셉트·레이아웃을 선택하는 행위
- 특정 포트폴리오 스타일이나 문구를 정답으로 지시하는 행위
- 팀 결과를 학생 개인 역할로 작성하거나 실제 없는 성과를 만들어 주는 행위

## 7. 회수와 채점 순서

1. 강사 확정 목록과 학생 인벤토리·PDF·원본·결과물 링크를 대조한다.
2. 프로젝트별 목적·타깃·문제·역할·과정·결과 설명을 확인한다.
3. 취업 목표·대표 프로젝트·콘셉트·편집 원칙을 확인한다.
4. 스타일 가이드·무드보드와 실제 화면 적용을 대조한다.
5. 정보구조·와이어프레임·시안의 흐름과 위계를 확인한다.
6. ChatGPT 프롬프트·응답·학생 수정과 적용 위치를 확인한다.
7. QA 기록과 수정 전후, 파일·링크·권한·버전을 확인한다.
8. `Exam.md`의 PF-01~PF-10에 직접 증빙 위치와 점수를 기록한다.

## 8. 미확인 처리

- 링크 권한 문제와 프로젝트 자체의 미제출을 구분한다.
- 팀 프로젝트의 역할을 확인할 수 없으면 확인 가능한 개인 기여만 판단한다.
- 외부 사이트가 중단되어도 로컬 결과 파일·캡처·원본으로 결과를 확인할 수 있으면 인정한다.
- 미확인 자료를 추측하여 인정하거나 자동 0점 처리하지 않는다.
