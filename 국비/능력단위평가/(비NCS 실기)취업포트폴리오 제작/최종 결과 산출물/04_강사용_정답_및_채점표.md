# 강사용 정답 및 채점표

## 1. 정답의 성격

이 과제에는 하나의 고정된 포트폴리오 디자인 정답이 없다. 다음 연결이 직접 증빙으로 성립해야 한다.

`확정 프로젝트 목록 → 인벤토리·결과물 → 프로젝트 분석·본인 역할 → 취업 목표·콘셉트 → 무드보드·스타일 가이드 → 정보구조·와이어프레임 → 주요 화면 시안 → ChatGPT 검토·수정 → QA·최종 패키지`

작품 수와 장식의 화려함보다 전체 제출 완전성, 학생 역할의 정확성, 채용 관점의 전달력과 통합 디자인의 일관성을 평가한다.

## 2. 등록용 정답 문구

프로젝트별 목적·타깃·담당 역할과 제작 과정을 정리하고, 브랜드 콘셉트·컬러·타이포그래피·레이아웃이 포함된 스타일 가이드, 무드보드, 와이어프레임, 주요 화면 시안, 최종 결과물 링크 또는 파일, ChatGPT 활용 기록 및 디자인 검토·수정 결과를 일관된 형식으로 구성한 취업용 웹디자인 포트폴리오.

## 3. 접수 확인

- [ ] 강사가 확정한 제출 대상 프로젝트 목록이 있다.
- [ ] 학생 인벤토리와 전체 프로젝트 수·명칭이 일치한다.
- [ ] 통합 PDF와 편집 원본 또는 공유 링크를 열 수 있다.
- [ ] 프로젝트별 결과물 파일·URL을 열 수 있다.
- [ ] 팀 프로젝트의 학생 역할을 확인할 수 있다.
- [ ] ChatGPT 기록, QA·수정 전후와 최종 제출 목록이 있다.

## 4. 직접 증빙 확인 순서

1. 확정 목록과 학생 인벤토리·PDF 목차·원본·결과물 경로를 대조한다.
2. 프로젝트별 목적·타깃·문제·본인 역할·과정·결과를 확인한다.
3. 취업 목표·대표 프로젝트·콘셉트·편집 원칙을 확인한다.
4. 무드보드·스타일 가이드와 실제 화면 적용을 대조한다.
5. 정보구조·프로젝트 순서·와이어프레임과 주요 화면 흐름을 확인한다.
6. 실제 콘텐츠를 사용한 메인·프로필·목록·상세 시안을 확인한다.
7. ChatGPT 프롬프트·응답·사실 확인·학생 수정·적용 위치를 확인한다.
8. QA 문제·수정 전후·재확인과 PDF·원본·파일·링크·권한을 확인한다.

## 6. 경계 사례

- 대표 프로젝트만 잘 정리됐더라도 확정 목록의 다른 프로젝트가 누락되면 전체 제출 완전성에서 판단한다.
- 외부 사이트가 중단됐지만 로컬 파일·캡처·원본으로 결과를 확인할 수 있으면 제출로 인정한다.
- 팀 프로젝트의 결과가 훌륭해도 학생의 역할과 직접 제작 범위를 확인할 수 없으면 개인 성취로 모두 인정하지 않는다.
- 스타일 가이드가 상세해도 실제 주요 화면에 적용되지 않으면 높은 수준으로 보지 않는다.
- 기존 프로젝트 화면을 그대로 나열한 경우 통합 정보구조와 취업용 편집의 성취를 별도로 확인한다.
- ChatGPT를 사용하지 않은 항목은 직접 작성·검토 근거가 있으면 불이익을 주지 않는다. 단, 평가계획에 따라 최소 한 번의 적절한 활용 기록은 확인한다.
- 신규 코딩·배포 결과가 있어도 통합 기획·시안·QA 증빙이 없는 항목 점수를 자동으로 높이지 않는다.

## 7. 중복 감점 방지

- 링크 권한 문제 하나가 여러 프로젝트 확인을 막으면 접근 장애와 영향 범위를 별도로 기록하고 같은 사유를 반복 기재하지 않는다.
- 역할 설명 누락이 소개 문구와 상세 페이지에 반복되어도 주된 프로젝트 분석 항목에서 처리하고 ChatGPT 항목은 사실 검토 여부를 본다.
- 스타일 규칙 하나의 불일치가 여러 화면에 반복되면 가이드 적용의 주된 항목에서 처리한다.
- 보고서 미관 자체는 평가하지 않는다. 가독성 때문에 직접 증빙을 확인할 수 없는 범위만 기록한다.

## 8. 최종 확인

- [ ] 강사 확정 목록과 학생 제출 프로젝트 수를 대조했다.
- [ ] 10개 항목 모두 PDF·원본·프로젝트 결과물의 직접 증빙 위치가 있다.
- [ ] 팀 결과와 학생 개인 역할을 구분했다.
- [ ] 모든 결과물 링크와 파일을 직접 열어 보았다.
- [ ] 같은 원인을 반복 감점하지 않았다.
- [ ] 학생 공개 피드백에 내부 ID와 점수 계산을 노출하지 않았다.
