# 서비스ㆍ경험디자인 관찰조사 평가 지침

## 현재 작업 범위와 근거

- 사용자 승인에 따라 원본 분석, 평가 설계, 학생·강사용 자료 제작 및 로컬 검증까지 진행한다.
- 기존 `AGTENS.md`는 초기 요청을 기록한 원본으로 보존한다. 그 문서의 “체크리스트 한 개만 제작” 범위는 이번 승인으로 확장되었다. 현재 운영 지침은 이 `AGENTS.md`를 적용한다.
- 모든 산출물과 검증 자료는 이 평가 폴더 안에 저장한다.
- 상위 공통 지침과 `../skills/ncs-exam-production/SKILL.md`를 적용하되 평가 대상·제출물·증빙은 아래 전용 조건을 우선한다.
- 기존 브랜딩·와이어프레임·스타일가이드·디지털디자인 사후관리 결과는 학생 프로젝트의 배경 자료로 참고할 수 있다. 다른 평가의 문항, 점수, 결함과 제출 요건을 가져오지 않는다.

## 평가 조건

- 기존 브랜딩 프로젝트를 바탕으로 학생이 구상한 가상 서비스 한 건을 다룬다.
- 개인평가, 180분, AI를 활용한 점검·보완을 허용한다.
- 학생은 서비스를 자세히 설명하고 조사 근거, 사용자 유형과 요구, 관찰 설계, 가상 이용 시나리오, 디자인 전략, AI 제안에 대한 판단, 수정과 재확인을 작성한다.
- 필수 제출은 작성 완료한 체크리스트를 변환한 PDF 한 개다. 편집용 Markdown, 소스 코드, 웹사이트 배포, 백업 서식 10종은 필수로 요구하지 않는다.
- 체크리스트의 필수 최소량은 과제 안내 기준이다. 빈칸 개수, 문서 길이, AI 대화량만으로 별도 점수를 부여하거나 감점하지 않는다. 다른 위치에 동등한 증빙이 있으면 인정한다.

## 원문과 평가의 관계

- 원본: `서비스ㆍ경험디자인 관찰 조사.pdf`, 95쪽, 학습모듈 `LM0802010613_17v3`.
- PDF의 평가 준거에 수록된 학습목표 12개를 `SO-01`~`SO-12`로 연결한다. SO 번호는 내부 추적 ID이며 공식 NCS 수행준거 번호가 아니다.
- 원문의 문장·순서·개수는 수행준거 TXT에 보존한다. 각 문장에 문항 1개를 연결하고 `Exam.md`의 총점 100점 및 4단계 기준을 적용한다.
- PDF에 별도 공식 수행준거 번호표가 없으므로 사이트 등록 단계에서 공시된 요소·수행준거 원문과 대조한다. 불일치 시 학습목표를 공식 수행준거인 것처럼 덮어쓰지 않고 대응과 배점을 재검토한다.

## 가상 관찰과 직접 증빙

- `[프로젝트]`, `[조사]`, `[가설]`, `[AI 제안]`을 구분한다. 실제 조사 자료를 인용하면 출처와 확인한 내용을 남긴다.
- 가상 서비스의 예상 행동·감정·반응은 가설로 표시한다. 실제 참여자, 발언, 빈도, 소요시간, 통계를 창작해 관찰 사실로 기록하지 않는다.
- 이번 평가는 모의 사례 기반의 관찰조사 설계·분석·개선 판단을 평가한다. 실제 현장 관찰 수행이나 사용자 효과 검증까지 확인했다고 단정하지 않는다.
- 가상 방식 자체나 실제 제3자 관찰 기록의 부재를 감점하지 않는다. 다만 출처 자료가 요구되는 문항에서 AI 답변 또는 근거 없는 가설만 제출한 경우 해당 자료 연결 요건은 충족하지 못한다.
- 잠재 요구는 행동 단서에서 도출한 해석임을 밝히고 대안 해석, 한계와 후속 확인 방법을 기록한다.
- 재확인은 수정된 문서·흐름·접점이 학생이 정한 조건을 충족하는지 확인하는 것이다. 실제 사용자 만족도 상승을 입증한 것으로 표현하지 않는다.

## 채점과 피드백

- PDF 페이지·절·기록 ID를 근거로 절대평가한다. 같은 원인에 대한 감점은 주된 문항 한 곳에서 처리하고 다른 문항에는 참조만 남긴다. 서로 다른 수행 누락은 독립 근거를 기록한다.
- 서비스 설명 부족은 별도 13번째 문항을 만들지 않고, 실제 판정을 방해한 해당 문항에만 반영한다.
- 웹·코드·브라우저 화면 피드백 대신 서비스 내용·문서의 정보 구조·PDF 가독성을 다룬다. 보기 좋은 편집 자체에 가산점을 부여하지 않는다.
- AI 사용 여부·모델·유료 서비스 이용 여부는 점수 기준이 아니다. 제안의 선택·수정·보류 근거와 서비스에 적용된 결과를 본다.
- 학생 공개용 피드백은 관찰 → 기준 → 판단 → 영향 → 구체적 개선 순서로 작성한다. 내부 SO 번호, 원점수·환산식·순위·강사용 판단표를 노출하지 않는다.
- 등록점수는 상위 공통 환산식과 최대잔여법으로 계산하고 원점수와 구분한다. PDF 열람 실패는 임의 0점 처리 대신 보류 사유를 남긴다.

## 향후 등록과 채점

- 이번 산출물 제작에는 사이트 등록이나 학생 채점이 포함되지 않는다. 관련 요청 시 로컬 자료를 기준으로 공통 파이프라인을 실행한다.
- 문제 등록: 과정·교과·능력단위·평가도구 대조 → 공식 수행준거 대응 확인 → 문제·설명·제출 기준·학생 공개용 채점기준 입력 → PDF 업로드 사용 → 상세 화면 재검증.
- 링크 기능은 별도 URL 제출을 받을 때만 사용한다. PDF 본문 출처 링크만으로 별도 링크 입력란을 필수화하지 않는다.
- 채점: 학생명·PDF 파일명·크기·SHA-256·수령일 확인 → PDF 증빙 검토 → 12문항 원점수와 판단 기록 → 환산·합계 검증 → 학생 피드백 → 요청 범위 내 등록·재검증.
- 저장소가 필수가 아니므로 PDF 제출을 채점하기 위해 GitHub 주소를 새로 요구하지 않는다.
- 실제 제출물을 받은 때 `채점 자료/<학생명>/`, 결과가 완성된 때 `채점 완료/<학생명>.txt`를 만든다. 빈 점수나 완료 상태를 미리 만들지 않는다.
