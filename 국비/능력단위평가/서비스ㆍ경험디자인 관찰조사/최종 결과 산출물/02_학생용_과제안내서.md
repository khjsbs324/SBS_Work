## 수행 내용

다음 순서로 체크리스트를 작성합니다. 짧은 문장과 기록 번호를 활용하고 같은 내용을 여러 번 길게 복사하지 않습니다.

| 순서 | 필수 작성 내용 |
|---|---|
| 1. 서비스 설명 | 대상·문제·제공 내용·이용 흐름·운영 방식·범위, 기존 브랜딩 근거 1건과 연결 원칙 |
| 2. 선행조사 | 직접 확인한 출처 2건, 그중 경쟁·유사 서비스 1건 이상. 사실과 해석, 서비스 개발방향·개념, 관찰할 의문 |
| 3. 사용자 분류 | 이용 상황·라이프스타일·인구학적 특성·가치관·동기·태도로 구분한 유형 2개와 예상 요구 |

| 5. 관찰설계 | 목적·대상·과업·환경·시점·방법·범위·기록 기준, 행동으로 확인할 질문 2개와 따로 물어볼 질문 1개 |
| 6. 가상 이용기록 | 이용 전·중·후 3단계의 행동·감정·접점·불편과 해석 |
| 7. 요구 해석 | 명시적 요구 가설 1개와 잠재 요구 가설 1개. 자료·행동 단서와 연결하고 카노 모델로 분류한 이유, 잠재 요구의 다른 해석과 후속 질문 |

출처 2건은 같은 페이지를 두 번 적는 방식으로 늘리지 않습니다. 경쟁 서비스의 공식 자료와 사용자·환경에 관한 문헌 등 서로 다른 자료를 활용합니다. 기존 조사 자료도 직접 다시 확인하면 사용할 수 있습니다.

사용자 유형은 가상으로 구성하되 라이프스타일·인구학적·소비심리학적 특성의 세 관점에는 실제 자료에서 확인한 내용과 위치를 연결합니다. 같은 자료를 여러 특성에 사용해도 됩니다. 자료를 자신의 가상 사용자에게 적용한 이유와 아직 알 수 없는 한계도 적습니다.

## 초보자를 위한 용어

| 용어 | 뜻 |
|---|---|
| 접점 | 사용자가 서비스를 만나는 화면·공간·안내·사람 등 |
| 사용자 여정 | 서비스를 알게 되기 전후부터 이용과 마무리까지의 과정 |
| 명시적 요구 가설 | 사용자가 직접 말할 수 있을 것으로 예상하는 요구 |
| 잠재 요구 가설 | 예상 행동이나 상황의 단서에서 해석한 숨은 요구 |
| 섀도잉 | 사용자 이동·이용 과정을 따라가며 관찰하는 방법 |
| 카노 모델 | 요구를 기본·성능·매력 등으로 나누어 만족과의 관계를 생각하는 틀 |

카노 모델에서는 없으면 불만이 생기는 필수 조건을 **기본 요구**, 충족 정도에 따라 만족이 달라지는 조건을 **성능 요구**, 예상하지 못한 추가 가치를 주는 조건을 **매력 요구**로 구분합니다. 이번에는 각 요구에 적합한 유형과 이유를 설명합니다. 정식 사용자 설문으로 분류가 확정되었다고 쓰지 않습니다.

수업에서 배운 다른 관련 이론을 사용해도 됩니다. 이론명·판단 기준과 자신의 요구에 적용한 이유를 적으면 됩니다.

## 근거와 가설의 구분

- **[프로젝트]**: 기존 자료와 직접 작성·수정·확인한 결과물의 내용. 자료명과 위치를 적습니다.
- **[조사]**: 직접 확인한 자료의 내용. 자료명·출처·주소·확인일을 적습니다.
- **[가설]**: 실제 사용자에게 확인하지 않은 유형·행동·발언·감정·요구·효과의 예상입니다.
- **[AI 제안]**: AI가 제시한 내용입니다. 채택 여부와 학생의 판단 이유를 적습니다.

이번 평가는 **조사설계와 가설 해석을 연습하는 모의 과제**입니다. 가상 기록은 실제 현장조사 실적을 뜻하지 않습니다. 관찰할 계획과 이번에 수행한 가상 검토를 구분하고, 실제 사용자를 만나지 않았다면 인터뷰·관찰을 한 것처럼 작성하지 않습니다. 출처에서 확인한 사실도 자신의 서비스 사용자에게 검증된 결과와는 구분합니다.

재확인은 수정한 문서·절차·화면 설명이 자신의 기준에 맞는지 다시 보는 과정입니다. 사용자 만족도·이탈률 개선 등 아직 측정하지 않은 결과는 가설로 남깁니다. 개인정보는 문서나 AI에 입력하지 않습니다.

## AI 활용과 수정

체크리스트에 있는 질문 틀에 자신의 서비스·자료 근거·가설·문제를 넣어 AI와 상의합니다. 두 제안 각각을 반영·수정 반영·보류·제외 중에서 판단하고 이유를 적습니다. 모든 제안을 채택하거나 일정 수를 억지로 거절할 필요는 없습니다.

제안을 그대로 붙여 넣는 것으로 끝내지 말고 자신의 서비스 설명·이용 절차·관찰계획·문구 등 **실제 본문 두 곳을 수정**합니다. 수정 전 상태를 기록에 남긴 뒤 수정 후 문장을 본문에 반영하고 다시 확인합니다. 전체 AI 대화나 외부 공유 링크 대신 질문과 답변의 핵심, 판단 이유가 PDF 안에 있으면 됩니다.

두 수정 중 적어도 하나는 잠재 요구를 해결하는 서비스 환경 개선에 직접 연결합니다. 바꾼 정보·절차·응대·공간·시간 등의 내용, 예상 효과·부작용과 확인 조건을 함께 기록합니다.

상세한 항목별 점수 기준은 [학생 공개용 채점기준](05_학생공개용_채점기준.md)을 확인합니다.

## 필수와 선택

표의 필수 내용을 먼저 완성합니다. 문장형 답변은 항목당 1~3문장을 권장하며 서비스 설명은 대상·상황·이유가 보이도록 구체적으로 적습니다. 정해진 페이지 수는 없으며 분량보다 작성 내용과 연결 관계를 확인합니다.

표와 같은 내용을 짧은 문단·도식으로 작성하거나 다른 절의 작성 위치를 연결해도 됩니다. 같은 내용을 다시 적을 필요는 없으며 표의 빈칸 수만으로 판단하지 않습니다. 최소 수량을 채우는 것만으로 평가가 결정되지 않고 근거와 설명의 연결을 함께 확인합니다.

추가 사용자·자료, SWOT 분석, 상세 여정도, 화면 목업, 추가 수정은 **선택**입니다. 코딩·개발·배포·GitHub 제출·실제 사용자 모집·새 화면 제작·유료 AI 사용은 요구하지 않습니다. 기존 자료의 필요한 내용은 PDF 안에 넣어 읽을 수 있게 하고 편집 원본은 개인 보관합니다.

확인할 내용은 사용자 분류와 요구의 근거, 경험과 디자인 전략의 연결, 자료에 근거한 관찰설계, 잠재 요구와 환경개선의 논리, 학생의 AI 판단과 수정·재확인 과정입니다. 같은 문제를 여러 항목에서 반복 감점하지 않습니다.
