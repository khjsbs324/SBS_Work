# 서비스ㆍ경험디자인 관찰조사 강사용 판단 기준 및 채점표

강사용 문서다. 학생에게는 별도 학생 공개용 채점기준을 제공한다.

## 모범 수행의 기준

학생이 복제해야 할 하나의 서비스나 완성 답안은 없다. 학생이 선택한 브랜드와 서비스에서 다음 관계가 증빙으로 이어지는지를 확인한다.

기존 브랜드·출처 자료 → 서비스 환경과 사용자 특성 → 사용자 유형·요구 → 관찰 질문과 설계 → 경험 기록과 잠재 요구 → 디자인 전략·요소 → AI 제안에 대한 판단 → 수정 전후·재확인·후속 조사.

출처 자료와 가상 시나리오를 섞지 않는다. 가설에서 도출한 잠재 요구가 설득력 있더라도 실제 관찰을 수행했다고 기록하지 않는다. 문서 재확인과 실제 사용자 효과 검증도 구분한다.

## 문항별 증빙 기록

아래 기록을 12문항 각각 작성한다. 점수표만 채우고 증빙을 생략하지 않는다.

| 항목 | 작성 내용 |
|---|---|
| 문항 ID | SO- |
| 직접 증빙 | PDF 페이지, 절, 기록 ID, 확인한 내용 |
| 기준 대조 | 적용한 점수 구간과 충족·미충족 요건 |
| 판단 | 구간 내 점수 선택 이유 |
| 중복 확인 | 같은 원인으로 다른 문항에서 이미 반영했는지, 참조할 문항 |
| 미확인 | 확인할 수 없는 이유와 추가로 필요한 자료 |

## 학생 체크리스트와 문항 연결

| 문항 | 주로 확인할 절 | 확인할 연결 |
|---|---|---|
| SO-01 | 1·3·5 | 서비스 상황 → 요구조건 |
| SO-02 | 3·5·6 | 경험요소 → 브랜드와 디자인 전략 |
| SO-03 | 2·3 | 자료 → 라이프스타일·인구학·소비심리 |
| SO-04 | 3 | 특성 요인 → 구별되는 유형 |
| SO-05 | 2·4 | 선행조사 → 구체적 관찰 설계 |
| SO-06 | 1·2 | 자료 시사점 → 개발 방향·범위 |
| SO-07 | 5 | 이론 기준 → 요구 분류와 해석 |
| SO-08 | 2·5 | 출처 자료 → 사용자 요구 |
| SO-09 | 1·2 | 경쟁사 비교 → 서비스 개념·차별 방향 |
| SO-10 | 3·6 | 사용자 성향 → 접점의 디자인 요소 |
| SO-11 | 4·5 | 경험 단서 → 잠재 요구·대안 해석·후속 질문 |
| SO-12 | 5~9 | 잠재 요구 → 문제·AI 판단·수정·효과 예측·재확인 |

절 번호는 편의를 위한 것이다. 동일 내용이 다른 절에 있어도 인정한다. 같은 자료를 여러 문항에서 사용하는 것과 같은 결함을 여러 번 감점하는 것은 구분한다.

## 혼동하기 쉬운 판단

- 가상 사용자 시나리오를 가설로 명시한 학생에게 실제 참여자 기록을 새로 요구하지 않는다. 실제 출처 자료를 요구하는 문항에서는 그 자료가 있는지를 별도로 판단한다.
- 사용자 특성 자료의 출처 누락을 SO-03에서 반영했다면 SO-04에서는 분류 자체의 논리를 본다. 자료 부족이라는 같은 이유를 반복하지 않는다.
- 자료 ID 하나가 빠졌어도 내용과 출처가 다른 절에서 명확하면 인정한다. ID 형식 자체는 별도 점수가 아니다.
- 문서의 가독성이 낮아 근거를 읽을 수 없으면 문제 위치와 영향을 기록한다. 장식이 적거나 페이지 수가 적다는 이유만으로 감점하지 않는다.
- AI 제안을 보류했어도 타당한 이유와 학생의 대안이 있으면 인정한다. 계획한 수정과 제출 PDF의 실제 내용이 이어지는지 본다.
- 명시적 요구를 잠재 요구로 잘못 분류한 경우 SO-11에서 판단한다. 이론 적용이나 개선의 논리에 독립된 문제가 없다면 같은 분류 오류를 다른 문항에서 반복하지 않는다.
- 환경 개선은 정보·동선·응대·절차·화면 등의 계획 변경으로 제시할 수 있다. 코드 구현이나 운영 중 효과 측정을 필수화하지 않는다.

## 결과 파일 구성

실제 채점 시 `채점 완료/<학생명>.txt`에 다음 구성을 사용한다. 빈 결과를 미리 만들지 않는다.

```text
[채점 기본 정보]
학생명 / 능력단위 / 과제명 / 채점일
제출 PDF 파일명 / 수령일 / 크기 / SHA-256
평가 형태: 가상 서비스 모의 사례 평가
실제 현장 관찰 수행 확인: 이번 과제의 검증 범위 밖
사이트 등록 상태: 실제 상태만 기록

[제출물 검증]
열람 가능 여부 / 페이지 수 / 서비스명 / 출처 및 가설 구분

[원점수 채점표]
SO-01~SO-12: 원점수/배점, PDF 페이지·절·기록 ID, 판단 근거

[점수 합계]
원점수 / 등록총점 / 문항별 등록점수 / 합계 검증

[학생 공개용 피드백]
관찰 사실, 기준 대조, 판단, 영향, 구체적 개선, 공개용 최종점수

[등록 검증]
등록을 실제 수행한 경우에만 과정·능력단위·학생·문항·점수·피드백 재확인 시각과 결과
```

## 완료 확인

- 12문항·배점 100점·영역별 32/40/28점이 일치한다.
- 문항별 증빙과 구간 내 점수 이유가 있다.
- 원점수와 등록점수를 구분하고 문항 합계가 맞는다.
- 가상 시나리오를 실제 조사 성과로 표현하지 않았다.
- 같은 결함을 반복 감점하지 않았다.
- 학생 공개 피드백에 내부 ID·원점수·환산식·순위·강사용 자료가 없다.
- 사이트 등록 전 공식 수행준거 대조가 필요한 상태를 정직하게 기록했다.
