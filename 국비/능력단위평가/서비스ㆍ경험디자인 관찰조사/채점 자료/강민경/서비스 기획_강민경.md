# 서비스ㆍ경험디자인 관찰조사 체크리스트

> 이 문서는 완성된 시험문제나 채점표가 아닌 기존 브랜딩 프로젝트를 바탕으로 가상의 서비스를 점검하고, 부족한 부분을 AI와 상의하여 보완하기 위한 학생용 작성 양식입니다.

## 0. 작성 안내

### 작업 목표

내가 기획한 서비스를 처음 보는 사람도 이해할 수 있도록 자세히 설명하고, 다음 과정을 한 문서 안에 기록합니다.

1. 서비스 초안과 브랜딩 자료를 확인합니다.
2. 사용자 유형과 요구를 구체화합니다.
3. 사용자 여정과 관찰조사 계획을 점검합니다.
4. 서비스의 부족한 부분을 찾아 우선순위를 정합니다.
5. AI와 상의하되 최종 판단은 직접 내립니다.
6. 수정 전·후와 재확인 결과를 기록합니다.
7. 작성이 끝난 체크리스트를 PDF로 변환하여 제출합니다.

### 판정 및 근거 표시

- 체크 항목이 충족되면 `[O]`, 미확인 또는 보완이 필요하면 `[ ]`로 표시합니다.
- 확인된 내용과 가상의 내용을 아래와 같이 구분합니다.
  - `[프로젝트]`: 기존 브랜딩 문서나 결과물에서 확인한 내용
  - `[조사]`: 출처가 있는 데스크 리서치·경쟁 서비스 조사 내용
  - `[가설]`: 아직 실제 사용자에게 확인하지 않은 예상
  - `[AI 제안]`: AI가 제안했지만 학생이 아직 검증하지 않은 내용
- 가상 서비스이므로 실제 사용자 조사나 관찰을 하지 않았다면 한 것처럼 작성하지 않습니다.
- AI의 답변은 조사 근거가 아닙니다. 출처가 필요한 사실은 별도로 확인합니다.
- 이름, 연락처, 얼굴, 계정 등 실제 개인정보를 입력하거나 AI에 전달하지 않습니다.
- 짧게 `있음`, `좋음`이라고만 쓰지 말고 대상·상황·이유·기대 효과가 드러나게 작성합니다.

### 1-3. 상세 서비스 설명

| 설명 항목 | 작성 내용 |
|---|---|
| 기획 배경 | 이 서비스를 생각하게 된 상황과 기존의 불편은 무엇인가? |
일정은 캘린더 앱, 필기는 Goodnotes, 간단한 메모는 메모장, 사진과 추억은 사진 앱처럼 기록이 여러 서비스에 나뉘어 있어 한 번에 관리하기 불편했음. 또 디지털 다이어리 앱은 사용은 쉬워도 내가 원하는 방식대로 꾸미거나 배치하기 어렵고, 자유도가 높은 필기 앱은 기능이 많아 복잡하게 느껴질 수 있었음. 그래서 DAMORI의 ‘기록을 내 방식대로, 삶을 나답게’라는 방향에 맞춰, 쉽게 시작하면서도 사용자가 원하는 방식으로 기록 구성을 바꿀 수 있는 앱을 기획함. |

| 해결할 핵심 문제 | 사용자는 언제, 어디에서, 무엇 때문에 어려움을 겪는가? |
사용자는 일상, 학교, 학원, 직장, 이동 중 등 여러 상황에서 일정·할 일·필기·메모·사진·감정 기록을 남기지만, 기록하는 앱이 다 달라 나중에 다시 찾거나 연결해서 보기 어려움. 또 정해진 속지만 사용할 경우 내 생활 방식에 맞게 쓰기 어렵고, 파일을 가져오거나 다른 기기에서 이어서 보는 것도 불편할 수 있음. 그래서 여러 기록을 하나의 기록책 안에 모으고, 날짜와 함께 연결해서 쉽게 기록하고 다시 볼 수 있도록 하는 것이 핵심임. |

| 주요 사용자 | 누구를 위한 서비스이며 그 사용자를 선택한 이유는 무엇인가? |
일정·필기·메모·사진 등 여러 기록을 한곳에서 관리하고 싶은 사용자 / 핵심 타깃: (일정·공부·취업 준비와 개인 기록을 함께 관리하는)20대 초중반 대학생·취업준비생, 확장 타깃: (일정관리·자기관리·일상 기록을 함께 사용하는 20대 중후반~30대 직장인과 기록 습관을 만들고 싶은)10대 후반~30대 기록 사용자|

| 핵심 제공 내용 | 사용자가 실제로 이용하는 기능·활동·지원은 무엇인가? |
메인 화면에서 사용자가 직접 만든 다이어리·노트 묶음을 확인하고, 기록책을 선택한 뒤 Monthly·Weekly·Daily·Free Note 같은 기본 속지를 골라 바로 기록할 수 있도록 함. 손글씨, 텍스트, 사진, 이미지, 스티커, 문서, PDF 등을 사용할 수 있고, 일정 영역·메모 영역·사진 영역·체크리스트 등을 추가하거나 빼고 위치와 크기도 바꿀 수 있도록 함. 캘린더에서는 일정과 그날 작성한 필기·사진·메모를 같이 확인할 수 있도록 하고, Google Calendar·Naver Calendar 연동과 PDF·이미지·문서·클라우드 파일 가져오기 기능도 고려함. 모바일·태블릿·웹에서 기록을 이어서 볼 수 있도록 하고, 잠금 기능과 표지·스티커·템플릿 꾸미기 기능도 포함함. |

| 이용 과정 | 서비스를 발견한 순간부터 이용 후까지 어떻게 진행되는가? |
사용자는 DAMORI 앱을 처음 실행한 뒤 스플래시와 온보딩을 통해 ‘흩어진 기록을 하나로 연결한다’는 서비스 내용을 확인함. 로그인 후 메인 화면에서 내가 만든 기록책과 최근 기록을 보고, 새 기록책을 만들거나 기존 기록책을 선택함. 그다음 기본 속지를 고르고 필요하면 레이아웃을 수정한 뒤 손글씨·텍스트·사진·문서 등을 기록함. 작성한 내용은 기록책과 날짜별로 쌓이고, 모바일에서는 빠르게 확인하거나 간단히 기록하고, 태블릿에서는 자세히 작성하거나 편집하는 방식으로 사용함. 이후 캘린더나 Archive에서 지난 기록을 다시 찾아볼 수 있도록 함. |

| 핵심 혜택 | 사용자의 시간·비용·감정·행동에 어떤 긍정적 변화가 생기는가? |
여러 앱을 오가며 기록하지 않아도 되어 사용이 편해지고, 일정·필기·메모·사진을 한곳에서 관리할 수 있음. 기본 템플릿이 있어 처음 시작하기는 쉽고, 필요하면 내가 원하는 방식으로 레이아웃을 바꿀 수 있어 자유롭게 사용할 수 있음. 기록이 날짜와 기록책별로 쌓여 나중에 다시 찾기 쉽고, 여러 기기에서 이어서 확인할 수 있어 기록이 끊기는 불편을 줄일 수 있음. 또 내가 만든 표지와 속지, 기록이 계속 쌓이면서 내 기록책이라는 애착도 생길 수 있음. |

| 서비스 제공 방식 | 누가, 어떤 공간·도구·콘텐츠·절차로 서비스를 제공하는가? |
DAMORI가 모바일 앱·태블릿 앱·웹 서비스를 제공하고, 사용자는 개인 계정으로 로그인해 자신의 기록을 관리함. 앱 안에서는 기록책 만들기, 속지 선택, 레이아웃 수정, 필기 도구, 사진·문서 가져오기, 캘린더, Archive, 템플릿과 꾸미기 기능 등을 제공함. 모바일은 빠른 확인과 간단한 기록 중심, 태블릿은 손글씨와 문서 필기, 레이아웃 편집 중심, 웹은 검색과 기록 정리 중심으로 역할을 나누는 방향임. 외부 캘린더와 클라우드 서비스는 이후 연동하는 방향으로 기획함. |

| 브랜드와의 연결 | 기존 브랜드의 가치·성격·시각 언어가 서비스에 어떻게 이어지는가? |
DAMORI는 ‘담다 + Memory’라는 의미를 가진 기록·아카이브 브랜드이고, ‘기록을 내 방식대로, 삶을 나답게’라는 방향을 가지고 있음. 앱에서도 단순히 글을 쓰는 기능만 제공하는 것이 아니라 일정·생각·감정·사진 같은 여러 기록을 한곳에 모으고 쌓는 경험을 중심으로 함. 메인 화면도 일반 파일 목록처럼 보이기보다 사용자의 기록책이 모여 있는 ‘기록 책장’처럼 구성하고, 기본 구조는 제공하되 사용자가 직접 바꿀 수 있도록 해서 DAMORI의 자유로운 기록과 개인 아카이브 개념을 이어가고자 함. |

| 포함 범위 | 이번 기획에서 실제로 다루는 범위는 어디까지인가? |
이번 기획에서는 DAMORI 앱의 전체 방향과 모바일 대표 화면 6장까지 우선 진행함. 모바일 6장은 Splash, Onboarding, 회원가입·로그인, Home·나의 기록책, Page Builder, Record 화면으로 구성함. 캘린더, Archive, 파일 가져오기, 동기화, 보안, 꾸미기, 템플릿 스토어, 커뮤니티, 마이페이지 기능은 전체 서비스 안에서 어떤 역할을 하는지 정리하는 정도까지 포함함. 이후 태블릿 기록 화면과 웹 관리 화면도 추가로 제작할 예정임. |

| 제외·제약 조건 | 이번 기획에서 다루지 못하는 내용과 현실적인 한계는 무엇인가? |
현재 단계에서는 실제 앱 개발, 서버 구축, 데이터 저장 방식, 결제 기능, 앱스토어·플레이스토어 등록, 외부 서비스 실제 연동, 개인정보 처리 방식 등은 다루지 않음. Google Calendar·Naver Calendar·Google Drive·iCloud·OneDrive 연동은 필요한 기능으로 생각하고 있지만 실제로 어디까지 가능한지는 아직 확인하지 않은 상태임. 템플릿 스토어·커뮤니티·기록 공유·템플릿 판매 기능도 이후 확장 기능으로 보고 있으며, 이번 모바일 6장에서는 별도 상세 화면으로 만들지 않음. |

### 1-4. 초안 자기 점검

- [O] 서비스가 단순한 이미지나 기능 목록이 아니라 사용자의 문제를 해결하는 과정으로 설명되어 있다.
- [O] 사용자가 누구인지, 언제·어디서 이용하는지가 구체적이다.
- [O] 서비스 제공자와 사용자의 역할을 구분할 수 있다.
- [O] 기존 브랜딩 프로젝트와 서비스의 연결 이유가 설명되어 있다.
- [O] 서비스의 포함 범위와 제외 범위가 분명하다.
- [O] 확인된 내용과 아직 검증하지 않은 가설이 구분되어 있다.

보완이 필요한 내용:

- Google Calendar, Naver Calendar 같은 외부 캘린더를 실제로 어디까지 연결할 수 있는지 확인 필요
- Google Drive, iCloud, OneDrive 같은 외부 파일 저장 서비스와 어떤 방식으로 연결할 수 있는지 확인 필요

## 9. 서비스 개념과 실행 방향 정리

### 9-1. 핵심 가치 제안

| 항목 | 작성 내용 |
|---|---|
| 고객 | 일정·필기·메모·사진 등 여러 기록을 함께 관리하고 싶고, 정해진 다이어리 형식보다 자신의 방식대로 기록하고 싶은 대학생·취업준비생을 가장 먼저 대상으로 함. 이후 직장인과 기록 습관을 만들고 싶은 사용자까지 확장함. |
| 문제 | 일정은 캘린더, 필기는 필기 앱, 메모는 메모장, 사진은 갤러리처럼 삶의 기록이 여러 앱에 나뉘어 있어 관리와 다시보기가 불편함. 쉬운 다이어리 앱은 자유도가 부족하고, 자유로운 필기 앱은 처음 사용하기 복잡할 수 있음. |
| 혜택 | 기록을 한곳에서 관리할 수 있어 편리하고, 기본 템플릿 덕분에 쉽게 시작할 수 있음. 필요한 부분은 직접 바꿀 수 있어 자유롭게 기록할 수 있고, 기록이 계속 쌓이면서 나만의 기록책과 Archive에 대한 애착도 만들 수 있음. |
| 해결 방식 | 메인에서 기록책을 선택하고 기본 템플릿을 고른 뒤 Page Builder를 이용해 필요한 부분만 수정함. 이후 손글씨·텍스트·사진·문서 등을 기록하고 Calendar·Archive를 통해 날짜와 기록을 연결해 다시 확인함. |
| 차별점 | 다욜의 직관적인 기록책 구조와 Goodnotes의 자유로운 필기·파일 활용 장점을 참고하면서, DAMORI는 기본 틀을 직접 수정할 수 있는 Page Builder와 일정·필기·사진·메모가 하나의 기록 흐름으로 쌓이는 구조를 중심 차이로 둠. |
| 사용자의 부담 | 처음에는 앱 구조와 Page Builder 사용 방법을 익혀야 하며, 외부 캘린더·파일 연동 시 권한 설정이 필요할 수 있음. 많은 기능이 한 번에 보이면 학습 부담이 커질 수 있어 처음에는 기본 기능 위주로 보여줄 필요 있음. 유료 템플릿·스토어 비용은 아직 정해지지 않음. |

### 9-2. 서비스 원칙

> 서비스의 기능이나 디자인을 결정할 때 기준이 될 원칙을 세 가지로 작성합니다.

1. 원칙 1: 쉽게 시작할 수 있어야 함
   - 필요한 이유: 자유도가 높아도 처음부터 모든 것을 직접 만들어야 하면 기록을 시작하기 어려워질 수 있기 때문임.
   - 적용 예시: Monthly·Weekly·Daily·Free Note 등 기본 템플릿을 먼저 제공하고, 사용자가 바로 기록을 시작할 수 있도록 함.

2. 원칙 2: 기본 틀은 제공하되 내 방식대로 바꿀 수 있어야 함
   - 필요한 이유: 기존 고정형 다이어리에서 느낀 레이아웃 부족 문제를 해결하면서 완전 자유형 기록의 부담도 줄이기 위함.
   - 적용 예시: Page Builder에서 일정·메모·사진·체크리스트 등의 위치와 크기를 바꾸거나 추가·삭제할 수 있도록 함.

3. 원칙 3: 기록이 끊기지 않고 이어져야 함
   - 필요한 이유: 현재 일정·필기·메모·사진이 여러 앱과 기기에 흩어져 있는 문제를 해결하는 것이 서비스의 핵심이기 때문임.
   - 적용 예시: 태블릿에서 작성한 기록을 모바일에서 확인하고, 일정과 해당 날짜의 필기·사진·메모를 Calendar·Archive에서 함께 볼 수 있도록 함.

[서비스 설명]

DAMORI는 일정, 필기, 메모, 사진, 일기처럼 여러 앱에 흩어진 기록을 하나의 흐름으로 연결해 관리할 수 있도록 만든 기록 서비스야.

사용자는 메인 화면에서 자신이 만든 기록책을 확인하고, 새 기록책을 만들거나 기존 기록책을 선택해서 기록을 시작할 수 있어.
Monthly, Weekly, Daily, Free Note 같은 기본 템플릿을 제공하고, 필요하면 Page Builder에서 일정, 메모, 사진, 체크리스트 같은 요소를 추가·삭제·이동해서 내 방식대로 레이아웃을 바꿀 수 있어.

기록 화면에서는 손글씨, 텍스트, 이미지, 사진, 스티커, PDF, 문서 등을 사용할 수 있고, 작성한 기록은 날짜와 기록책 기준으로 쌓이도록 기획하고 있어.
캘린더에서는 일정뿐만 아니라 해당 날짜에 작성한 필기·사진·메모도 같이 확인할 수 있도록 하고, 태블릿에서 작성한 기록을 모바일에서 확인하거나 이어서 보는 구조도 생각하고 있어.

모바일은 일정 확인과 빠른 기록, 태블릿은 필기와 자세한 편집, 웹은 기록 검색과 관리 중심으로 역할을 나누는 방향이야.
이번 기획에서는 모바일 앱 대표 화면 6장을 우선 제작하고, 핵심 흐름은 Splash → Onboarding → Login → Home → Page Builder → Record 순서로 구성하고 있어.

## 14. 최종 정리

- 내 서비스의 가장 분명한 강점: 다욜처럼 쉽게 기록을 시작할 수 있는 구조를 유지하면서, 사용자가 기본 템플릿을 자신의 방식대로 수정할 수 있고 일정·필기·메모·사진·파일을 하나의 기록 흐름으로 연결할 수 있다는 점

- 점검 전 가장 부족했던 부분: 기록, 일정, 파일, 동기화, 커뮤니티, 스토어 등 넣고 싶은 기능이 많아 어떤 기능이 DAMORI 앱의 가장 중요한 경험인지 우선순위가 명확하지 않았음

- AI와 상의한 뒤 내가 선택한 핵심 개선: 메인 화면은 ‘나의 기록책’을 중심으로 정리하고, 핵심 기능을 Page Builder와 Record로 좁힘. Calendar·Archive·파일·기기 연결은 기록을 이어주는 기능으로 두고 커뮤니티·스토어는 이후 확장 기능으로 분리함.

- 개선으로 달라진 사용자 경험: 사용자는 앱을 실행한 뒤 자신의 기록책을 먼저 확인하고, 기본 템플릿을 선택해 바로 기록할 수 있음. 필요한 경우에만 레이아웃을 수정할 수 있어 처음에는 쉽고 사용하면서 자유도를 높일 수 있는 구조로 바뀜.

- 아직 실제 사용자에게 확인해야 하는 가설: 사용자가 일정·필기·사진·메모를 실제로 하나의 기록 흐름으로 사용하는 것을 선호하는지, Page Builder에서 원하는 자유도는 어느 정도인지, 태블릿 작성·모바일 확인이라는 역할 구분이 실제 사용 습관과 맞는지 확인 필요함.

- 시간 또는 범위 때문에 남겨 둔 항목: 실제 앱 개발, 외부 캘린더·클라우드 연결, 실시간 동기화, 데이터 저장 방식, 결제·스토어, 커뮤니티 상세 기능, 고객지원·오류 복구 과정은 이후 단계로 남겨 둠.

- 다음 단계에서 가장 먼저 실행할 관찰 또는 검증: 모바일 6장과 핵심 Page Builder·Record 프로토타입을 제작한 뒤, 처음 보는 사용자가 Home → 기록책 선택 → 템플릿 선택 → 레이아웃 수정 → 기록 흐름을 설명 없이 사용할 수 있는지 확인하는 테스트 진행
