### 근거를 표시하는 방법

- `[프로젝트]`: 내 기존 자료나 직접 수정·확인한 문서에서 확인한 내용. 자료명과 쪽 또는 위치를 적습니다.
- `[조사]`: 내가 실제로 열어 확인한 문헌·보고서·공식 서비스 자료의 내용. 자료명, 출처·주소, 확인일을 적습니다.

- `[AI 제안]`: AI가 제안한 내용입니다. 내가 채택했더라도 사용자에게 검증된 사실로 바뀌지 않습니다.
- 확인된 자료 내용과 나의 해석을 서로 다른 문장으로 적습니다. AI 답변 자체는 조사 출처가 아닙니다.
- **가상 이용기록과 명시적 요구 가설은 실제 관찰·인터뷰 결과가 아닙니다.** 실제로 만나지 않은 사람의 발언이나 측정값을 실측 결과처럼 쓰지 않습니다.

## 4. 관찰조사 설계 — 필수

실제로 관찰을 진행할 때 사용할 계획을 구체화합니다. **이번 시험에서 실행하는 활동은 가상 이용 시나리오 검토**입니다. 관찰계획과 실제로 수행한 작업을 구분합니다.

| 항목 | 작성 내용 |
|---|---|
| 관찰 목적·연결 자료 | SRC- / USER- / 무엇을 확인하면 어떤 기획 결정을 할 수 있는가? |
| 관찰 대상·과업 | 어느 유형의 어떤 이용 상황·과업을 볼 것인가? |
| 환경·시점·소요 시간 | 어디서, 이용 과정의 언제, 얼마 동안 관찰할 계획인가? |
| 포함·제외 범위 | 어떤 행동·접점을 기록하고 무엇은 제외하는가? |
| 계획한 관찰 방법·선택 이유 | 직접 관찰, 섀도잉, 시간 또는 사건 중심 기록 등에서 선택하고 이유 설명 |
| 기록 방법·판단 기준 | 어떤 행동·중단·재시도·시간 등을 어떻게 기록하고 비교할 것인가? |
| 관찰 질문 1 | 행동으로 확인할 질문 / 연결한 자료나 예상 요구 |
| 관찰 질문 2 | 행동으로 확인할 질문 / 연결한 자료나 예상 요구 |
| 따로 물어볼 질문 | 관찰만으로 알 수 없는 생각·이유를 확인할 개방형 질문 1개 |
| 실행 구분·한계 | 이번에는 `[가설]` 기반 검토 / 실제로 확인하지 못하는 것 |
| 실제 조사 시 참여자 보호 계획 | 목적·방법·동의 안내, 개인정보 최소 기록, 촬영·녹음 시 별도 동의 계획 |

- [ ] 선행조사에서 나온 의문을 관찰 목적과 질문으로 바꾸었다.
- [ ] 대상·환경·시점·방법·기록 기준이 서로 연결된다.

### 5-2. 명시적 요구와 잠재 요구

**명시적 요구 가설**은 사용자가 직접 말할 수 있을 것으로 예상한 요구입니다. **잠재 요구 가설**은 행동·상황의 단서에서 해석한 숨은 요구입니다. 가상 발언을 실제 인용으로 쓰지 않습니다.

관련 이론으로 **카노 모델**을 적용합니다. 기본 요구는 없으면 불만을 만드는 필수 조건, 성능 요구는 충족 정도에 따라 만족이 달라지는 조건, 매력 요구는 예상 밖의 추가 가치를 주는 조건으로 구분합니다. 각 요구에서 가장 적합한 유형을 하나 골라 이유를 적습니다. 이는 설문으로 확정한 분류가 아닌 기획 가설입니다.

수업에서 배운 다른 관련 이론을 사용해도 됩니다. 이 경우 이론명·판단 기준과 자신의 요구에 적용한 이유를 적습니다.

| 요구 기록 | 작성 내용 |
|---|---|
| NEED-01 명시적 요구 가설 | `[가설]` 사용자 USER- / 예상 발언과 요구 / 출처 SRC- 또는 FLOW- 단서 / 요구로 해석한 이유 / 기본·성능·매력 중 선택 및 이유 |
| NEED-02 잠재 요구 가설 | `[가설]` 사용자 USER- / 행동·상황 단서 FLOW- / 단서에서 해석한 숨은 요구 / 자료 SRC-와의 연결 / 기본·성능·매력 중 선택 및 이유 |
| 다른 해석·후속 질문 | NEED-02의 같은 단서를 다르게 해석할 가능성 / 두 해석을 구분하기 위해 실제 사용자에게 확인할 질문 |
| 요구 우선순위·판단 이유 | 어떤 요구를 먼저 해결할 것인가? 사용자 영향·서비스 목표·실행 가능성에서 설명 |

- [ ] 이용 전·중·후와 각 접점의 행동·감정·불편을 기록했다.
- [ ] 수집한 자료와 가상 이용기록에서 요구를 도출하고 이론을 적용했다.
- [ ] 잠재 요구에는 행동 단서와 해석 과정이 함께 있다.

## 6. 디자인 요소 점검과 문제 선정 — 필수

**디자인 요소 2개**를 사용자 성향·요구와 연결하여 설정합니다. 화면·기능 외에도 공간·동선·정보·절차·대기시간·응대 등 서비스에 필요한 요소를 선택할 수 있습니다.

| 요소 기록 | 작성 내용 |
|---|---|
| ELEMENT-01 | 구체적인 요소·적용 위치·운영 방식 / 연결 USER-·NEED-·FLOW- / 선택 이유 / 적용할 브랜드 원칙 / 적합·보완·미확인 판단 |

- [ ] 잠재 요구를 해결하기 위한 환경개선과 예상 효과를 설명했다.

## 7. AI와 상의하고 직접 판단하기 — 필수

서비스 설명, 사용자 유형, 자료에서 확인한 내용, 가설, OBS-01·02, 유지할 브랜드 원칙을 AI에 전달합니다. 질문과 답변의 핵심을 PDF 안에 넣습니다. 전체 대화 내보내기나 유료 AI 사용은 요구하지 않습니다.

**사용할 수 있는 질문 틀**

> 아래 서비스와 문제를 검토해 줘. 확인된 자료, 내 가설, AI 제안을 구분하고 제공하지 않은 사용자 발언·통계·조사 결과를 만들지 마. 문제마다 보완안 2개와 장단점, 연결되는 사용자 요구, 실제 관찰로 추가 확인할 점을 제안해 줘.
>
> 서비스 설명: … / 사용자: … / 자료 근거: … / 가설: … / 문제 OBS-01·02: … / 유지할 원칙: …

| 기록 | 작성 내용 |
|---|---|
| 사용 AI·사용일 | 도구명 / 날짜 |
| AI-01 | 연결 OBS- / 내가 입력한 질문의 핵심 / `[AI 제안]` 핵심 답변 / 반영·수정 반영·보류·제외 중 결정 / 내 판단 이유 / 추가 확인할 점 |
| AI-02 | 연결 OBS- / 내가 입력한 질문의 핵심 / `[AI 제안]` 핵심 답변 / 반영·수정 반영·보류·제외 중 결정 / 내 판단 이유 / 추가 확인할 점 |

- [ ] 내 서비스의 근거와 제약을 전달했고 답변을 내가 이해했다.
- [ ] 두 제안 모두 내 판단과 이유를 기록했다. 실제로 거절한 제안이 있을 때 그 이유도 적었다.
- [ ] AI가 제시한 출처나 수치를 확인 없이 사실로 사용하지 않았다.
