# 서비스ㆍ경험디자인 시나리오 개발 피드백 기준

## 작성 방식

[공통 피드백 작성 지침](../피드백.md)의 말투와 근거 원칙을 적용한다. 학생의 최종 PDF 전체를 확인하고, 주요 장면·표·스토리보드·평가 기록을 직접 근거로 사용한다.

10개 평가항목은 모두 검토해 교사용 기록에 남기되, 학생 공개문은 가장 중요한 강점과 수정 우선순위를 중심으로 관련 문제를 묶어 설명한다. 내부 SC 번호, 원점수 계산, 순위와 강사용 판단 예시는 공개하지 않는다.

## 반드시 확인할 내용

- 서비스가 해결할 문제, 제공 가치와 주요 이해관계자가 시나리오 목적에 연결되는가.
- 대표 페르소나의 목표·동기·제약·행동 특성이 사용자 자료와 시나리오에 연결되는가.
- 주요 단계와 세부 행동, 접점, 서비스 반응, 전환 조건이 시간과 인과관계에 맞는가.
- 사용성·편의성·접근성, 이탈·오류·예외·회복 경로가 구체적 장면에서 검토됐는가.
- 문장·흐름도·스토리보드가 같은 사용자 경험을 일관되게 설명하는가.
- 잠재 문제의 장면·원인·영향·우선순위와 개선 방향이 추적되는가.
- 대내적 관점과 대외적 관점이 구분되고 평가 방법·기준·결과·한계가 기록됐는가.
- 평가 결과가 수정 전후와 최종 시나리오에 실제로 반영됐는가.
- 모의평가, 가설, 실제 참여자 반응과 평가자의 제안이 서로 구분되는가.
- PDF의 글자·표·그림·출처가 읽히고 필요한 기록을 찾을 수 있는가.

## 판단 범위

- 가상 페르소나나 수업 내 역할평가를 사용했다는 이유만으로 감점하지 않는다. 실제 사용자 검증을 수행한 것으로 과장했는지를 구분한다.
- 실제 참여자 수, 만족도, 완료율이나 시장 효과를 확인하지 못했다면 성과 사실로 단정하지 않는다.
- 기능이 많거나 스토리보드가 화려하다는 이유로 높은 평가를 하지 않는다. 사용자 목표와 문제 해결에 필요한지를 본다.
- 특정 시나리오 유형이나 시각화 도구를 정답으로 강제하지 않는다. 학생이 선택한 표현 방식으로 행동·감정·접점·서비스 반응과 흐름을 판단할 수 있으면 인정한다.
- 체크박스나 표의 빈칸만으로 수행 누락을 단정하지 않고 다른 절의 동등한 근거를 먼저 확인한다.
- 같은 원인의 문제는 묶어서 설명하며 문항마다 반복 감점하지 않는다.

## 실행 가능한 개선 안내

- 흐름 문제는 어느 단계에서 앞뒤 조건이 끊기는지 짚고, 필요한 전환 조건이나 서비스 반응을 제안한다.
- 페르소나 문제는 인구통계 정보를 더 늘리기보다 어떤 목표·동기·제약이 장면 선택과 행동을 바꾸는지 작성하도록 안내한다.
- 상황이 추상적이면 시간·장소·환경·동행자·기기·제약 중 무엇을 구체화해야 하는지 설명한다.
- 사용성 문제가 기능 의견에 머물면 사용자의 목표, 행동, 실패 조건, 회복 방법과 연결하도록 안내한다.
- 평가가 약하면 내부 실현가능성 관점과 외부 사용자 경험 관점을 나누고 같은 장면을 어떤 기준으로 재검토할지 제시한다.
- 개선안이 평가와 연결되지 않으면 평가 기록 ID, 문제 ID, 수정 ID를 이어서 전후 차이를 확인하게 한다.
- 교사가 제시하는 예시는 앞으로 검토할 제안임을 밝히고 학생이 이미 수행한 사실처럼 쓰지 않는다.

## 공개 전 확인

- 학생명·프로젝트명·최종점수와 실제 PDF가 일치하는가.
- 실제 확인, 모의평가, 가설과 개선 제안이 구별되는가.
- 다른 학생이나 다른 능력단위의 근거가 섞이지 않았는가.
- 같은 문제를 반복 설명하거나 중복 감점하지 않았는가.
- 학생이 무엇을 어디에서 어떻게 고치고 다시 확인할지 이해할 수 있는가.
- 공식적인 `~습니다`, `~하세요`, `~바랍니다` 말투를 유지했는가.
- 마지막에 공개 가능한 최종점수와 가장 먼저 수정할 항목을 짧게 안내했는가.
