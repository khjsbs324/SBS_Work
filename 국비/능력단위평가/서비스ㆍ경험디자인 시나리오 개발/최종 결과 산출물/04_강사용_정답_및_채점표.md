# 강사용 기준 및 채점표

평가 종료 전 학생에게 공개하지 않습니다.

## 1. 모범 수행의 연결 구조

이 평가에는 학생이 복제해야 하는 하나의 서비스 정답이나 스토리보드가 없다. 다음 연결 관계가 모범 수행의 기준이다.

```text
입력 자료와 서비스 가치
→ 이해관계자와 시나리오 목적
→ 사용자 유형과 대표 페르소나
→ 구체적 상황과 서비스 접점
→ 5~7개 주요 단계와 전환 조건
→ 문장·흐름도·스토리보드
→ 잠재 문제와 원인·우선순위
→ 대내외 타당성 평가
→ 평가 기반 개선
→ 변경 이력이 있는 최종 시나리오
```

## 2. 직접 증빙 확인표

- [ ] 서비스가 해결할 문제와 제공 가치가 한 문장으로 정리됐다.
- [ ] 주요 이해관계자와 시나리오의 활용 대상이 구분됐다.
- [ ] 페르소나의 목표·동기·제약·행동 특성에 근거가 있다.
- [ ] 주요 단계와 세부 행동, 서비스 반응과 전환 조건이 연결됐다.
- [ ] 사용성·편의성·접근성, 예외·오류·회복 경로가 검토됐다.
- [ ] 문장·흐름도·스토리보드가 같은 경험을 설명한다.
- [ ] 문제 ID에 발견 장면·원인·영향·우선순위가 연결됐다.
- [ ] 내부 관점과 외부 관점의 평가 역할·기준·결과가 구분됐다.
- [ ] 실제평가와 모의평가가 구분되고 확인 범위가 기록됐다.
- [ ] 평가 결과가 수정 전후와 최종 시나리오에 반영됐다.

## 4. 영역별 빠른 검수

### 시나리오 기획 및 단계 구조화 — 28점

서비스 목적·이해관계자와 5~7개 주요 단계, 전환 조건, 사용성·편의성·예외·회복 흐름을 확인한다. 단계 수만으로 점수를 정하지 않는다.

### 사용자 시나리오 제작 및 문제 개선 — 38점

페르소나 근거, 특정 상황, 문장·스토리보드의 일치와 잠재 문제의 장면·원인·영향·개선 방향을 확인한다. 그림 실력이나 장식은 독립 점수로 사용하지 않는다.

### 타당성 평가·문서화·보완 — 34점

내부 실현가능성 관점과 외부 사용자 경험 관점의 평가를 구분하고, 평가 결과가 문제·개선·최종 시나리오로 이어지는지 확인한다.

## 5. 평가 방식 판단

- 수업 내 역할평가나 모의평가는 인정한다. 다만 실제 사용자 반응·성과로 표현하면 근거 신뢰성을 해당 문항에서 판단한다.
- 실제 참여자 자료를 제출한 경우 참여자 수 자체보다 평가 목적·조건·질문·기록·한계가 적절한지 본다.
- 휴리스틱, 워크스루, 체크리스트, 역할평가 중 어느 하나만 정답으로 요구하지 않는다.
- 평가 의견을 보류하거나 반영하지 않았더라도 사용자·서비스 근거가 타당하면 인정한다.

## 6. 감점 및 보류 원칙

- 같은 흐름 누락을 여러 문항에서 반복 감점하지 않는다.
- 빈칸이 있어도 다른 절에 동등한 답변이 있는지 먼저 확인한다.
- 시각 자료의 미려함이나 문서 길이를 점수 근거로 사용하지 않는다.
- 코드·웹 구현·배포 자료가 없다는 이유로 감점하지 않는다.
- PDF가 열리지 않거나 표·글자가 판독되지 않으면 임의 0점 처리하지 않고 확인 불가 범위와 재제출 조건을 기록한다.
- 평가 환경 문제와 학생 제출 누락을 구분한다.
