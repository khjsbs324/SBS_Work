# 강사용 수업진행안

## 1. 평가 개요

| 항목 | 내용 |
|---|---|
| 능력단위 | 서비스ㆍ경험디자인 시나리오 개발 |
| 능력단위 코드 | `0802010619_23v4` |
| 평가 방식 | 개인 포트폴리오 |
| 평가 시간 | 240분 |
| 평가 대상 | 기존 서비스 기획 또는 강사 제공 서비스 개념 한 건 |
| 필수 제출 | `이름_서비스경험_시나리오개발.pdf` 1개 |
| 문항·총점 | 10문항, 100점 |

## 2. 평가 목적

학생이 서비스 기능을 나열하는 데 그치지 않고, 사용자 자료에 근거한 페르소나를 중심으로 목표·상황·행동·감정·접점·서비스 반응을 시간 흐름에 따라 구조화하는지를 평가한다. 제작된 시나리오를 내부 실현가능성 관점과 외부 사용자 경험 관점에서 검토하고, 평가 결과를 최종 보완안까지 추적하는 과정도 함께 본다.

## 3. 평가 전 준비

- [ ] 학생별 서비스 주제와 입력 자료를 확정한다.
- [ ] 기존 관찰조사 자료 또는 서비스 개념서가 열리는지 확인한다.
- [ ] 실제 조사 사실, 학생 가설과 모의평가를 구분하도록 안내한다.
- [ ] 역할평가를 사용할 경우 내부 역할과 외부 역할을 미리 구분한다.
- [ ] 학생에게 02·03·05번 자료만 배포한다.
- [ ] 강사용 채점표와 `Exam.md`가 학생 자료에 포함되지 않았는지 확인한다.

## 4. 240분 진행

### 1단계. 입력 자료와 범위 확정 — 15분

서비스가 해결할 문제, 제공 가치, 주요 사용자와 이해관계자, 사용할 기존 자료를 확정한다. 학생은 실제 자료·가설·모의평가의 표시 방법을 정한다.

### 2단계. 서비스 기획과 페르소나 설정 — 35분

시나리오의 목적·범위·활용 대상을 정하고, 대표 페르소나의 목표·동기·제약·행동 특성과 선정 근거를 작성한다.

### 3단계. 단계별 흐름 구조화 — 50분

서비스 이용 과정을 5~7개 주요 단계로 나누고 행동, 접점, 서비스 반응, 감정, 전환 조건을 연결한다. 이탈·오류·예외·회복 경로와 전방·후방 지원을 함께 검토한다.

### 4단계. 시나리오와 스토리보드 제작 — 55분

대표 장면을 사용자 관점의 이야기로 작성하고 흐름도 또는 스토리보드로 시각화한다. 정상 경로뿐 아니라 서비스의 판단이 필요한 특정 상황을 포함한다.

### 5단계. 문제 도출과 대내외 타당성 평가 — 45분

학생은 잠재 문제를 장면에 연결하여 원인·영향·우선순위를 분석한다. 내부 이해관계자 관점과 외부 사용자·전문가 관점으로 나누어 체크리스트, 워크스루, 역할평가 등 적절한 방법으로 평가한다.

수업 내 모의평가를 사용할 수 있다. 강사는 모의평가를 실제 제3자 사용자 테스트 결과로 쓰지 않도록 확인한다.

### 6단계. 개선·문서화·최종 시나리오 — 30분

평가 결과에서 수정할 문제를 선택하고 전후 차이, 변경 이유, 확인 조건을 기록한다. 최종 시나리오의 흐름과 문서 간 일관성을 다시 확인한다.

### 7단계. PDF 변환과 제출 점검 — 10분

파일명, 학생 정보, 표·그림·글자의 가독성, 페이지 잘림, 출처, 필수 절의 존재를 확인하고 PDF 한 개를 제출받는다.

## 5. 과정 관찰 항목

- 사용자 자료와 페르소나를 구분해 설명하는가.
- 페르소나 특성이 장면·행동·의사결정에 실제로 반영되는가.
- 단계 사이의 전환 조건과 서비스 반응이 연결되는가.
- 이탈·오류·회복을 사용자의 실패 탓으로만 돌리지 않는가.
- 내부 실현가능성과 외부 사용자 경험을 다른 기준으로 평가하는가.
- 평가 의견을 모두 수용하지 않고 근거로 선택·보류하는가.
- 평가 결과와 최종 수정이 ID로 추적되는가.

## 6. 회수 및 채점 순서

1. 학생명·프로젝트명·파일명과 PDF 열림 상태를 확인한다.
2. 서비스 입력 자료와 페르소나 선정 근거를 확인한다.
3. 단계 구조와 문장·스토리보드가 같은 흐름인지 대조한다.
4. 문제 ID, 평가 기록, 개선 ID와 최종 시나리오를 연결한다.
5. 모의평가와 실제 참여자 자료가 구분됐는지 확인한다.
6. `Exam.md`의 SC-01~SC-10에 PDF 페이지·절·표를 직접 증빙으로 기록한다.
7. 동일한 문제를 여러 문항에서 반복 감점하지 않았는지 검토한다.

## 7. 운영 유의사항

- 실제 외부 참여자를 섭외하지 못했다는 이유만으로 감점하지 않는다.
- 모의평가를 실제 사용자 반응·완료율·만족도로 과장하지 않는다.
- 스토리보드의 그림 실력이나 문서 장식보다 흐름과 판단 근거를 본다.
- 특정 앱·웹·기술·시각화 도구를 공통 필수조건으로 추가하지 않는다.
- 다른 평가의 제출물과 문항을 이 평가의 필수조건으로 가져오지 않는다.
