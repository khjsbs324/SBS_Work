# 서비스ㆍ경험디자인 시나리오 개발 능력단위평가

## 과제 목표

기존에 기획한 서비스 또는 강사가 제공한 서비스 개념을 바탕으로 대표 사용자의 경험 시나리오를 개발합니다. 사용자의 목표와 상황에서 시작해 행동, 감정, 서비스 접점과 반응을 단계별로 구성하고, 잠재 문제와 대안 경로를 검토합니다. 작성한 시나리오는 내부 실현가능성 관점과 외부 사용자 경험 관점에서 평가한 뒤 최종안으로 보완합니다.

## 평가 조건

- 개인평가
- 평가 시간: 240분
- 필수 제출: `이름_서비스경험_시나리오개발.pdf` 1개
- 편집 가능한 원본: 선택 제출
- 웹사이트·앱·코드·실제 서비스 배포: 필수 아님

## 사용할 입력 자료

다음 중 한 건을 사용합니다.

- 본인이 작성한 서비스 기획·아이데이션·관찰조사 결과
- 기존 브랜딩 프로젝트에서 도출한 서비스 개념
- 강사가 제공한 서비스 개념서와 사용자 자료

자료가 실제 조사 결과인지, 수업용 가설인지 구분해 표시하세요. 참고한 외부 자료가 있다면 자료명과 출처를 적으세요.

## 작업 순서

1. 서비스가 해결할 문제, 제공 가치와 주요 이해관계자를 정리합니다.
2. 시나리오의 목적·범위·활용 대상을 정합니다.
3. 사용자 자료를 바탕으로 대표 페르소나를 설정합니다.
4. 이용 과정을 5~7개 주요 단계로 나눕니다.
5. 각 단계의 목표·행동·접점·감정·서비스 반응·전환 조건을 연결합니다.
6. 사용성·편의성·접근성과 이탈·오류·예외·회복 경로를 검토합니다.
7. 사용자 관점의 시나리오를 문장으로 작성하고 핵심 장면을 흐름도 또는 스토리보드로 표현합니다.
8. 장면별 잠재 문제를 찾아 원인·영향·우선순위를 정합니다.
9. 내부 이해관계자 관점과 외부 사용자·전문가 관점으로 타당성을 평가합니다.
10. 평가 결과에 따라 시나리오를 수정하고 전후 차이와 남은 문제를 기록합니다.

## 대내외 타당성 평가

실제 외부 사용자를 반드시 섭외해야 하는 평가는 아닙니다. 수업 안에서 역할을 나눈 모의평가를 사용할 수 있습니다.

- 대내적 관점 예시: 기획자, 디자이너, 개발자, 운영자, 마케터가 구현 가능성·운영 가능성·비용·일정·일관성을 검토
- 대외적 관점 예시: 목표 사용자 또는 외부 전문가 역할이 이해 가능성·사용성·접근성·신뢰·시장 수용성을 검토

모의평가라면 `[모의평가]`라고 표시하세요. 실제 참여자가 없다면 사용자가 실제로 만족했다거나 완료율이 향상됐다고 작성하지 않습니다.

## AI 활용

AI는 누락 확인, 대안 발상, 문장 정리에 사용할 수 있습니다. AI가 제안한 내용은 바로 정답이 되지 않습니다. 제안을 선택·수정·보류한 이유를 본인의 서비스와 사용자 근거로 판단하세요. AI가 만든 숫자·출처·사용자 반응을 확인 없이 실제 사실로 사용하지 않습니다.
