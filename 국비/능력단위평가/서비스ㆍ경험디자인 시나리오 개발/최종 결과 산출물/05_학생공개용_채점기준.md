# 학생 공개용 채점기준

## 평가에서 보는 핵심

이 평가는 서비스 기능을 많이 제안하거나 스토리보드를 화려하게 그리는 평가가 아닙니다. 사용자 자료에 근거한 페르소나가 구체적인 상황에서 서비스를 경험하는 과정을 논리적으로 구성하고, 평가 결과에 따라 문제를 보완할 수 있는지를 봅니다.

## 1. 시나리오 기획과 단계 구조화 — 28점

### 높은 성취

- 서비스가 해결할 문제, 가치, 이해관계자와 시나리오 목적이 분명합니다.
- 주요 단계와 세부 행동, 접점, 서비스 반응과 전환 조건이 자연스럽게 이어집니다.
- 사용성·편의성·접근성, 이탈·오류·회복 경로가 구체적인 장면에 반영됩니다.

### 보완이 필요한 경우

- 서비스 기능은 많지만 누구의 어떤 경험을 설명하는지 불분명합니다.
- 단계가 기능 목록처럼 나열되고 앞뒤 전환 조건이 없습니다.
- 편리하다는 설명만 있고 실패 상황이나 대안 경로를 찾기 어렵습니다.

## 2. 사용자 시나리오 제작과 문제 개선 — 38점

### 높은 성취

- 사용자 자료에 근거한 페르소나의 목표·동기·제약이 행동과 선택에 반영됩니다.
- 시간·장소·환경과 서비스 접점이 구체적이며 문장과 스토리보드가 같은 흐름을 보여줍니다.
- 잠재 문제의 발견 장면, 원인, 영향, 우선순위와 개선 방향이 연결됩니다.

### 보완이 필요한 경우

- 페르소나가 이름·나이·직업 설명에 머물고 시나리오에 영향을 주지 않습니다.
- 상황이 일반적이어서 다른 사용자나 서비스에도 그대로 적용됩니다.
- 문제와 개선안을 나열했지만 어느 장면에서 왜 필요한지 알기 어렵습니다.

## 3. 타당성 평가와 최종 보완 — 34점

### 높은 성취

- 내부 실현가능성 관점과 외부 사용자 경험 관점을 구분해 적절한 기준으로 평가합니다.
- 평가 의견과 판단의 한계를 기록하고, 실제평가와 모의평가를 구분합니다.
- 평가 결과에서 문제와 개선 우선순위를 도출하고 수정 전후와 최종 시나리오를 추적할 수 있습니다.

### 보완이 필요한 경우

- 평가자의 역할과 기준이 불분명하고 의견만 나열되어 있습니다.
- 모의평가를 실제 사용자 반응이나 성과처럼 작성합니다.
- 평가 결과와 최종 수정의 연결 또는 변경 이력을 확인하기 어렵습니다.

## 공통 확인사항

- 모든 중요한 판단에 프로젝트·조사·가설·평가 중 하나 이상의 근거가 있어야 합니다.
- 확인하지 않은 통계와 사용자 반응을 만들지 않습니다.
- 외부 자료와 이미지에는 출처를 표시합니다.
- 표·글자·스토리보드가 읽히고 페이지 밖으로 잘리지 않아야 합니다.
- 웹·앱·코드·실제 서비스 배포는 필수 제출물이 아닙니다.
- AI 사용 여부 자체는 점수에 영향을 주지 않습니다. 제안의 적합성을 본인이 판단해야 합니다.

최종점수는 각 평가영역의 수행 내용과 제출 PDF에서 확인되는 직접 근거를 종합하여 산정합니다.
