# 서비스ㆍ경험디자인 시나리오 개발 평가 지침

## 평가 목적

이 폴더의 능력단위는 `서비스ㆍ경험디자인 시나리오 개발(0802010619_23v4)`이다. 학생이 기존 서비스 기획과 사용자 자료를 바탕으로 페르소나 중심의 서비스 시나리오를 기획·구조화하고, 문장 또는 스토리보드로 제작한 뒤 타당성 평가 결과에 따라 문제점을 보완하는 전 과정을 평가한다.

## 기준 자료

1. 사용자의 최신 지시
2. `Exam.md`
3. `서비스ㆍ경험디자인 시나리오 개발 수행준거.txt`
4. 원본 NCS 학습모듈 PDF와 `pdf요약결과.md`
5. `최종 결과 산출물/`의 운영·제출 문서

원문의 문장·순서·개수는 수행준거 TXT를 기준으로 하고, 평가 방식·배점·제출 조건은 현재 `Exam.md`를 따른다. `SC-01`~`SC-10`은 내부 추적 ID이며 공식 NCS 수행준거 번호가 아니다.

## 평가 조건

- 개인평가, 240분, 포트폴리오 방식으로 진행한다.
- 기존 브랜딩·아이데이션·관찰조사 결과 또는 강사가 제공한 서비스 개념서 중 한 건을 입력 자료로 사용한다.
- 필수 제출은 `이름_서비스경험_시나리오개발.pdf` 한 개다. 편집 가능한 원본은 선택 제출이며, 미제출만으로 감점하지 않는다.
- 웹사이트·앱·코드·프로토타입 구현과 실제 서비스 배포는 필수 조건이 아니다.
- 글, 표, 흐름도, 고객 여정, 서비스 청사진, 스토리보드 등 서비스 시나리오의 판단 근거가 PDF 안에서 읽혀야 한다.
- AI 도구는 아이디어 점검과 문장 정리에 사용할 수 있으나 사용 여부·모델·유료 여부는 점수 기준이 아니다. AI가 만든 사용자 반응·통계·평가 결과를 실제 사실로 제출하지 않는다.

## 판단 원칙

- 서비스 기능의 수나 시각적 화려함보다 사용자 목표, 상황, 행동, 감정, 접점, 서비스 반응과 단계 간 인과관계를 평가한다.
- 페르소나는 인구통계 정보만 나열하지 않고 목표·동기·제약·행동 특성과 시나리오 선택에 연결되어야 한다.
- 5~7개 주요 단계는 과제 안내의 구조화 기준이다. 단계 수 자체보다 시작·진행·완료·이탈·예외·회복 흐름의 완전성을 판단한다.
- 대내외 타당성 평가는 내부 이해관계자 관점과 외부 사용자·전문가 관점을 구분하여 수행한다. 수업 내 역할평가 또는 모의평가를 사용할 수 있으며, 가상 방식 자체를 감점하지 않는다.
- 모의평가 결과는 실제 사용자 효과나 시장 성과로 단정하지 않는다. 실제 참여자 자료가 있다면 동의·익명화·확인 범위를 기록한다.
- 휴리스틱, 워크스루, 역할평가, 체크리스트 등 선택한 방법이 서비스 시나리오와 평가 목적에 적합한지 본다. 특정 방법 하나를 정답으로 강제하지 않는다.
- 동일 문제는 주된 문항에서만 감점하고 다른 문항에서는 관련 근거로 참조한다.
- 다른 능력단위의 문항·배점·결함·필수 제출물을 가져오지 않는다. 관찰조사 결과는 시나리오의 입력 근거로만 사용한다.

## 직접 증빙

- 서비스 개념, 이해관계자, 사용자 자료와 출처
- 대표 페르소나와 선정 근거
- 시나리오 구성요소, 주요 단계, 전환 조건과 대안 경로
- 사용성·편의성·접근성·예외·회복 검토
- 정황 시나리오, 주요 경로 또는 점검 시나리오와 스토리보드
- 문제 ID, 원인, 영향, 우선순위와 개선 방향
- 대내외 평가 계획·기록·결과와 확인 범위
- 수정 전후 비교, 변경 이력과 최종 시나리오

확인하지 못한 활동을 수행했다고 추정하지 않는다. 빈칸만으로 누락을 단정하지 않고 PDF의 다른 절에서 동등한 증빙을 먼저 확인한다.

## 채점과 피드백

- `Exam.md`의 SC-01~SC-10을 사용하고 모든 점수에 PDF 페이지·절·표·기록 ID를 연결한다.
- 자료가 열리지 않거나 판독할 수 없으면 임의 0점 대신 확인 불가 사유와 재확인에 필요한 자료를 기록한다.
- 학생 공개용 피드백은 실제 장면과 기록을 근거로 강점, 주요 보완점, 수정 방법과 재확인 순서를 설명한다.
- 공개문에 내부 SC 번호, 원점수 환산 과정, 순위, 강사용 판단 예시와 다른 학생 정보를 넣지 않는다.

## 검증

국비 폴더에서 다음을 실행한다.

```powershell
python -B scripts/harness.py check --records
```

원문 10문장, Exam 10문항, 강사용 채점표와 학생 공개용 기준의 대응, 총점 100점, 4단계 점수 구간, 240분과 PDF 1개 제출 조건을 함께 확인한다. 학생용 자료에 강사용 정답이 노출되지 않았는지도 검토한다.
