- 이미지 확인: 텍스트층이 없는 PDF 3~9쪽을 실제 이미지로 렌더링하여 공통 「NCS학습모듈의 이해」 안내임을 확인

## 2. 원문 대응

| 영역 | 내부 ID | 원문 수 | Exam 문항 수 | 배점 |
|---|---|---:|---:|---:|

- 수행준거 TXT의 원문·순서와 `Exam.md`의 `- 원문:` 문장을 대조했다.
- `SC-01`~`SC-10`은 내부 추적 ID이며 공식 NCS 수행준거 번호로 표현하지 않았다.
- 모든 문항에 직접 증빙과 4단계 정수 점수 구간을 작성했다.
- 각 점수 구간은 0점부터 문항 만점까지 중복이나 빈틈 없이 구성했다.

## 3. 평가 조건 일치

- 개인평가: 모든 운영·학생 문서에서 일치
- 평가 시간: 240분으로 일치
- 필수 제출: `이름_서비스경험_시나리오개발.pdf` 1개로 일치
- 편집 원본: 선택 제출로 일치
- 코드·앱·웹·배포: 필수조건이 아님을 명시
- 실제 외부 참여자: 필수로 요구하지 않으며 모의평가와 실제평가를 구분
- AI: 사용 여부를 점수화하지 않고 가상 반응·통계의 사실화 금지

## 4. 학생용·강사용 분리

- 학생 배포 문서: `02_학생용_과제안내서.md`, `03_학생_제출_산출물.md`, `05_학생공개용_채점기준.md`
- 강사 전용 문서: `01_강사용_수업진행안.md`, `04_강사용_정답_및_채점표.md`, 상위 `Exam.md`
- 학생용 3개 문서에서 내부 SC 코드, 원점수·환산식, 강사용 판단 예시가 노출되지 않았음을 검색으로 확인했다.

## 5. 자동 검증

국비 폴더에서 다음 명령을 실행했다.

```powershell
python -B scripts/harness.py check --records
```

결과:

- `ok: true`
- 서비스ㆍ경험디자인 시나리오 개발: 10문항, 총점 100점
- 현재 평가자료 관련 오류: 없음
- 출력된 경고는 기존 서비스ㆍ경험디자인 관찰조사 학생 제출물의 CRLF/LF 차이로, 이번 신규 평가자료와 무관하다.

## 6. 별도 확인 범위

- 학생용 Markdown 작성 양식은 제작했으며 배포용 PDF 자체는 생성하지 않았다.
- 학생이 작성한 최종 PDF를 회수할 때 표·글자·그림 잘림과 링크·출처 가독성을 학생별로 확인해야 한다.
- 평가 사이트 문제 등록과 점수 등록은 이번 작업 범위에 포함하지 않았다.
