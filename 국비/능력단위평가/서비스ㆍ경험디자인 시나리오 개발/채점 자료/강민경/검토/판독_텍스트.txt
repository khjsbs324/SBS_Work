[P01-L0120] DAMORI 앱 서비스 기획 캔버스
[P01-L0121] 01. 서비스 기본 정의
[P01-L0122] 항목기획 내용프로젝트DAMORI(다모리) 투트랙 기록·아카이브 브랜드 프로젝트서비스명
[P01-L0123] DAMORI(다모리) 앱서비스 유형모바일·태블릿 중심 디지털 기록·아카이브 서비스브랜드 내
[P01-L0124] 역할DAMORI 브랜드의 디지털 부가 서비스이자 독립적인 기록 경험을 제공하는 서비스서비
[P01-L0125] 스 주제일정·필기·메모·사진·일기처럼 여러 곳에 흩어진 기록을 하나의 기록 흐름으로 연결하
[P01-L0126] 고, 사용자가 자신의 방식대로 기록 구조를 구성하며 시간이 지난 뒤 다시 찾아볼 수 있도록 하
[P01-L0127] 는 디지털 기록 서비스핵심 키워드기록 / 편의 / 축적 / 자유 / 애착핵심 서비스 문장틀은 제공
[P01-L0128] 하지만 틀에 갇히지는 않는 기록 서비스UX 핵심 문장쉽게 시작하고, 내 방식대로 기록하며, 삶
[P01-L0129] 의 기록을 하나로 이어가는 앱기록 흐름PLAN → RECORD → ARCHIVE → REVIEW
[P01-L0130] 02. 서비스 목적
[P01-L0131] DAMORI 앱의 목적은 단순히 종이 다이어리를 화면에 옮겨놓는 것이 아니다.
[P01-L0132] 사용자는 현재 일정은 캘린더 앱, 필기는 필기 앱, 짧은 생각은 메모 앱, 사진은 갤러리, 일기는
[P01-L0133] 별도의 다이어리 앱처럼 기록 목적에 따라 여러 서비스를 오가며 생활의 기록을 관리하고 있
[P01-L0134] 다.
[P01-L0135] 이 과정에서 하나의 하루에 있었던 일정·생각·사진·필기·감정이 서로 다른 장소에 저장되고, 시
[P01-L0136] 간이 지나면 “무엇을 어디에 기록했는지 다시 찾기 어려운 상태”가 생긴다. 기존 기획서에서도
[P01-L0137] 이 기록 분산을 DAMORI가 해결하려는 핵심 문제로 정의하고 있다.
[P01-L0138] DAMORI는 이를 해결하기 위해 다음 경험을 제공하는 것을 목적으로 한다.
[P01-L0139] 여러 곳에 흩어진 기록을 하나의 기록책과 시간 흐름 안에 모으고, 사용자가 기본 구조에서 쉽
[P01-L0140] 게 시작한 뒤 자신의 생활 방식에 맞게 기록 방법을 바꾸며, 시간이 지나도 다시 찾아보고 이어
[P01-L0141] 쓸 수 있도록 한다.
[P01-L0142] 즉 서비스의 목적은 단순한 “작성”이 아니라,
[P01-L0143] 시작 → 구성 → 기록 → 축적 → 탐색 → 재열람 → 다시 기록
[P01-L0144] 까지 연결하는 데 있다.
[P01-L0145] 03. 사용자가 가지고 있는 핵심 니즈
[P01-L0146] A. 기록은 하고 싶지만 무엇부터 만들어야 할지 모르겠다
[P01-L0147] 완전히 자유로운 빈 페이지는 자유도는 높지만 사용자가 처음부터 모든 구조를 설계해야 한다.
[P01-L0148] 반대로 이미 완성된 디지털 다이어리는 시작하기 쉽지만 사용자의 생활 방식과 맞지 않는 경우
[P01-L0149] 수정하기 어렵다.
[P01-L0150] 사용자 니즈
[P01-L0151] “처음에는 바로 쓸 수 있었으면 좋겠지만, 쓰다 보니 나한테 안 맞는 부분은 바꾸고 싶다.”
[P01-L0152] DAMORI 해결 방향
[P01-L0153] 기본 템플릿 제공 + 필요한 부분만 수정
[P01-L0154] B. 내 생활 방식과 맞는 다이어리를 만들고 싶다
[P01-L0155] 사용자마다 필요한 기록이 다르다.
[P01-L0156] 누군가는 일정과 공부가 중요하고,
[P01-L0157] 누군가는 감정과 습관,
[P01-L0158] 누군가는 사진과 추억,
[P01-L0159] 누군가는 이 모든 것을 함께 사용한다.
[P01-L0160] 사용자 니즈
[P01-L0161] “다이어리에 내가 맞추는 게 아니라, 다이어리를 내 방식에 맞추고 싶다.”
[P01-L0162] DAMORI 해결 방향
[P01-L0163] Page Builder(페이지 구성 편집)를 통해 필요한 기록 요소를 추가·삭제·이동·조절한다.
[P01-L0164] C. 기록이 너무 여러 곳에 흩어져 있다
[P01-L0165] 예:
[P01-L0166] 일정 → 캘린더 수업 필기 → Goodnotes 간단한 생각 → 메모 사진 → 갤러리 일기 → 다이어
[P01-L0167] 리 앱
[P01-L0168] 사용자 니즈
[P01-L0169] “오늘 있었던 일을 나중에 다시 보고 싶은데 앱을 여러 개 뒤져야 한다.”
[P01-L0170] DAMORI 해결 방향
[P01-L0171] 일정·메모·필기·사진·문서 등을 다이어리 + 날짜 + 기록 구조 안에 연결한다.
[P01-L0172] D. 기록을 며칠 쉬면 다시 시작하기 어렵다
[P01-L0173] 기록 앱에서 연속 기록이나 매일 작성이 지나치게 강조되면 사용자가 기록을 하지 못한 날을
[P01-L0174] 실패처럼 느낄 수 있다.
[P01-L0175] 사용자 니즈
[P01-L0176] “매일 완벽하게 쓰지는 못해도 필요할 때 다시 돌아와 계속 기록하고 싶다.”
[P01-L0177] DAMORI 해결 방향
[P01-L0178] 스트릭이나 기록 압박보다 최근 기록, 마지막 페이지, 기록책으로 자연스럽게 돌아오는 구조를
[P01-L0179] 중요하게 본다.
[P01-L0180] E. 자유도는 필요하지만 복잡한 앱은 싫다
[P01-L0181] 높은 자유도를 제공하는 필기 앱은 기능이 많아질수록 툴바와 메뉴가 복잡해질 수 있다.
[P01-L0182] 사용자 니즈
[P01-L0183] “기능은 많았으면 좋겠지만 처음부터 모든 기능을 보고 싶지는 않다.”
[P01-L0184] DAMORI 해결 방향
[P01-L0185] 자주 쓰는 기능 → 먼저 노출
[P01-L0186] 추가 기능 → 필요할 때 노출
[P01-L0187] 고급 기능 → 더보기·하위 패널
[P01-L0188] 즉, 기능을 무조건 줄이는 것이 아니라 노출 우선순위를 설계한다.
