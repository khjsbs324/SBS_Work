# 디자인 구성요소 제작 피드백 기준

## 목적

피드백은 학생의 스타일가이드가 기준 이미지와 얼마나 비슷한지를 평가하지 않는다. 학생이 세운 설계의도와 디자인의도가 브랜드, 대상 사용자, 리서치, 브랜딩 와이어프레임과 웹디자인에 적합하게 반영됐는지를 설명한다.

  ## 작성 원칙
  1. 학생이 실제로 제출한 자료만 근거로 평가한다.
  2. 재확인으로 이전 판단이 달라졌다면 먼저 정정한다.
  3. 학생의 목적과 의도를 설명한 뒤 결과물과 비교한다.
  4. 각 항목은 `관찰 → 적절성 → 영향 → 개선 방법` 순서로 작성한다.
  5. 장점과 부족한 점 모두 구체적인 제출물 근거를 제시한다.
  6. 개선점은 학생이 바로 수정할 수 있도록 예시와 방법을 안내한다.
  7. 같은 문제를 여러 항목에서 반복 지적하거나 중복 감점하지 않는다.
  8. 확인하지 않은 내용은 추측하지 않는다.
  9. 마지막에는 전체 장점, 핵심 보완점과 점수 산정 이유를 정리한다.
  10. 내부 환산식, 순위와 다른 학생의 정보는 공개하지 않는다.
  11. 최대한 세세하게 작성한다.

## 피드백 구성
1. 관찰: 학생이 실제로 유지·변경한 내용
2. 의도: 학생이 번호별 기획 설명에 작성한 목적
3. 적합성: 브랜드·사용자·리서치·와이어프레임과 맞는 부분 또는 충돌하는 부분
4. 영향: 위계, 분위기, 가독성, 일관성 및 사용 경험에 미치는 효과
5. 개선 방향: 학생의 의도를 더 잘 구현할 수 있는 원칙과 재검증 방법

## 반드시 다룰 내용
- 기본 스타일가이드 파악의 정확성
- 1차 선호 디자인 리서치의 출처와 분석
- 13개 초안의 공통 아이덴티티
- 웹디자인 초안과 브랜딩 와이어프레임의 연결
- 초안 자기 비평의 구체성
- 2차 개선 리서치와 최종 변경의 연결
- 최소 3개 변경 항목의 개선 효과
- 변경하지 않은 항목의 유지 이유
- 최종 스타일가이드와 최종 웹디자인의 일관성

## 기본 문장 구조
  > {학생명} 학생은 {과제명}에 필요한 {주요 제출물}을 제출했습니다. 재확인 결과 {정정 사항 또는 제출 상태}가 확인되었습니다.

  > {평가항목}에서는 {실제 관찰한 내용}이 확인됩니다. 이는 {학생의 목적 또는 과제 요구사항}에 {적합한 이유} 때문에 적절합니다. 그 결과 {가독성·사
  용성·일관성·설득력 등에 미친 영향}이 나타납니다.

  > 다만 {확인된 문제}는 {문제가 미치는 영향}이 있습니다. {구체적인 수정 방법}으로 보완하고, 수정 후 {재검증 방법}으로 확인하면 좋습니다.

  > 전체적으로 {핵심 장점}이 잘 드러납니다. 다만 {핵심 보완점}이 완성도를 제한하고 있어 최종점수는 {점수}로 산정했습니다. 먼저 {1순위 수정사항}을
  보완하면 결과물의 완성도를 높일 수 있습니다. 고생하셨습니다^^


## 피해야 할 피드백
- “원본과 다르다”만으로 감점하는 표현
- “예쁘다/별로다”처럼 근거 없는 취향 평가
- 학생이 작성하지 않은 브랜드 의도를 대신 추측하는 표현
- 모든 학생에게 같은 색·서체·레이아웃을 정답처럼 제시하는 방식
- 최종 변경 장수가 적다는 이유만으로 부정적으로 평가하는 방식
- 근거 없는 “잘했습니다”, “부족합니다”
- “더 완성도 있게 하세요”처럼 방법이 없는 조언
- 평가자의 취향을 정답처럼 제시하는 표현
- 확인하지 않은 내용에 대한 추측
- 다른 학생의 내용 복사
- 동일한 문제의 반복 지적

상세 문항과 배점은 `Exam.md`의 DC-01~DC-12를 따른다.
