1. 프로젝트 설계와 요구사항의 적절한 적용 여부를 위하여 디자인 산출물을 리뷰하고 수정·보완 필요 요소를 파악할 수 있다. (8점)

- 정답 이미지와 문제 화면을 1920px·1600px·1024px·768px·480px에서 비교하고, 컨테이너 폭·5열 그리드·가로 스크롤의 이상 현상을 개발자 도구 근거와 함께 3건 모두 식별하였다. (7~8점)

- 화면 비교와 개발자 도구 점검을 수행하여 결함 3건 중 2건을 정확히 식별했으나 일부 화면 너비 또는 근거 기록이 부족하다. (5~6점)

- 육안 비교 중심으로 결함 1건만 식별했거나 현상은 기록했으나 CSS 속성과 연결하지 못했다. (3~4점)

- 리뷰 기록이 없거나 결함을 식별하지 못했으며 정답 이미지와 현재 화면의 차이를 설명할 수 없다. (0~2점)

 

2. 디자인 보완사항에 따라 본래 의도대로 적합하게 수정·보완 작업할 수 있다. (12점)

- --containner를 --container로 수정하고, repeat(5 1fr)를 repeat(5, 1fr)로 수정하며, body의 min-width: 1600px을 제거하여 원래 디자인을 유지한 채 결함 3건을 모두 해결하였다. (10~12점)

- 결함 3건 중 2건을 정확한 위치와 방법으로 수정했으며 수정한 영역에서는 정답 이미지와 동일한 결과가 확인된다. (7~9점)

- 결함 1건만 정상 수정했거나 임의의 고정 폭·강제 위치값 등 우회 방식으로 일부 화면만 맞췄다. (4~6점)

- 핵심 결함을 수정하지 못했거나 HTML 콘텐츠 삭제, 전체 스타일 제거 등 원래 의도를 훼손하는 방식으로 처리하였다. (0~3점)

 

3. 디자인 수정·보완 후 전체적인 관점에서 재검증을 실시할 수 있다. (8점)

- 5개 지정 화면 너비에서 헤더·메인 비주얼·상품 그리드·푸터를 재검증하고 가로 스크롤, 잘림, 겹침, 여백 이상이 없음을 수정 전·후 이미지와 체크 결과로 제시하였다. (7~8점)

- 3~4개 화면 너비에서 주요 영역을 재검증했으며 최종 화면은 정상이나 일부 증빙 또는 세부 영역 확인이 빠졌다. (5~6점)

- 1~2개 화면 너비만 확인했거나 단순 완료 문구만 있고 재검증 범위와 결과가 불명확하다. (3~4점)

- 재검증 기록이 없고 최종 화면에도 가로 스크롤, 레이아웃 파손 또는 핵심 결함이 남아 있다. (0~2점)

 

4. 기획 의도에 맞는 제작 여부를 위하여 콘텐츠 산출물을 리뷰하고 수정·보완 필요 요소를 파악할 수 있다. (8점)

- index.html의 콘텐츠 순서와 의미 구조, 이미지·링크·버튼, CSS 파일 연결 구조를 검토하여 유지할 콘텐츠와 수정할 표현·구조를 구분하고 근거를 기록하였다. (7~8점)

- 주요 콘텐츠와 CSS 연결 구조를 검토했으나 일부 이미지 대체텍스트, 링크 목적 또는 콘텐츠 흐름에 대한 분석이 부족하다. (5~6점)

- 콘텐츠 존재 여부만 확인했으며 구조적 역할이나 수정 필요성을 구체적으로 설명하지 못했다. (3~4점)

- 콘텐츠 리뷰 기록이 없거나 필요한 콘텐츠를 임의로 삭제·변경하여 기획 의도를 확인하기 어렵다. (0~2점)

 

5. 콘텐츠 사용성을 통해 문제점을 수정·보완 작업할 수 있다. (10점)

- 기존 style.css를 normal.css, root.css, component.css, btn_cpn.css, item_cpn.css, layout_cpn.css, style.css, media.css의 8개 역할별 파일로 정확히 분리하고 중복·누락 없이 정상 연결하였다. (9~10점)

- 8개 파일을 모두 생성하고 대부분 역할에 맞게 분리했으나 소수 규칙의 위치가 부적절하거나 경미한 중복·누락이 있다. (6~8점)

- 파일 분리는 했으나 2개 이상 파일이 비어 있거나 역할 구분이 불명확하고 다수 규칙이 기존 style.css에 남아 있다. (3~5점)

- CSS를 역할별로 분리하지 않았거나 분리 후 스타일이 크게 손상되어 콘텐츠를 정상적으로 사용할 수 없다. (0~2점)

 

6. 콘텐츠 수정·보완 후 전체적인 관점에서 재검증을 실시할 수 있다. (8점)

- index.html의 CSS 연결 순서가 normal→root→component→btn_cpn→item_cpn→layout_cpn→style→media이며, Network 404 없음·Console 오류 없음·캐스케이드 적용을 모두 확인하였다. (7~8점)

- 연결 순서와 화면 적용은 정상이나 Network, Console, 캐스케이드 중 1개 확인 기록이 부족하다. (5~6점)

- CSS 파일 일부의 경로 또는 순서가 잘못되었으나 화면의 주요 스타일은 확인 가능하고 부분 보완이 필요하다. (3~4점)

- 다수 CSS 파일이 로드되지 않거나 연결 순서 오류로 화면이 파손되었으며 재검증 기록이 없다. (0~2점)

 

7. 사용성·접근성·업계 표준 준수 여부 평가를 기반으로 보완·수정 요소를 파악할 수 있다. (8점)

- HTML 문서 구조, 이미지 alt, 링크와 버튼의 구분, 키보드 포커스, 텍스트 가독성, 작은 화면 조작성을 점검하고 기존 콘텐츠 범위 안에서 개선 필요 요소와 판단 근거를 제시하였다. (7~8점)

- 주요 alt·링크·버튼·포커스를 점검했으나 일부 항목 또는 모바일 사용성 근거가 부족하다. (5~6점)

- 접근성 용어는 제시했으나 실제 코드 위치와 연결된 점검 결과가 적고 일부 필수 속성을 놓쳤다. (3~4점)

- 접근성·사용성 점검이 없거나 링크·버튼·이미지의 역할을 구분하기 어려운 상태가 그대로 남아 있다. (0~2점)

 

8. 기능요소의 바른 실행에 대한 리뷰를 기반으로 수정·보완에 필요한 요소를 파악할 수 있다. (8점)

- 개발자 도구의 Styles·Computed·Layout·Network·Console을 사용하여 각 오류의 증상, 발생 선택자, 무효 또는 계산된 속성, 수정 대상을 결함별로 명확히 기록하였다. (7~8점)

- 개발자 도구로 결함 위치와 관련 속성을 대부분 확인했으나 패널별 확인 결과 또는 캡처가 일부 부족하다. (5~6점)

- 개발자 도구를 사용했으나 오류 현상과 원인 속성의 연결이 불명확하고 추측 중심으로 기록하였다. (3~4점)

- 기능 리뷰 근거가 없거나 개발자 도구를 통한 확인 없이 결과 코드만 제출하였다. (0~2점)

 

9. 파악된 오류에 대한 정확한 원인 분석에 따라 수정 작업할 수 있다. (12점)

- BUG-01은 사용자 정의 속성명 불일치, BUG-02는 repeat() 함수 인수 구분 문법 오류, BUG-03은 고정 최소 폭으로 인한 반응형 차단임을 설명하고 정확한 코드로 3건 모두 수정하였다. (10~12점)

- 3건 중 2건의 원인을 CSS 문법·계산 결과와 연결하여 설명하고 정확히 수정하였다. (7~9점)

- 1건만 원인과 수정 방법을 정확히 설명했거나 결과는 수정했지만 원인 분석이 부분적으로 잘못되었다. (4~6점)

- 원인 분석 없이 값을 임의 변경했거나 정답 코드를 복사하여 각 수정의 이유를 설명할 수 없다. (0~3점)

 

10. 기능 요소를 수정·보완 후 전체적인 관점에서 재검증을 실시할 수 있다. (8점)

- Chrome을 포함한 주요 브라우저 환경과 5개 지정 화면 너비에서 CSS 로드, 컨테이너, 그리드, 가로 스크롤, 링크·버튼 동작을 재검증하고 결과를 표 또는 이미지로 남겼다. (7~8점)

- 주요 브라우저 또는 3~4개 화면 너비에서 핵심 기능을 확인했으며 최종 결과는 정상이나 일부 환경의 증빙이 부족하다. (5~6점)

- 단일 브라우저·1~2개 화면에서만 확인했거나 검증 항목이 화면 표시 여부에 한정되었다. (3~4점)

- 기능 재검증 기록이 없고 화면 너비에 따라 핵심 레이아웃 또는 조작 요소가 정상 동작하지 않는다. (0~2점)

 

11. 기능 요소에 관련되는 프로그래밍에 대한 이해와 분석을 할 수 있다. (10점)

- CSS 변수, Grid repeat(), min-width, 캐스케이드, 미디어쿼리의 역할을 자기 말로 설명하고, 의미 있는 커밋 4개 이상과 작업 목적·검증 내용이 정리된 Pull Request를 제출하였다. (9~10점)

- 핵심 CSS 개념을 대체로 설명하고 3개 이상의 구분된 커밋과 Pull Request를 제출했으나 기록이 일부 간단하다. (6~8점)

- 개념 설명이 단편적이거나 커밋이 1~2개에 불과하고 Pull Request에 변경 이유와 검증 내용이 부족하다. (3~5점)

- CSS 수정 내용을 설명할 수 없고 단일 일괄 커밋만 있거나 GitHub 저장소·Pull Request를 제출하지 않았다. (0~2점)
