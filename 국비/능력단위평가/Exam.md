## 3. 공통 채점 규칙

1. 수행준거 1개당 문항 1개를 유지하며 11개 문항을 합치거나 나누지 않는다.
2. 수행준거별 원점수는 정수이며 원점수 합계는 100점 이하여야 한다.
3. 실제 평가·사이트 등록총점은 `ROUND(60 + (원점수 × 0.4), 0)`으로 환산해 정수로 입력한다. 문항별 이상적 환산값 `문항 배점 × 0.6 + 문항 원점수 × 0.4`는 중간 계산에만 사용하고, 각 값을 내림한 뒤 전체 정수 등록총점과의 차이를 소수 나머지가 큰 문항부터 1점씩 배분한다. 동률이면 문항 ID가 앞선 문항을 우선한다.
4. 화면만 비슷하게 만든 결과보다 결함 원인 분석, 정확한 코드 수정, CSS 책임 분리, 재검증과 Git 기록을 함께 평가한다.
5. 정답 코드와 파일 내부 순서가 달라도 책임 분리가 논리적이고 캐스케이드·동작이 유지되면 인정한다.
6. 같은 결함을 여러 문항에서 감점할 때는 서로 다른 수행준거를 침해한 직접 근거를 각각 남긴다.
7. 학생이 제출해야 할 증빙이 없으면 해당 문항 기준에 따라 감점한다. 평가 환경 문제로 확인하지 못한 항목은 `평가 보류`로 구분한다.
8. 모든 학생 결과에는 코드 피드백과 화면 피드백을 포함한다.
9. 다른 학생과의 상대 순위로 원점수를 조정하지 않는다. 60~100점 환산은 모든 학생에게 동일한 고정식을 적용한다.

- CSS 수정 내용을 설명할 수 없고 단일 일괄 커밋만 있거나 GitHub 저장소·Pull Request를 제출하지 않았다. (0~2점)

## 6. 학생별 결과 파일 형식

`채점 완료/<학생 이름>.txt`에 다음 순서로 기록한다.

1. 능력단위명, 학생 이름, 저장소 URL, 리포지터리 이름, 브랜치, 채점 커밋과 시각
2. 11개 문항별 배점·원점수·등록점수·직접 증빙·판단 근거
3. 원점수 합계, 60~100점 환산 등록점수, 통과 여부와 평가 보류 항목
4. 잘한 점
5. 우선 수정 사항
6. 화면 너비·상태별 화면 피드백
7. 재검증 체크리스트
8. 주요 결함 3~7개의 학생 코드·최소 정답 코드 비교와 구체적인 피드백
9. 완성 영역·미완성 영역·빠른 구현 순서·응용 및 재검증·전체 정리와 격려의 5개 종합 문단
10. 사이트 등록 상태와 저장 확인 시각

`사이트 입력용 피드백` 부분은 학생 공개용이다. 이 부분에는 원점수·등록점수·총점, 60~100점 환산 범위·공식·과정, 통과 여부, 순위 또는 내부 채점 판단을 포함하지 않는다. 해당 정보는 점수표와 최종 판정 같은 내부 기록에만 둔다.

## 7. 사이트 입력 전 검증

- [ ] 수행준거 수와 채점 문항 수가 모두 11개이다.
- [ ] 문항별 만점 합계가 100점이다.
- [ ] 학생별 11개 원점수 합계와 원점수 총점이 같다.
- [ ] 학생별 11개 등록점수가 모두 정수이고 합계가 `ROUND(60 + (원점수 총점 × 0.4), 0)`와 같다.
- [ ] 모든 점수에 직접 증빙 또는 미확인 사유가 있다.
- [ ] 코드 피드백과 화면 피드백이 모두 있다.
- [ ] 사이트 입력용 피드백에 주요 결함별 학생 코드·최소 정답 코드·구체적인 피드백이 있다.
- [ ] 코드 비교 뒤에 5개 종합 문단이 있고 강사용 정답 전체는 노출하지 않았다.
- [ ] 사이트 입력용 피드백에 원점수·등록점수·총점·환산 방식·통과 여부·순위가 없다.
- [ ] 저장소·리포지터리 이름·학생 이름의 매핑이 정확하다.
- [ ] 사이트 수행준거 문구와 본 문서의 문구가 일치한다.
- [ ] 사이트 입력값 합계와 학생 결과 파일의 환산 등록점수가 같다.
