# 능력단위평가 공통 채점 및 피드백 기준

## 1. 적용 범위

이 문서는 HTML, CSS, JavaScript, Git, GitHub 범위의 모든 능력단위평가에 공통으로 적용한다. 실제 문항, 수행준거, 배점, 필수 기능과 화면 조건은 선택한 평가 폴더의 자료를 우선한다.

특정 프로젝트명, 선택자, 결함, 목표 이미지 또는 화면 너비를 다른 평가에 자동 적용하지 않는다.

## 2. 평가 준비

채점 전에 다음 항목을 확정한다.

```yaml
ability_unit: 능력단위명
assignment: 과제명
criteria_count: 수행준거 수
rubric_total: 총점
required_viewports: 평가에서 요구한 화면 너비
required_interactions: 평가에서 요구한 동작
required_submission: 제출 파일, 저장소, 배포 및 문서
reference_files: 수행준거, 문제 코드, 정답 및 목표 자료
```

- 수행준거 원문, 순서와 개수를 보존한다.
- 수행준거 1개당 채점 문항 1개를 원칙으로 한다.
- 별도 지시가 없으면 배점 합계는 100점으로 한다.
- 각 문항에 과제에 맞는 구체적인 4단계 점수 구간을 작성한다.
- 학생명과 저장소 URL의 연결 및 채점 커밋을 기록한다.

## 3. 증빙 원칙

모든 점수와 피드백에는 파일·코드, 선택자·함수, 화면 너비·상태, Console·Network 결과, Git 기록 또는 캡처 중 하나 이상의 직접 근거를 연결한다.

확인하지 못한 기능은 정상으로 추정하지 않는다. 제출 누락과 평가 환경 장애를 구분하고, 확인 불가 사유와 재검토에 필요한 자료를 기록한다.

## 4. 공통 검토 영역

### HTML

- 문서 기본 구조, 언어, 문자 인코딩과 viewport
- 시맨틱 구조와 제목 계층
- 링크와 버튼의 역할 구분
- 이미지 대체텍스트, 폼 레이블과 접근 가능한 이름
- 닫히지 않은 태그, 임시 문구와 깨진 경로

### CSS

- 파일 연결 순서와 상대 경로
- Flex 또는 Grid 사용 목적
- hover, focus와 키보드 상태
- 요구된 반응형 구간, 겹침, 잘림과 가로 스크롤
- 중복·미사용·무효 선언 및 과도한 보정값

### JavaScript

- 요구 기능의 이벤트와 상태 변경
- 키보드 조작, 포커스와 ARIA 상태
- 콘솔 오류, 잘못된 요소 참조와 중복 이벤트
- 사용하지 않는 함수, 변수와 도달 불가능한 코드

### Git 및 문서

- 저장소와 배포 URL의 접근 가능 여부
- 파일명, 폴더 구조와 대소문자 경로
- 변경 단위가 드러나는 커밋 메시지
- README의 작업 범위, 구조, 실행 방법과 알려진 문제

## 5. 브라우저 검토

1. 배포 URL 또는 격리된 로컬 정적 서버로 결과물을 연다.
2. 평가에서 지정한 화면 너비를 모두 확인한다.
3. 필수 상호작용을 마우스와 키보드로 검증한다.
4. Console 오류와 Network 404를 확인한다.
5. 목표 화면이 있으면 같은 조건에서 비교한다.
6. 디자인 자유 영역은 취향이 아니라 요구사항, 정보 위계, 접근성과 안정성으로 평가한다.

화면을 확인하지 못했으면 피드백을 생략하지 않고 원인, 확인한 정적 증빙과 재검토에 필요한 자료를 기록한다.

## 6. 문항별 채점

1. 수행준거와 과제 요구사항을 읽는다.
2. 필수 증빙을 수집한다.
3. 관찰 사실과 요구사항의 차이를 기록한다.
4. 4단계 기준 중 해당 구간을 선택한다.
5. 충족 요소 수, 오류 영향과 재현 빈도로 정수 점수를 정한다.
6. 동일 결함이 다른 문항에서 이미 반영됐는지 확인한다.

| 문항 ID | 평가 내용 | 배점 | 원점수 | 등록점수 | 직접 증빙 | 판단 근거 |
|---|---|---:|---:|---:|---|---|
| 항목별 ID | 수행준거 요약 | 정수 | 정수 | 정수 | 파일·화면·동작 | 관찰 사실과 기준 구간 |

재현할 수 없는 인상만으로 점수를 결정하지 않는다.

## 7. 점수 환산

평가별 별도 규칙이 없으면 다음 공통식을 사용한다.

```text
원점수 = 모든 문항 원점수의 합
정수 등록총점 = ROUND(60 + (원점수 × 0.4), 0)
문항별 이상적 등록점수 = 문항 배점 × 0.6 + 문항 원점수 × 0.4
```

문항별 이상적 등록점수를 내림한 뒤 정수 등록총점과의 차이를 최대잔여법으로 배분한다. 나머지가 같으면 문항 ID가 앞선 항목을 우선한다. 문항별 등록점수 합계는 등록총점과 같아야 하며 문항 만점을 초과할 수 없다.

## 8. 학생 피드백

모든 학생에게 직접 증빙이 있는 잘한 점, 우선 수정 사항, 코드 구조와 구현 순서, 화면 피드백, 재검증 방법과 재제출 체크리스트를 제공한다.

사이트 입력용 피드백은 주요 결함 3~7개를 영향도 순서로 선정해 다음 구조로 작성한다.

```text
1. [결함 제목]

[언어명]
[학생이 제출한 최소 관련 코드]

[언어명]
[수정에 필요한 최소 기준 코드]

피드백:
[관찰 사실 → 요구사항과 차이 → 영향 → 수정 방향]
```

- 언어명은 `html`, `css`, `javascript`, `text` 중 하나를 사용한다.
- 학생 코드는 확인한 그대로 쓰며 임의로 고치지 않는다.
- 기준 코드는 결함 수정에 필요한 최소 범위만 제시한다.
- 대체 구현이 요구사항을 충족하면 정답과 다르다는 이유로 감점하지 않는다.
- 강사용 정답 파일 전체를 공개하지 않는다.

코드 비교 뒤에는 완성 영역, 미완성 영역, 빠른 구현 순서, 응용·재검증 방법, 전체 정리와 격려를 각각 한 문단으로 작성한다.

학생 공개용 피드백에는 원점수·등록점수·총점, 환산 공식, 통과 여부, 순위와 내부 채점 판단을 넣지 않는다.

## 9. 결과 저장

학생별 결과에는 제출 확인, 문항별 점수와 증빙, 화면 피드백, 잘한 점, 우선 수정 사항, 재제출 체크리스트, 사이트 입력용 피드백, 최종 판정, 평가 보류 항목과 사이트 등록 상태를 포함한다.

결과는 선택한 평가 폴더의 `채점 완료/<학생 이름>.txt`에 UTF-8로 저장한다.

## 10. 최종 검증

- [ ] 선택한 능력단위 폴더와 자료가 일치한다.
- [ ] 수행준거 수와 문항 수가 같다.
- [ ] 배점 합계와 학생별 점수 합계가 정확하다.
- [ ] 모든 점수에 직접 증빙 또는 미확인 사유가 있다.
- [ ] 동일 결함을 설명 없이 중복 감점하지 않았다.
- [ ] 모든 학생에게 코드 및 화면 피드백이 있다.
- [ ] 학생 공개용 피드백에 내부 점수 정보가 없다.
- [ ] 학생 수, 저장소 수와 결과 파일 수가 일치한다.
- [ ] 저장소와 배포 URL을 혼동하지 않았다.
- [ ] 강사용 정답 전체가 학생 자료에 노출되지 않았다.
- [ ] 한글 인코딩, 경로와 링크가 정상이다.
- [ ] 다른 능력단위 자료를 평가 근거로 혼합하지 않았다.
