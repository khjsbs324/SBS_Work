# 프런트엔드 기능별 프로세스 정의서

## 모바일 메뉴(FN-MENU)

1. HTML에 메뉴 버튼과 내비게이션을 기본 구조로 둔다.
2. JS는 버튼 클릭 시 열림 클래스와 `aria-expanded`를 함께 변경한다.
3. Escape 또는 닫기 버튼으로 메뉴를 닫는다.
4. 닫힌 뒤 메뉴 버튼으로 포커스를 되돌린다.
5. 데스크톱 전환 시 모바일 전용 상태를 초기화한다.

## 탭·아코디언·모달(FN-WIDGET)

- 탭은 선택 상태, `aria-selected`, `tabindex`, 패널 표시를 동기화한다.
- 아코디언은 버튼과 패널을 ID로 연결하고 열림 상태를 알린다.
- 모달은 열릴 때 제목 또는 첫 조작 요소로 이동하고, Escape로 닫으며, 실행 요소로 복귀한다.
- JS 비활성 시 핵심 콘텐츠가 숨겨지지 않도록 기본 HTML을 설계한다.

## 문의 폼(FN-FORM)

1. `submit` 이벤트에서 `preventDefault()`를 호출한다.
2. 값을 앞뒤 공백 제거 후 필수 여부와 이메일 형식을 검사한다.
3. 오류 메시지를 필드와 연결하고 첫 오류로 포커스를 이동한다.
4. 정상인 경우 실제 전송 없이 성공 데모 메시지를 표시한다.
5. 이름·이메일·문의 내용은 저장소나 콘솔에 기록하지 않는다.

## 학습 진도(FN-PROGRESS)

- 저장 키 예: `eduProgress.course-ux.lesson-01`
- 값: `true/false` 또는 완료 차시 ID 배열만 사용
- 저장소 접근은 `try...catch`로 처리하고 실패해도 화면 조작은 가능해야 한다.
- 초기화는 프로젝트 접두사의 키만 삭제한다.

## GitHub 협업·배포(FN-GITHUB)

1. 이슈에 요구사항·완료 조건을 기록한다.
2. `feature/menu-accessibility`처럼 기능 브랜치를 만든다.
3. 작은 단위로 의미 있는 커밋을 작성한다.
4. PR에 변경 내용, 테스트 환경, 결과, 스크린샷을 첨부한다.
5. 승인 후 병합하고 GitHub Pages 배포 URL에서 다시 검증한다.

## 금지·주의

- `innerHTML`로 사용자 입력 삽입
- 전역 이벤트에만 의존하거나 존재하지 않는 요소를 무조건 참조
- 개인정보를 `localStorage`, URL, 콘솔에 기록
- 절대 경로(`/css/style.css`)로 GitHub Pages 하위 경로를 깨뜨림
- JS로만 콘텐츠를 생성해 비활성 상태에서 핵심 정보가 사라짐
