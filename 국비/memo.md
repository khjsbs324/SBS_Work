# 국비 디렉터리 사용법·트리거·프롬프트

이 문서는 국비 업무를 Codex에 요청할 때 사용하는 메모다. 운영 규칙은 [AGENTS.md](AGENTS.md), 자동화 설계·입력 형식·검증 범위는 [HARNESS.md](HARNESS.md)에서 관리한다.

## 1. 시작 방법

PowerShell에서 저장소 루트로 이동하고 실행한다.

```powershell
Set-Location -LiteralPath 'C:\Users\SBS\Documents\GitHub\SBS_Work'
python -B 국비/scripts/harness.py run
```

Codex가 `국비`를 작업 폴더로 사용하며, 시작 전과 CLI 종료 후 자동화 연결을 검사한다. 이미 PowerShell의 현재 위치가 국비 폴더라면 `python -B scripts/harness.py run`을 실행한다.

아래 **터미널 명령은 저장소 루트 기준**, **Codex에 붙여 넣는 프롬프트의 자료 경로는 국비 폴더 기준**이다. `[]`로 표시한 학생명·파일명·과정명 등은 실제 값으로 바꾼다.

Codex가 시작되면 다음처럼 요청한다.

```text
능력단위평가/디자인 구성요소 제작에서 작업해줘.
해당 폴더의 AGENTS.md와 Exam.md를 읽고 현재 평가 자료의 구조와 보완할 내용을 정리해줘.
```

능력단위를 지정해 새 세션을 직접 시작할 수도 있다.

```powershell
codex.cmd -C '국비/능력단위평가/디자인 구성요소 제작'
```

직접 실행은 `harness.py run`의 시작·종료 검사를 거치지 않는다. 기본 작업은 `run`으로 시작하고, 사전 검사 오류를 Codex로 수정해야 할 때 직접 실행을 사용할 수 있다.

```text
├─ HARNESS.md                         자동화 운영·입력 형식·검증 설명
├─ .gitignore                         자동화 임시 파일 제외 설정
├─ .agents/skills/
│  ├─ ncs-exam-production/
│  │  ├─ SKILL.md                     평가 분석·출제·채점 작업 선택
│  │  ├─ agents/openai.yaml           스킬 표시명과 호출 예시

├─ scripts/
│  ├─ harness.py                     검증·점수 계산·시간 배분·Codex 실행
│  └─ test_harness.py                자동화 스크립트의 회귀 테스트
├─ 능력단위평가/
│  ├─ AGENTS.md / CLAUDE.md / 피드백.md

│  ├─ AGENTS.md
│  ├─ 편성기준_2026_UIUX.md           과거 특정 과정의 확정값 기록
│  └─ 기존 XLSX·PNG·훈련교과편성.txt
├─ 국비 시상식/
│  ├─ 기존 XLSX 평가표
│  └─ 면담 일지/                     전용 지침·학생별 TXT·검토 이미지

```

| 자료 또는 작업 | 사용하는 위치 | 사용 원칙 |
|---|---|---|
| 시험 원본·수행준거·Exam.md | `능력단위평가/[능력단위명]/` | 해당 평가의 기준으로 읽는다. |
| 학생 안내·서식·강사용 자료 | 해당 평가의 `최종 결과 산출물/` | 학생용과 강사용 내용을 구분한다. |
| 학생 제출물·직접 증빙 | 해당 평가의 `채점 자료/[학생명]/` | 원본을 보존하며 학생별로 구분한다. |
| 완성된 채점 결과 | 해당 평가의 `채점 완료/[학생명].txt` | 점수·근거·공개 피드백을 구분해 기록한다. |
| 훈련시간·교과 순서·시간표 | `타임테이블/` | 현재 과정에 해당하는 확정 자료를 사용한다. |
| 시상식 평가표 | `국비 시상식/` | 지정한 통합문서·시트·셀을 대상으로 작업한다. |
| 면담 분석·일지 | `국비 시상식/면담 일지/` | 해당 학생의 실제 응답을 근거로 작성한다. |
| 반복 업무 절차 수정 | `.agents/skills/` | 판단과 작성 절차를 바꿀 때 편집한다. |
| 계산·정형 검증 수정 | `scripts/` | 계산 로직을 바꾸고 관련 테스트를 실행한다. |

평가별 기존 폴더 구성이 다를 수 있으므로 필요한 자료가 실제로 있는지 먼저 확인한다. 다른 능력단위 자료를 대신 사용하거나 빈 완료 기록을 미리 만들지 않는다. 과거 `.검증/`에는 결과를 다시 쓰는 스크립트도 있으므로 일반 검증은 `harness.py`로 실행한다.

## 3. 트리거: 무엇을 입력하면 무엇이 실행되는가

스킬을 확실히 지정하려면 프롬프트에 `$스킬명`을 넣는다. 자연어 요청도 스킬 선택의 근거가 되지만 특정 단어를 입력하는 것만으로 모든 작업이 자동 실행되는 고정 명령은 아니다.

| 업무 | 명시적 스킬 트리거 | 자연어 요청 예시 | 수행 내용 |
|---|---|---|---|
| NCS 자료 분석·출제 | `$ncs-exam-production` | `수행준거 분석해줘`, `평가 자료 제작해줘` | 원문·Exam 확인, 학생·강사용 자료 제작, 검증 |
| 학생 채점 | `$ncs-exam-production` | `[능력단위명]의 [학생명] 채점해줘` | 제출 증빙 검토, 문항별 판단, 계산, 결과 작성 |
| 피드백 수정 | `$ncs-exam-production` | `기존 점수 유지하고 피드백 다듬어줘` | 제출 근거와 기존 판단에 맞춰 공개문 수정 |
| 평가 문제 등록 | `$ncs-exam-production` | `[능력단위명] 문제 등록해줘` | 로컬 준비·검증 후 요청한 사이트 등록·상세 확인 |
| 평가 점수 등록 | `$ncs-exam-production` | `검증된 [학생명] 점수 등록해줘` | 학생·문항 대응 확인, 점수·피드백 저장·재확인 |
| 시간표 편성 | `$ncs-timetable` | `훈련교과 편성해줘`, `시간표 검산해줘` | 교과 순서 판단, 시간 분할·이월·합계 확인 |
| 면담 일지 | `$student-interview` | `학생 면담 분석해줘`, `상담 일지 작성해줘` | 실제 응답 기반 심리상태 분석과 일지 작성 |
| 시상식 평가표 | 별도 전용 스킬 없음 | `시상식 평가표 수식 검토해줘` | 지정 XLSX의 수식·배점·학생 정보 검토 |
| 구조·연결 검사 | 스킬 없이 명령 실행 | `python -B 국비/scripts/harness.py check` | 파일·스킬·상대 링크·문법 검사 |

`AGENTS.md`는 작업 규칙의 진입점이다. 하위 평가로 작업 대상을 옮기면 그 폴더의 전용 지침도 읽도록 요청하면 된다. `.agents/skills`는 국비 또는 그 하위 폴더에서 시작할 때 탐색된다. [Codex 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)

현재 별도 Agent/Subagent와 native Hook은 없다. `agents/openai.yaml`은 스킬 UI 정보다. 파일 저장마다 검사하거나 매 응답 끝에 자동 검사하는 설정은 없으며, `run`은 **CLI 시작 전·종료 후**, 개별 검증 명령은 **실행한 시점**에 작동한다.

## 4. 프롬프트 작성 기본형

짧은 요청도 가능하다. 대상이나 결과가 여러 가지일 때는 다음 네 가지를 적으면 된다.

```text
[스킬 트리거]
대상: [능력단위명 / 학생명 / 파일·시트·범위]
근거: [사용할 원본·Exam.md·제출물·확정 조건]
작업: [분석 / 제작 / 채점 / 문체 수정 / 등록]
결과: [저장 위치·파일명·형식과 확인할 내용]
```

이미 대화에서 확정한 조건은 다시 적지 않아도 된다. `채점`과 `사이트 등록`은 서로 다른 작업이므로 등록까지 원하면 그 범위를 명시한다. 같은 자료의 분석만 원하는지, 기존 파일의 수정까지 원하는지도 적으면 작업 범위가 분명해진다.

## 5. 복사해서 사용하는 업무별 프롬프트

### A. 폴더와 현재 진행 상태 확인

```text
국비 폴더의 AGENTS.md와 HARNESS.md를 읽어줘.
현재 능력단위평가·타임테이블·면담 일지의 주요 파일과 역할을 정리하고,
내가 다음 작업을 요청할 때 지정해야 할 대상과 기준 자료를 알려줘.
이번에는 파일을 수정하지 말고 현황만 정리해줘.
```

### B. 평가 자료 제작·보완

```text
$ncs-exam-production
능력단위평가/디지털디자인 사후관리에서 작업해줘.
전용 AGENTS.md, 원본 PDF, 수행준거와 Exam.md를 기준으로
학생 과제안내서·제출 안내·강사용 채점표의 누락과 불일치를 확인하고 보완해줘.
결과는 해당 평가의 최종 결과 산출물 폴더에 반영해줘.
수행준거별 문항·배점·4단계 기준을 검증하고 변경 내용을 보고해줘.
```

### C. 학생 한 명 채점

```text
$ncs-exam-production
능력단위평가/서비스ㆍ경험디자인 관찰조사의 [학생명]을 채점해줘.
채점 자료/[학생명]의 실제 제출물을 전용 AGENTS.md와 Exam.md 기준으로 검토해줘.
문항별 직접 증빙·판단·원점수·등록점수를 기록하고 환산과 합계를 검증해줘.
학생 공개용 피드백을 작성하고 채점 완료/[학생명].txt에 결과를 저장해줘.
이번 작업은 로컬 채점까지 진행해줘.
```

### D. 여러 학생을 같은 기준으로 채점

```text
$ncs-exam-production
능력단위평가/[능력단위명]의 [학생명 목록]을 동일한 Exam.md 기준으로 채점해줘.
각 학생의 제출물을 구분해 직접 증빙을 확인하고 학생별 결과 파일을 작성해줘.
제출물이 없거나 판독되지 않는 항목은 보류 사유를 기록해줘.
마지막에 대상 학생 수·작성된 결과 수·점수 계산 검증 결과를 대조해줘.
```

### E. 기존 점수를 유지하며 피드백만 수정

```text
$ncs-exam-production
능력단위평가/[능력단위명]/채점 완료/[학생명].txt의 학생 공개용 피드백을 다듬어줘.
기존 점수와 평가 요건을 유지하고 공통·전용 피드백.md를 적용해줘.
실제 제출 근거와 학생이 다음에 고칠 대상·방법을 중심으로 작성해줘.
반복 문장과 내부 채점 용어를 정리하고 ~습니다 문체를 유지해줘.
```

### F. 사이트에 평가 문제 등록

아래 요청은 실제 사이트 등록·수정까지 포함한다. 대상 과정·회차·평가도구는 현재 사이트와 대조할 수 있게 작성한다. 사이트 접속 수단과 권한이 필요한 작업이다.

```text
$ncs-exam-production
[과정명 / 평가 회차 / 평가도구]의 [능력단위명] 문제를 사이트에 등록해줘.
해당 평가 폴더의 원본·수행준거·Exam.md·최종 결과 산출물로 등록 내용을 준비하고 검증해줘.
사이트의 공식 수행준거와 대응을 확인하고 평가기준 원문을 보존해줘.
같은 문제가 이미 있으면 기존 문제를 수정해줘.
저장 후 상세정보에서 내용·배점 합계·학생 공개용 채점기준·업로드 및 링크 설정을 다시 확인해줘.
```

### G. 검증된 점수와 피드백 등록

```text
$ncs-exam-production
[과정명 / 평가 회차]의 [능력단위명]에서 [학생명 목록]의 점수와 피드백을 사이트에 등록해줘.
완성된 로컬 채점 기록을 먼저 검증하고 학생 식별자·문항·기존 점수를 대조해줘.
저장 후 학생별 상세 화면에서 문항 점수·총점·피드백 전문이 일치하는지 확인해줘.
실제로 확인한 등록 결과와 확인 시각을 학생별 기록에 남겨줘.
```

### H. 시간표 초안 편성

```text
$ncs-timetable
타임테이블 폴더에서 [과정명]의 시간표 초안을 편성해줘.
기준 자료: [현재 과정의 확정 교과·시간·가용시간 자료 경로]
고정 조건: [오전·오후 / 담당 교사 / 시작·마지막 교과 / 선후 관계]
위 조건으로 시간대별 교과 순서를 정하고 셀 분할·이월·교과 총시간을 계산해줘.
모든 교과를 배정한 뒤 남는 시간은 공란으로 표시해줘.
타임테이블/[결과파일명].txt에 과목 순서·총시간·분할시간을 저장해줘.
```

기존 XLSX의 660H와 `훈련교과편성.txt`의 540H를 같은 과정의 확정값으로 섞지 않는다. `편성기준_2026_UIUX.md`도 현재 과정에 해당하는지 확인한 뒤 참고한다.

### I. 기존 스프레드시트 시간표 수정

```text
$ncs-timetable
[스프레드시트 URL 또는 XLSX 경로]의 [시트명 / 셀 범위]를 수정해줘.
현재 값을 먼저 읽고 [변경할 교과·시간·순서]를 반영해줘.
교과별 확정 총시간과 시간대 고정 조건을 유지하며 셀 합계도 맞춰줘.
기존 병합·색상·서식·행열 구조를 보존하고 수정한 범위를 다시 읽어 검증해줘.
```

### J. 학생 면담 분석·일지 작성

```text
$student-interview
[학생명]의 [면담지·설문지·상담 기록 경로]를 근거로 면담 일지를 작성해줘.
학생이 직접 작성하거나 선택한 응답을 확인하고,
학생 심리상태 분석과 일지의 세 범주로 문단을 작성해줘.
자료에서 확인되지 않은 내용은 추정하지 말고 확인되지 않았다고 기록해줘.
국비 시상식/면담 일지/[학생명]_면담일지_초안.txt에 저장해줘.
```

### K. 시상식 평가표 검토

```text
국비 시상식/5월 UIUX A 중간 시상식 평가표_최종.xlsx를 검토해줘.
학생 식별 정보와 배점·환산 수식·총점 계산을 확인해줘.
이번에는 파일을 수정하지 말고 오류가 있는 시트·셀·현재 값·수정 제안을 정리해줘.
```

### L. 자동화 구조 점검·수정

```text
국비 폴더의 AGENTS.md, 스킬과 scripts/harness.py 연결을 점검해줘.
깨진 상대 링크·중복 지침·실행 경로·입력 형식 문제를 확인하고 자동화 파일의 오류를 수정해줘.
기존 업무 범위와 원본 자료를 보존하고 수정 후 연결 검사를 실행해줘.
스크립트를 변경했다면 관련 회귀 테스트도 실행하고 결과를 보고해줘.
```

## 6. 터미널에서 직접 실행하는 명령

아래 명령은 `SBS_Work` 저장소 루트 기준이다. `scores`와 `timetable`의 `입력.json`은 실행 전에 실제 업무 데이터로 준비한다. JSON 입력 예시는 [HARNESS.md](HARNESS.md)에 있다.

| 목적 | 명령 |
|---|---|
| 국비 파일 현황 | `python -B 국비/scripts/harness.py inventory` |
| 스킬·지침·경로·문법 검사 | `python -B 국비/scripts/harness.py check` |
| 평가·점수 기록·제출물 검사 | `python -B 국비/scripts/harness.py check --records` |
| 사본까지 바이트 일치 검사 | `python -B 국비/scripts/harness.py check --records --strict-hashes` |
| 준비된 원점수 환산 | `python -B 국비/scripts/harness.py scores "입력.json"` |
| 준비된 교과 순서로 시간 배분 | `python -B 국비/scripts/harness.py timetable "입력.json"` |
| Codex 실행 경로만 확인 | `python -B 국비/scripts/harness.py run --dry-run -- --version` |
| 자동화 스크립트 테스트 | `python -B -m unittest discover -s 국비/scripts -p test_harness.py` |

`scores`는 증빙을 보고 원점수를 매기는 기능이 아니라 이미 정한 정수 원점수를 공통 환산식으로 계산하는 기능이다. `timetable`은 입력한 순서대로 시간을 배분하며 교육적 선후관계·휴일·담당 교사의 가능 시간을 대신 결정하지 않는다. 두 명령은 입력 파일을 수정하지 않고 JSON 결과를 화면에 출력한다.

반복할 요청을 비대화형으로 한 번 실행하려면 다음처럼 사용한다.

```powershell
python -B 국비/scripts/harness.py run -- exec '$ncs-exam-production 서비스ㆍ경험디자인 관찰조사의 현재 Exam.md와 수행준거를 대조하고 수정 없이 불일치만 보고해줘.'
```

PowerShell에서는 스킬 이름의 `$`가 변수로 해석되지 않도록 프롬프트를 작은따옴표로 감싼다. 이 명령은 요청 한 건을 실행하며 정기 예약 실행을 설정하지 않는다.

## 7. 작업을 이어가거나 결과를 확인할 때

```text
이전 작업의 [능력단위명 / 학생명 / 파일명]을 이어서 진행해줘.
현재 파일과 검증 결과부터 확인하고 미완료 항목을 처리해줘.
마지막에 수정한 파일·실행한 검증·남은 보류 사항을 정리해줘.
```

검사 출력에서 `ok`, `errors`, `warnings`를 함께 확인한다. 줄바꿈 경고는 원본 ZIP과 수록 파일의 해시가 일치하고 사본의 CRLF/LF만 다를 때 표시된다. 엄격 모드에서는 같은 차이도 실패로 보고한다. 경고를 없애기 위해 원본이나 기록된 해시를 임의 변경하지 않는다.

로컬 검사 통과와 PDF 시각 검토·학생 증빙 판단·실제 사이트 저장 확인은 구분한다. 완료 보고에 무엇을 실제로 확인했는지 기록하도록 요청한다.
