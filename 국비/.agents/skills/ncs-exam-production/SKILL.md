# NCS 평가 작업

1. [국비 지침](../../../AGENTS.md)과 [평가 공통 지침](../../../능력단위평가/AGENTS.md)을 읽는다. 요청·현재 폴더·직전 확정된 능력단위로 대상을 선택한다. 이 정보로도 대상을 특정할 수 없을 때만 묻는다.
2. 대상 폴더의 AGENTS.md, Exam.md, 수행준거 TXT와 원본 PDF를 확인한다. 문장·순서·개수는 원문, 배점과 평가 방식은 현재 Exam.md를 따른다. 충돌한 부분은 기록하고 다른 평가로 대체하지 않는다.
3. 요청에 맞는 절차만 읽는다. 채점·피드백은 [grading.md](references/grading.md), 문제·점수 등록은 [registration.md](references/registration.md)를 사용한다. 출제만 요청받았다면 아래 제작 절차를 따른다.

## 시험 제작

- 텍스트 PDF는 원문을 추출한다. 스캔 PDF는 관련 페이지를 실제 이미지로 확인한다. 읽지 못한 문장을 추측하거나 요약만 보고 원문 전체를 검증했다고 쓰지 않는다.
- 수행준거별 문항, 직접 증빙과 4단계 점수 구간을 연결한다. 기존 DC·DM·SO ID 형식을 유지하며, 원본 문장과 내부 추적 ID를 구분한다.
- 문제 코드·정답이 과제에 있는 경우에만 두 자료의 차이와 동작을 비교한다. 결함 재현 위치, 선택자, 화면 조건, CSS 연결 순서, 콘솔·네트워크 오류를 확인한다. 디자인 프로세스나 PDF 과제에 코딩·배포 조건을 추가하지 않는다.
- 학생 안내·서식과 강사용 판단 예시·정답을 분리한다. 학생 파일에는 강사용 정답을 포함하지 않는다. 최종 전달 자료는 해당 평가의 `최종 결과 산출물/`, 원본 분석은 `pdf요약결과.md`에 둔다. 파일명 지정이 있으면 그 지시를 따른다.
- [검증 스크립트](../../../scripts/harness.py)의 `check --records`를 실행한다. 스크립트는 Exam의 문항·배점·4단계 구간, 수행준거 TXT의 ID 순서, 지원되는 채점 JSON을 검사한다. 원문 PDF와의 의미 일치, 정답 노출, 브라우저 동작 및 PDF 잘림은 직접 확인한다.

새 평가가 현재 Exam 형식과 다르면 검증기를 함께 확장한다. 기존 자료 형식을 임의 변환해 통과시키지 않는다. 과거 `.검증/`의 학생·시험일에 고정된 생성 스크립트를 공통 검증기로 실행하지 않는다.
