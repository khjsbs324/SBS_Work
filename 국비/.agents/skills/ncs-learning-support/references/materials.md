# 그룹별 지원자료

공통 내용은 학습 목표, 실제 평가에서 확인한 보완 방향, 학습 순서, 설명·시각 예시, 실습, 참고자료 활용법, 완료 기준, 다음 학습 방향이다. A는 강점 확장·심화 검수, B는 누락 보완·설명과 결과 연결, C는 파일·기초 확인부터 작은 실습 완성으로 구성한다. 그룹명만 바꿔 같은 글을 게시하지 않는다.

국내 전문가 자료·한국어 유튜브·국내 무료 강의를 우선하고 한국어 공식 문서로 보완한다. 원문을 직접 열어 제목·제공자·무료 범위·내용·접근성을 확인한다. sources에는 실제 확인 시각, 읽거나 볼 범위, 자신의 작업에 적용할 활동을 쓴다. 접속 성공만으로 내용 검토를 완료했다고 쓰지 않는다. 영상·재생 시각을 만들지 않는다.

[content.example.json](../../../../희의록및지원내역/템플릿/지원내역본문/content.example.json)은 형식 예시이며 example=true인 입력은 제작을 거절한다. 실제 내용으로 교체한 후 example을 false로 바꾼다. sections.html은 XML로 읽을 수 있는 HTML 조각이다. img를 닫고 &는 &amp;로 쓴다. 이미지는 `@@파일명.png@@`로 연결한다. files에는 학생용 파일만 명시하고 내부 JSON·성적·학생 제출물을 넣지 않는다.

본문은 기존 최대 폭 980px·글자 17px·줄간격 1.95·제목 32/25px·표 여백 14×16px·교차 배경·목차·실습 강조를 유지한다. PDF는 A4로 생성하고 실제 페이지 수·글자/표/이미지 잘림·빈 페이지·이미지 로딩을 판독한다. 최근 PDF 10쪽·양식 6종은 참고 사례이며 모든 단위의 고정 수량이 아니다. 내용이 길면 페이지 구성을 조정한다.

시각자료는 단위의 학습 목적에 맞춰 직접 제작하거나 사용 가능한 원문 링크로 제공한다. 독립 제작 예시와 학생 결과물·평가 정답을 구분한다. SVG는 XML·크기·글자 잘림·외부 의존성을 확인하고 실제 편집 가능한 범위를 설명한다. Figma/Illustrator 가져오기나 실물 출력 검증을 안 했다면 했다고 쓰지 않는다. MORU NOTE 예시를 모든 단위의 프로젝트로 강제하지 않는다.

실습 양식은 실제 파일·근거·선택 이유·수정·적용·검수 결과·남은 질문을 적는 빈칸이다. 원래 평가에 없는 코딩·배포·매체 수·인쇄값을 필수 기준으로 만들지 않는다.

build → 브라우저에서 guide.html 확인·PDF 생성 → 실제 PDF·시각자료 판독 → package → validate 순으로 수행한다. materials_verified 증빙에는 실제 local_checks·pdf_reviewed·visual_reviewed·sources_reviewed·privacy_reviewed와 확인 시각을 기록한다. 검수한 파일이 바뀌면 등록 전에 다시 검수한다.
