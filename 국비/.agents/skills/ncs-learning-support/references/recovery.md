# 등록 자료 정정과 오류 복구

등록 전 자료 변경은 재생성·재검수 후 `materials_verified`를 다시 기록한다. 등록 후 변경은 현재 게시글을 읽고 `revise`로 시작한다. 명령은 [README](../../../../희의록및지원내역/README.md)에 있다.

1. 현재 글의 과정·단위·그룹·제목·번호·본문·첨부를 확인한다. 공통 증빙 필드와 post_id·url·title·live_post_checked=true를 실제 관측 JSON에 기록한다.
2. 실제 요청과 수정 이유를 전달해 `revise RUN GROUP --evidence ... --reason ... --request ...`를 실행한다. 검수본과 현재 로컬 파일이 다르면 정정을 열지 않는다. 기존 검수본을 보존된 원본에서 복구하고 현재 사이트와 대조한다.
3. 명령은 `05_정정이력/정정ID/`에 수정 전 자료·상태·현재 게시글 관측을 보존한다. 대상 그룹의 기존 등록 번호는 유지하고 자료 검수·상세 검증을 다시 수행하게 한다. 다른 그룹은 변경하지 않는다.
4. content·본문·PDF·ZIP을 수정하고 실제 판독·패키징·검증 후 `materials_verified`를 기록한다. 새로 추가하거나 변경한 참고자료는 도착 페이지의 실제 학습 내용과 연결된 PDF/영상 접근까지 확인한다.
5. 현재 LMS 수정 폼을 확인하고 같은 게시글 번호로 본문·첨부를 교체한다. 기존 browser_adapter의 prepare-post/submit-post는 신규 등록용이므로 정정에 재사용하지 않는다. 현재 수정 폼의 실제 필드와 버튼을 Playwright MCP로 확인해 조작한다.
6. `read-post`로 상세와 다운로드를 다시 확인하고 `verified` 증빙을 기록한다. 정정의 번호·URL·첨부 해시가 맞아야 닫히며 `정정완료.json`을 남긴다. `status`의 active_revisions가 비어 있는지 확인한다.

중단 후에는 다시 revise를 실행하지 않고 `next RUN`으로 열린 정정을 이어간다. 외부 저장 결과가 불명확하면 글을 조회해 실제 상태부터 확인한다. 새 요청으로 취소·되돌리기가 필요하면 수정 전 자료와 현재 사이트의 차이를 확인해 진행하며 백업을 삭제하지 않는다.
