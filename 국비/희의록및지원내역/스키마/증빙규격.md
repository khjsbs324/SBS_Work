# 증빙 JSON

형식 검사는 record가 수행한다. 아래 필드를 실제 관측 결과로 채운다. 증빙에는 쿠키·CSRF·암호를 포함하지 않는다.

모든 증빙의 공통 필드는 course_id, unit, lcode, Pcode, BoardCode, version, checked_at이다. checked_at은 시간대가 포함된 실제 ISO 시각이다. 그룹 증빙에는 group과 post_date도 필요하다. 모두 작업정보.json과 일치해야 한다.

| 단계 | 추가 필드 |
|---|---|
| target_confirmed | course_name, unit_end_date, screen_confirmed=true |
| sources_collected | scores_read, feedback_read, meeting_read=true, source_urls 배열. 신규 실행은 아래 task_basis 규칙 적용 |
| meeting_resolved | mode(existing/created/updated/skipped/drafted), reason. existing/created/updated는 exact_readback=true. drafted는 prepare 실행만 허용 |
| materials_verified | local_checks, pdf_reviewed, visual_reviewed, sources_reviewed, privacy_reviewed 모두 true, 실제 pdf_page_count 양의 정수 |
| registered | title, post_id 문자열, url, observed_in_list=true |
| verified | registered와 같은 title/post_id/url, course_confirmed, title_exact, date_exact, text_exact, images_loaded, anchors_valid, anchor_navigation, references_checked, layout_reviewed 모두 true, 실제 reference_urls 배열, attachment_status=200, attachment_sha256 |

PDF 판독에는 실제 페이지 수와 판독한 페이지·캡처 위치를 추가로 남긴다. 개인정보 검토는 학생용 파일 전문과 이미지를 확인한 뒤에만 통과로 기록한다. 자동화는 위 선언의 사실 여부를 추정하지 않으며 실제 수행 증거가 필요하다.

materials_verified의 파일 snapshot과 recorded_at은 record가 계산한다. 직접 입력한 snapshot으로 검수를 대체할 수 없다. verified의 첨부 해시는 현재 검수 ZIP과 같아야 한다. post URL은 현재 과정 버전·Pcode·BoardCode·게시글 번호를 포함해야 한다.

신규 실행의 작업정보에는 evidence_version=2가 들어간다. 평가 근거는 다음처럼 구분한다.

- task_basis=original: task_read=true, original_task_full_text_available=true. 실제 원문을 읽은 경우다.
- task_basis=feedback_reconstruction: task_read=false, original_task_full_text_available=false, task_scope와 비어 있지 않은 limitations 배열. 실제 피드백으로 파악한 범위만 사용한다.
- 근거가 부족해 과제 범위를 파악할 수 없으면 sources_collected를 완료 처리하지 않는다.

기존 evidence_version 없는 실행과 기존 증빙은 그대로 보존한다. 기존 task_read 선언을 새 원문 확인 사실로 해석하지 않는다.

drafted 회의록 증빙에는 local_reviewed=true와 실행 폴더 기준 draft_path가 필요하다. 초안 JSON은 example=false, analysis, improvement, actual_date를 포함해야 하며 record가 파일 해시를 보존한다.

정정 시작 증빙은 공통 대상·그룹 필드, title/post_id/url, live_post_checked=true를 포함한다. 실제 수정 요청과 사유를 revise에 전달한다. 자료·상태 백업과 재검수는 코드가 처리하며 verified가 같은 글·최종 파일을 확인한 뒤에만 정정을 닫는다.
