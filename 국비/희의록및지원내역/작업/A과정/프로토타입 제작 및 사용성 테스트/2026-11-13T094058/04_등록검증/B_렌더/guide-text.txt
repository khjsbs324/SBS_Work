1. 이번 실습에서 맞출 세 가지
질문·탐색·저장 화면이 연결되어 있다면 이제 사용자가 기대한 결과와 실제 동작을 맞춥니다.
선택한 값, 버튼이 약속한 행동, 도착한 화면을 한 줄씩 대조해 보세요. 이번 목표는 가장 중요
한 불일치 한 건을 수정하고 같은 과업으로 다시 확인하는 것입니다.
1. 본인 파일에서 질문부터 결과까지 한 과업을 선택합니다.
2. 버튼 이름·예상 결과·실제 결과를 기록합니다.
3. 선택 표시와 결과 요약, 저장·재추천, 복귀 화면을 대조합니다.
4. 영향이 큰 불일치부터 고치고 동료가 같은 과업을 수행하도록 합니다.
Figma 원본과 실행 링크, 수정 전 캡처를 준비합니다. 이미 만든 프로젝트를 사용하며 새로운
서비스나 실제 추천 엔진을 만들 필요는 없습니다. 고정된 예시 결과를 연결했다면 어떤 선택
에 대응하는 화면인지 파일과 설명에서 구분하세요.

2. 선택한 답과 결과가 이어지는지 보기
가상 향 추천에서 사용자가 “차분한 향”을 선택했다면 선택 표시와 결과 요약이 같은 조건을
보여 주어야 합니다. 질문만 넘어가고 결과 화면에 이전 선택이 남아 있으면 어떤 답이 반영되
었는지 알기 어렵습니다.
누르는 항목 기대하는 결과 점검할 화면
질문의 답변 현재 선택한 답이 구분됨 강조 표시·선택 문구
결과 보기 선택 조건을 확인하고 추천을 읽음 조건 요약·추천 항목
다시 선택 답을 수정하고 새 결과를 확인함 수정한 선택 표시와 연결 화면
색만 달라지는 표시라면 문구나 아이콘 등으로 선택 여부도 확인할 수 있게 합니다. 실제로 여
러 선택 조합을 지원하지 않는 시제품은 이번 테스트에서 사용할 조건을 정하고 그 흐름이 정
확히 연결되는지 확인하세요.

3. 버튼 문구와 도착 화면 대조하기
버튼을 눌러 화면이 바뀌어도 목적이 맞지 않으면 과업이 끊깁니다. “후기 보기”는 후기 정보
로, “상품 보기”는 상품 정보로 이어지는지 확인하세요. 분류 제목도 공간별 탐색인지 상품 종
류별 탐색인지 알 수 있도록 씁니다.
버튼 이름 예상 결과 불일치 예시
현재 추천 저장 현재 추천을 보관하고 완료 확인 새 추천 화면으로 이동함
다시 추천 조건 재선택 또는 새 추천 탐색 저장 표시만 바뀜
선택한 공간의 후기 해당 공간의 후기 목록 분류 설명 없는 전체 상품 목록
1. 주요 버튼을 실행 순서대로 적고 누르기 전 예상 결과를 씁니다.
2. 실제로 눌러 열린 화면 이름과 상태를 기록합니다.
3. 다른 결과가 나오면 문구가 잘못됐는지 연결이 잘못됐는지 구분합니다.
4. 프로토타입의 해당 요소와 목적지를 확인하여 수정합니다.
이 표의 불일치는 학습용 예시입니다. 자신의 화면에서 실제로 확인한 항목만 수정 대상으로
적으세요.

4. 저장과 복귀의 맥락 유지하기
저장은 현재 결과를 보관하는 동작이고 재추천은 다른 결과를 탐색하는 동작입니다. 두 버튼
이 같은 화면으로 이동하면 사용자는 어느 일이 일어났는지 이해하기 어렵습니다. 각 버튼의
도착 상태와 완료 안내를 분리해서 점검하세요.
1. 선택한 조건과 현재 결과의 이름을 기록합니다.
2. 저장 버튼을 눌러 저장 대상과 완료 표시를 확인합니다.
3. 뒤로 가기 또는 목록 버튼을 눌러 어느 화면으로 돌아오는지 봅니다.
4. 돌아온 화면에서 이전 선택·분류·결과를 이어서 확인할 수 있는지 봅니다.
상황 작은 수정의 예
저장 여부가 보이지 않음 현재 결과 이름과 저장 완료 문구를 함께 표시
뒤로 가면 처음부터 시작함 해당 과업의 이전 화면으로 연결하고 선택 상태를 표현
분류의 뜻이 모호함 분류 제목과 목록 내용이 같은 기준을 쓰도록 수정
서버에 실제 저장되지 않는 시제품이라면 화면 상태를 표현한 범위를 설명합니다. 화면 시연
과 실제 서비스 저장을 혼동하지 않도록 작업 메모에 남기세요.

5. 한 건 수정하고 같은 과업 재실행하기
완료를 막거나 다른 결과로 보내는 불일치를 먼저 고릅니다. 수정 전 화면을 남기고 문구·연결·
상태 중 바꾼 부분을 표시하세요. 여러 장을 수정하더라도 하나의 문제를 해결하기 위한 변경
인지 설명할 수 있어야 합니다.
1. “조건을 선택하고 추천을 저장한 다음 다시 확인해 보세요”처럼 과업을 작성합니다.
2. 동료에게 같은 시작점과 과업을 주고 실제 행동을 관찰합니다.
3. 멈춘 곳, 도움을 준 말, 도착 화면을 적습니다.
4. 예상 결과와 실제 결과를 다시 나란히 적어 불일치가 남았는지 확인합니다.
“잘 작동함”만 적지 말고 “선택한 조건이 결과에 표시되고 저장 완료 후 같은 추천을 다시 열
었다”처럼 확인한 동작을 적습니다. 동료가 도움을 받아 완료했다면 그 내용도 남기세요.
실습양식 1은 버튼 대조, 2는 선택·저장·복귀의 상태, 3은 수정과 재확인에 사용합니다. 과업 하
나를 끝낸 뒤 남은 버튼을 같은 방법으로 점검하세요.

6. 완료 기준과 이어서 할 일
답변 선택 표시와 결과 요약이 서로 맞습니다.
분류 제목·버튼 문구·도착 화면이 같은 목적을 설명합니다.
저장과 재추천이 서로 다른 행동으로 구분됩니다.
완료 뒤 이전 과업의 맥락으로 돌아옵니다.
불일치 한 건의 수정 전후와 재확인 결과가 남아 있습니다.
교사에게 버튼 하나를 가리키며 예상 결과를 먼저 설명하고 직접 실행해 보세요. 설명과 화면
이 다르면 그 지점이 다음 보완 대상입니다. 완료 항목과 남은 항목을 나누어 다음 작업 순서
를 정합니다.
다음 학습에서는 이 판단을 자신의 작업 방식으로 설명합니다. 예를 들어 실제로 고친 버튼 이
름과 연결 이유를 소개문 근거로 활용할 수 있습니다. “직관적인 디자인”이라는 표현을 쓰기
전에 어떤 불일치를 어떻게 해결했는지 먼저 정리하세요.
