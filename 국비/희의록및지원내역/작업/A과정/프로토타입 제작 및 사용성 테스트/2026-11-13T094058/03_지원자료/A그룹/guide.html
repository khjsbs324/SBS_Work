1. 학습 목표와 준비

이미 연결한 핵심 흐름을 유지하면서 사용자가 안내를 이해하고 결과를 확인하는지 살펴봅니다. 이번 실습에서는 촬영·선택·저장·상세 보기 중 한 과업을 골라 실제 관찰 기록, 수정 화면, 재확인 결과를 한 묶음으로 만듭니다.

자신의 Figma 원본, 실행 링크, 현재 화면 캡처를 준비하세요. 관찰 전 원본을 복제하고 수정 전 버전을 남깁니다. 제작자가 시연한 결과와 다른 사람이 직접 수행한 결과는 각각 기록합니다.

  1. 과업의 시작 화면과 성공 조건을 정합니다.
  2. 안내·진행 단계·완료 상태·복귀 위치를 먼저 대조합니다.
  3. 동료 두 명에게 같은 과업을 안내하고 관찰합니다.
  4. 중요한 문제 한 건을 수정한 뒤 같은 조건으로 다시 확인합니다.

완성할 자료는 과업 흐름표, 참여자별 관찰표, 수정 전후 비교표입니다. 실제 촬영·결제·서버 저장이 없는 시제품은 화면에서 확인할 수 있는 상태를 성공 조건으로 정하세요.

2. 안내와 실제 동작을 함께 점검하기

가상 사진 기록 서비스에서 “앞·뒤·왼쪽·오른쪽을 촬영하세요”라고 안내했다면 화면의 단계 표시와 다음 버튼도 같은 순서여야 합니다. 저장 버튼 뒤에는 무엇이 저장되었는지, 어디에서 다시 볼 수 있는지 보여주세요.

점검 구간확인할 질문자신의 화면에서 찾을 근거
촬영·진행안내한 횟수와 실제 단계가 같은가?단계 번호, 다음 버튼, 완료 화면
저장·종료저장이 끝났다는 사실을 알 수 있는가?저장 대상 이름과 완료 문구
상세·복귀상세 확인 후 탐색을 이어갈 수 있는가?이전 목록·분류가 유지되는 복귀 화면

화면이 열렸다는 이유만으로 완료라고 적지 않습니다. 사용자가 “저장됨”을 확인하고 목록에서 해당 항목을 다시 찾는 장면까지 과업에 포함할 수 있습니다. 자신의 프로젝트에 없는 기능은 점검 대상에서 제외하세요.

3. 동료 두 명의 수행을 관찰하기

과업 문장은 목적만 안내하고 정답 버튼을 알려주지 않습니다. 예를 들어 “오늘의 사진 기록을 저장한 뒤 목록에서 다시 찾아보세요”라고 말합니다. “오른쪽 아래 저장 버튼을 누르세요”는 위치를 알려 주므로 첫 수행의 관찰 과업으로 쓰지 않습니다.

  1. 목표 사용자 조건에 가까운 동료 두 명을 구하고 참여자 1·2로 기록합니다.
  2. 동일한 시작 화면·과업 문장·성공 조건을 사용합니다. 화면 버전도 적습니다.
  3. 진행 중 설명을 덧붙이지 않고 멈춘 화면, 선택한 버튼, 실제 발언을 기록합니다.
  4. 도움이 필요하면 제공한 설명을 그대로 적고 도움을 받은 완료로 구분합니다.
관찰 항목기록 방법
시작·종료실제 시각 또는 동일한 방식으로 잰 소요 시간
멈춤·도움어느 화면에서 무엇을 찾았는지, 어떤 도움을 주었는지
발언·결과실제 발언을 따옴표로 적고 완료·미완료를 성공 조건으로 판단

아직 테스트하지 않은 칸은 비워 둡니다. 예상 발언이나 그럴듯한 시간을 실제 관찰 결과로 채우지 마세요. 참여자의 이름이나 연락처를 학습자료에 적을 필요는 없습니다.

4. 관찰 사실에서 수정 한 건 고르기

관찰한 행동, 원인에 대한 해석, 수정안을 나누면 무엇을 바꿔야 하는지 분명해집니다. 아래는 기록 방법을 보여 주는 가상 예시이며 실제 참여자의 결과가 아닙니다.

구분가상 예시
관찰 사실저장 뒤 같은 화면에 머물며 “끝난 건가요?”라고 질문함
원인 해석완료 안내가 눈에 띄지 않았을 가능성이 있음
수정안저장 대상과 완료 문구를 표시하고 목록으로 가는 버튼을 추가
확인할 결과도움 없이 완료를 알아차리고 목록에서 기록을 찾는지 관찰

한 과업의 완료를 막는 문제부터 고릅니다. 색상 취향보다 막힌 단계, 잘못 이해한 버튼, 완료 여부를 모르는 상황을 먼저 살펴보세요. 여러 문제를 동시에 고치면 어떤 변경을 확인했는지 설명하기 어려워집니다.

  1. 관찰표의 문제 한 건에 번호를 붙입니다.
  2. 수정 전 화면과 해당 위치를 남깁니다.
  3. 문구·상태·연결 중 무엇을 바꿀지 정하고 반영합니다.
  4. 수정 이유를 해당 관찰 사실과 한 문장으로 연결합니다.

5. 같은 과업으로 다시 확인하기

수정 후에는 시작점·과업 문장·성공 조건을 유지하고 버전만 바꾸어 다시 수행하게 합니다. 같은 동료가 참여하면 앞선 경험을 기억할 수 있으므로 재참여 여부를 관찰표에 적습니다. 결과가 좋아져도 변경 하나의 효과라고 단정하지 않고 실제로 달라진 행동을 설명하세요.

수정 전후 비교 항목기록할 내용
문제와 변경 위치문제 번호, 수정 전·후 화면 이름 또는 캡처
수행 조건참여자, 재참여 여부, 시작점, 버전, 제공한 도움
확인 결과완료 여부, 멈춘 곳, 발언, 남은 문제
다음 조치유지할 변경과 추가 확인할 항목

두 명의 관찰을 한 줄 평균으로만 합치지 않습니다. 참여자별 기록을 남겨 서로 다른 어려움이 있었는지 확인합니다. 관찰하지 못한 항목은 “추가 확인”으로 남기세요.

실습양식의 관찰표는 참여자마다 복제해서 사용하고, 수정 전후 비교표는 문제마다 한 장씩 작성합니다. 캡처는 자신의 파일에서 가져오며 버튼과 상태를 읽을 수 있는 크기로 남깁니다.

6. 완료 확인과 다음 학습

  • 한 과업이 시작부터 결과 확인·복귀까지 이어집니다.
  • 안내 문구와 실제 단계가 일치하고 완료 상태가 보입니다.
  • 동료 두 명의 멈춤·도움·발언과 결과가 각각 기록되어 있습니다.
  • 관찰한 문제, 수정 위치, 재확인 결과를 같은 번호로 찾을 수 있습니다.
  • 반영한 수정과 앞으로 할 작업을 구분했습니다.

동료에게 실행 링크만 전달하고 과업을 마칠 수 있는지 확인해 보세요. 설명이 필요했던 위치는 관찰표에 남깁니다. 교사에게는 변경한 한 장면을 보여 주며 “어떤 행동을 보고 무엇을 바꾸었는지” 설명합니다.

다음 학습에서는 이 개선 과정을 실제 작업 경험으로 정리합니다. AI 기획과 발상의 소개문에 활용할 때에는 “사용성을 높였다”라는 포괄적인 표현보다 자신이 관찰하고 판단하고 수정한 행동을 적으세요. 첨부 자료의 빈칸은 실제 기록으로 채워 사용합니다.
