1. 학습 목표와 평가에서 확인한 보완점

이미 요구사항과 주요 화면 흐름을 비교적 안정적으로 연결한 설계를 바탕으로, 왜 그 UI를 선택했는지와 다른 화면에도 재사용할 기준을 설명합니다. 자신의 기존 결과물을 먼저 열고 설계 방향 제안서, 화면 설계서, 와이어프레임의 같은 섹션을 나란히 놓으세요.

  • 유사 서비스의 UI 사례에서 채택할 원리와 제외할 원리를 구분한다.
  • 컴포넌트의 역할, 상태, 사용 금지 조건을 디자인 가이드에 적는다.
  • 데스크톱·태블릿·모바일의 공통 규칙과 화면별 예외를 실제 프레임으로 검증한다.
  • LLM 제안의 수정·채택·제외 내역을 증거와 함께 남긴다.

예시는 가상의 '주말 클래스 신청' 서비스로 독립 제작했습니다. 자신의 평가 과제에 있던 조건과 화면을 그대로 대체하는 정답이 아닙니다.

2. 레퍼런스는 표현보다 문제 해결 원리로 비교

유사 사례 두 건을 고르고 각 사례에서 사용자 목표, 콘텐츠 순서, 신청 경로와 신뢰 정보를 관찰합니다. 화면을 따라 그리기 전에 원리가 내 서비스의 사용자와 제약에 맞는지 판단하세요.

관찰한 UI채택 또는 제외 판단내 설계에 남길 근거
신청 요약을 CTA 근처에 배치채택 검토: 결정 직전의 정보 확인에 도움신청 화면의 서비스 범위와 비용 안내 위치를 비교
자동 전환 후기 슬라이드제외 검토: 읽는 속도를 사용자가 통제하기 어려움정적 카드와 명시적 넘김 버튼을 대안으로 검토

실습양식 01에 사례 URL, 확인한 화면, 선택 이유, 채택하지 않은 이유를 기록합니다. '최신 유행' 같은 표현만으로 선택 근거를 끝내지 않습니다.

3. 컴포넌트와 디바이스 규칙을 한 장에 연결

하나의 신청 버튼을 기본·포커스·비활성·완료 등 필요한 상태로 정리하고, 라벨·크기·여백·색상 역할·예외를 가이드에 명시합니다. 수치는 아래처럼 예시 프레임에서 시험해 보고 자신의 콘텐츠 길이와 사용 환경에 맞춰 결정합니다.

확인 항목데스크톱태블릿모바일
신청 CTA본문 옆 배치 검토요약 뒤 배치 검토핵심 정보 뒤 단일 열 배치 검토
카드 정보나란한 비교폭에 따라 2열 또는 1열제목·가격·조건 순서로 1열
검수시선 이동·여백중간 폭에서 줄바꿈터치와 긴 문구 판독

표의 배치와 그림은 검토 예시입니다. 특정 픽셀 값이나 세 화면의 제작 수를 평가의 새 필수 조건으로 만들지 마세요.

4. LLM 제안은 변경 이력으로 검증

프롬프트 원문만 모으지 말고 요청, 최초 결과, 문제, 재질문 또는 수동 수정, 최종 반영·제외, 확인 위치를 한 줄로 연결합니다. 클라이언트 정보와 임시 예시 데이터도 구분합니다.

단계가상 예시 기록
요청·결과신청 전환을 돕는 구성 제안 요청 → 자동 재생 후기 배치 제안
문제·판단읽기 통제와 실제 후기 근거가 불명확해 제외
수정·검증후기 대신 제공 조건 카드로 수정 → 화면 설계서 S-04와 프레임 F-04 대조

실습양식 02에는 자신의 실제 프롬프트와 결과를, 03에는 디바이스별 규칙과 검수 위치를 적습니다. AI가 제시한 사실은 원문 또는 클라이언트 브리프와 대조한 뒤 사용하세요.

5. 완료 기준과 다음 수업에서 확인할 내용

  • 사례 두 건의 선택·제외 이유가 실제 화면 변경 위치와 이어진다.
  • 같은 UI의 상태와 재사용 규칙이 설계서와 프레임에서 충돌하지 않는다.
  • 태블릿을 포함한 화면별 정보 우선순위, 줄바꿈, 조작 방식이 설명된다.
  • LLM 결과 중 수정 또는 제외한 항목과 검증 근거가 남는다.

다음 관련 수업에서는 자신의 설계서와 대표 화면을 함께 열어 한 가지 결정의 근거와 변경 결과를 설명합니다. 설명만 추가하지 말고 해당 화면의 실제 차이를 확인하세요.
